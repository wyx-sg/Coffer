# 聚合 agent 的记忆，绝不写入它

**Related**: spec [memory](../../specs/memory/spec.md)、spec [knowledge](../../specs/knowledge/spec.zh.md)、[Knowledge Is Plain Files](knowledge-is-plain-files.zh.md)、[One Shared Knowledge Store](agent-native-shared-memory.zh.md)、[`docs/research/memory-systems-landscape.zh.md`](../research/memory-systems-landscape.zh.md)

## 背景

Coffer 三次尝试成为开发者的 agent 记忆所在之处，三次都被移除：

1. **原生投射**（2026-06-18 移除）：Coffer 拥有那个 store，把它 symlink 或 render 进每个 agent 自己的记忆位置，并关掉 agent 的原生记忆，使第二份副本无从发散。它因侵入性与不可读而被移除——也因为业界没有任何可比系统会去写另一个 agent 的记忆文件。
2. **转录蒸馏**（2026-09-09 移除）：Coffer 读会话转录，把它们蒸馏进一条 journal lane。随那条 lane 一起被移除。
3. **会话上下文注入**（2026-09-10 移除）：投射唯一真实收益——环境式加载——的替代品，以逐 agent 的 SessionStart hook 交付，而它被移除的理由值得直说：**它在维护者本人的机器上一次都没被安装过**，所以两个月里这条路径从未跑过。

剩下的是一个只能拉取的层：五个工具，外加一个告诉 agent 它存在的 skill。在实际 vault 上量过之后，这没有奏效：知识语料有 58 篇文件，而一个月里针对它的每一次工具调用，都落在某个 agent 建起它的那一天。

与此同时，在同一台机器上，两个受支持的 agent 各自跑着自己的记忆闭环，而且都在奏效：

| | Claude Code | Codex |
| --- | --- | --- |
| 形态 | 一条事实一个 Markdown 文件，frontmatter 标类型 | 一份 `MEMORY.md` 的任务分组，外加一份蒸馏出的 profile |
| 规模 | 光这一个项目就有 69 条事实 | 127 KB 的分组、172 KB 的原始记录、9 KB 的 profile |
| 由谁写 | agent 自己，持续地、无需提示 | 一条跑在它自己 rollout 上的蒸馏流水线 |
| 由谁加载 | agent 自己，环境式地，在会话开始时 | agent 自己，分两层：profile 恒在，分组按需 |
| 对另一个 agent 可见 | 否 | 否 |

这张表推出三件事。**积累记忆这份活，Coffer 赢不了**——host 在闭环里面，Coffer 不在；去竞争的结果，是两个满的 store 旁边多了一个空的。**而 Coffer 能做的那份活，host 做不了**：两者互相看不见，两者都活不过这台机器，两者都不能让用户在一个地方查看和纠正。还有，**注入层当初想够到的那个投递形态，Codex 已经替它验证过了**：一份小而恒在的 profile，加上一份按需取用的大语料。

2026-06-18 定下的那条禁令不在讨论之列。这里没有任何东西会去写 agent 的记忆文件。

## 决策

**Coffer 以只读方式聚合各 agent 的原生记忆，把它们归一成一套派生的、按项目分区的事实集合，整理这套集合，并把一份受预算约束的摘要推回每个 agent 的会话。** 五步。

1. **只读，绝不写。** Coffer 从每个已注册、已启用 agent 自己的 `config_dir` 推导出路径，读它的原生记忆，并且不修改那里的任何东西——不改文件、不改格式、不改 agent 的记忆设置。它也不读转录或 rollout：两个 agent 都已经在蒸馏自己的，而且比 Coffer 被移除的那套蒸馏做得更好，所以这一层从它们的产出开始。

2. **除了开发者的决定，Coffer 持有的一切都是派生的。** `~/.coffer/memory/` 下的整棵树都可以删掉，再从 agent 自己的副本重建。唯一无法重算的那部分状态——开发者隐藏了哪条事实、置顶了哪条、把哪条标为被取代、在哪一对冲突上做了裁决——单独存放，以一个能挺过重算的来源身份为键，并在每一趟之后重新施加。正是这道分离，让其余部分可以随意重写而无风险。

3. **按项目分区，外加一个 `global`。** 一条事实属于它被学到的那个项目；一条关于人而不关于项目的事实，无论来自哪里都属于 `global`。分区以从项目根推导出的可读 slug 命名——绝不用不透明 id，那正是当年杀死原生投射的那种不可读。每个分区都是一个 Resource，因此由框架的 per-agent scope 授权，默认授给它被聚合自的那些 agent，于是记忆不需要任何配置步骤就流回它的来源。

4. **大胆整理，因为它是派生的。** 跨 agent 合并重复、把一条事实标记为被后来的相反说法取代、把一对无法裁决的标为冲突、以及重写摘要，全部由内部连接完成，不设归档环节。知识层那条 `.history/` 规则之所以存在，是因为知识是唯一的副本；记忆不是，所以它不适用。没有配置内部连接时，摘要仍会机械地生成——这个功能会降级，但不会消失。

5. **投递是推送，分三层，且必须是有意安装的。** L0（恒在，几百 tokens）：开发者是谁、这个项目里有什么、以及怎么要更多。L1（预算装得下时）：摘要，一条事实一行。L2（按需）：一个 `recall` 工具，走 spec `knowledge` 提供的同一套带排序的检索。由渠道驱动的一轮对话，通过 Coffer 本来就在组装的 system prompt 追加拿到 L0 和 L1——不需要 hook，因为那份上下文本来就归 Coffer 所有。开发者自己驱动的 agent，则通过该 agent 自己的会话开始 hook 拿到，由一次明确的动作安装，带 marker 界定范围，可移除。**Coffer 会报告投递是否已安装、上一次是什么时候触发的**，因为上一代注入层的失败隐形了两个月，而一个说不出自己有没有跑过的功能，不能被信任为跑过了。

## 后果

### 正面

- 一个 agent 学到的东西能抵达另一个——这正是三次尝试所求的东西——而且为此没有动过任何 agent 自己的闭环。
- 这个 store 不会烂成第二份真相：它是派生的，所以漂移在构造上就不可能，一次糟糕的整理最多付出一次重新同步的代价。
- 聚合后的记忆进入 vault，因此可以通过导出与备份活过这台机器——原生的那些 store 不行。
- 开发者得到一个地方，可以查看、纠正并裁决自己的 agent 都相信些什么，而这是两个 host 都不提供的。
- Coffer 不再在 host 更擅长的事情上与它们竞争，转而去做只有它能做的事。

### 负面

- 两个读取器耦合在两套没有文档的私有格式上。格式一变就会弄坏一个读取器；缓解办法是它必须响亮且局部地坏掉（spec memory FR-005），而不是悄无声息地把 store 清空。
- 没有原生记忆的 agent 什么也贡献不了。今天两个受支持的 agent 都有，所以现在这不花什么代价；但在接入一个没有原生记忆的 agent 之前，这个问题需要有答案。
- 安装一个会话开始 hook 会写入 agent 的设置文件。那不是记忆文件，禁令依然成立；但那毕竟是往用户自己的工具里写，所以只会在用户明确指示时才做。
- 事实在 agent 的 store 与 Coffer 的派生副本之间是重复的。这一点接受：那份副本是可丢弃的，而另一条路就是已经被移除的那套投射设计。

### 中性

- 新增一张表，只装开发者的覆盖决定，别无他物。
- 没有 `remember` 工具。agent 按它本来的方式记录；Coffer 在下一趟里把它捡起来。

## 备选方案

- **Coffer 作为唯一的 store，关掉 agent 的原生记忆。** 纸面上最干净的模型，被否决，因为那意味着关掉现存唯一两条被证明有效的记忆闭环，也因为关掉它们就是往用户配置里写——正是 2026-06-18 移除掉的那种侵入。
- **把聚合后的视图写回每个 agent 的原生记忆。** 这样投递就完全不需要 hook 了。否决：这就是换了个名字的原生投射，带着同样的可逆性与可读性问题，而且会让 Coffer 的副本成为一份 agent 也在写的文件的第二个写入者。
- **交给一个 skill 和更好的工具描述。** 这就是当前的设计，量过了：一个月里只有一天在用。skill 能告诉 agent 有这么一个 store；它没法让 store 的内容在 agent 需要的那一刻就在场。
- **在 Coffer 里重新做转录蒸馏。** 双重否决：它当初被移除有充分理由，而且两个 host 现在都做得更好，所用的数据 Coffer 得以高得多的代价重读一遍。

## 修订历史

- **2026-06-18** —— *Memory via MCP, not native projection*：原生投射层被移除；Coffer 保留自己的逐条事实 store，agent 通过 MCP 工具触达它，环境式加载被推迟给一个会话 hook。
- **2026-09-12** —— 改写为本 ADR。那条禁令逐字存留，并且如今是承重的；所有权模型则发生反转。Coffer 不再持有 agent 往里写的那个规范 store——持有它的是 agent，Coffer 聚合它。MCP 面收窄为一个 `recall` 工具，环境式加载则以一次明确、可观测的安装回归，而不再是一个被推迟的后续项。
