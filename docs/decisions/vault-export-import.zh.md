# 仓库导出与导入

> English: [vault-export-import.md](./vault-export-import.md)

- **状态：** 已采纳
- **Spec：** [vault-export-import](../../specs/vault-export-import/spec.md)
- **章程：** 原则 1（0.4.0——导出属于普通的本地文件输出，无需例外）

## 背景

Coffer 是本地优先的：每台机器拥有自己的仓库，没有任何厂商云端充当事实记录方。
用户换新机器、或同时在两台机器上工作时，需要把仓库带过去——知识、记忆、
已注册资源与凭据。

本 ADR 最初的答案是基于用户自有 git 仓库的持续同步。但事实证明，让两个活着的
仓库保持收敛，比把一个仓库搬过去要难得多：它需要机器身份、带 TTL 的墓碑（以免
删除被复活）、对竞争编辑做时间戳仲裁、对导入失败的资源做隔离重试、一个独立的
git 工作树，以及一个后台 worker。这套机制占了 sync 切片的大半，而用户真正提出
的问题一个都不需要它们。

## 决策

Coffer 把仓库**导出**到用户选定的目录，并能把导出**导入**回来。不存在传输介质、
不存在远程、也没有后台复制——把目录搬到另一台机器上是用户自己的事（`scp`、
U 盘，或者他们自己愿意用的 git 仓库）。

因为导出是用户掌控下的普通本地文件输出，它不需要对原则 1 的任何例外：它不产生
第二个事实记录方，也没有任何数据抵达厂商掌控的服务。

### 导出与导入是横切服务，不是资源 kind

它们作用于*整个*仓库；它们不像 `mcp_server` 或 `channel` 那样是用户管理的实体。
因此它们遵循 retention/credentials 的横切模式——`application/sync/` +
`infrastructure/sync/` + CLI 与 HTTP 表面——而不是 `Kind` 框架，这样跨 kind 的
导入契约里就不会混进一个非 kind。

### 导出物是一个文本目录

- **知识 / 记忆**以文件形式镜像（它们本来就是磁盘上的事实）；SQLite 索引在导入
  时由既有的按内容哈希对账路径重建。
- **配置资源**被**确定性地**序列化（键排序、时间戳归一化、剥离仅本机字段）为每个
  资源一个 YAML 文件，并经由 kind 无关的 `ResourceService` 对账回 SQLite。
- **凭据**以 Fernet 密文块形式随行，且仅在用户明确要求时。

SQLite 仍是本机的事实记录方；导出物是可读的文本，因此用户在把它带走之前，能确切
看到自己带的是什么。

### 路径在导出时归一化、导入时展开

在一台机器上写出的导出物，必须能在 home 目录不同的另一台机器上导入。`$HOME` 下的
绝对路径以 `~` 哨兵相对存储，并在导入时对着导入方机器的 home 展开。这是从持续同步
中唯一存活下来的可移植性机制，因为它处理的是机器之间的真实差异，而不是它们之间的
竞态。

### 主密钥绝不进入导出物

导出物只承载密文。Fernet 主密钥经带外途径引导到另一台机器
（`coffer sync key export/import`）。只有密文而没有密钥的机器会报
`credentials_locked` 并拒绝拉起受影响的资源——它绝不静默地解密失败。

凭据默认不包含在导出物里，只有显式加参数才会带上，因为一个导出目录很容易被随手
落在不安全的地方。

### 导入是"导入方为准"，且绝不删除

导入方仓库接受导出物中所有内容的版本，并保留自己持有、而导出物没有的一切。这里
没有仲裁，因为不存在需要与之仲裁的并发写入方——用户在运行命令时就已经选定了数据
搬运的方向。

导出物中不存在的资源绝不会被删除：导出物是一台机器的快照，而不是对"哪些东西应该
在所有地方存在"的断言。

## 已考虑的备选方案

- **基于用户自有 git 仓库的持续同步**——本 ADR 此前的决策。它确实带来了收敛，
  但代价是墓碑、机器身份、冲突仲裁、隔离重试、git 工作区与 worker——对一个实际上
  只会跑那么几次的工作流而言，这是一大片高频改动的表面。已撤销。
- **托管的 Coffer 同步服务**——体验最好，但会形成厂商掌控的事实记录方；否决
  （需要范围大得多的章程修订）。
- **点对点（Syncthing 式）**——最本地优先，但需要设备发现与在线时段重叠；否决。
- **整体拷贝 `~/.coffer/`**——最简单，但会带上仅本机的状态（daemon 发现文件、
  绝对路径、各机器自己的日志）以及一个无法查看、也无法部分应用的二进制 SQLite
  文件；否决。故有此确定性文本导出。

## 影响

- `sync/` 切片仍横跨各层存在，但只保留序列化、路径可移植性、文件树镜像、凭据
  密文处理，以及那两个操作。没有 `sync_config`/`sync_state`/墓碑/机器表，没有
  git 子进程，没有 worker，没有文件监听。
- 没有网络出口：导出与导入只触及本地文件系统。
- 资源序列化器的确定性仍然是承重的——导出物本就该能被用户 diff——并保持单元测试
  覆盖。
- 带上凭据是一个刻意的两步动作：导出时的密文参数，加上带外的密钥引导。
- 两台机器可能各自漂移，Coffer 不会察觉、也不会去对账。让它们保持一致要靠手动
  重新导出，这正是本 ADR 接受的权衡。
