# 设计系统 {#design-system}

Web 界面和桌面应用渲染的是同一套前端，其中每个界面都出自一个小小的设计系统。本页讲它背后的想法：为什么颜色是角色而不是值，浅色和深色怎样工作，字号和几何尺度是做什么用的，哪些共享组件承载了产品里反复出现的概念，以及构建过程怎样防止这一切偏移。它写给要改界面的人，也写给想知道 Coffer 为什么长这样的人。视觉上的唯一依据是设计画布上的 **Foundations** 画板组；本页描述运行中的应用如何遵循它。

## 原则 {#principles}

当两个设计都能用时，由下面六条来裁决。符合得更多的那个胜出。

- **注意力优先。** 页面先展示需要你处理的事。健康的东西保持安静；出错的服务器或被挂起的一轮同步会升到最上面。
- **只有一个强调色。** 靛蓝只表示「这是操作」或「这是已选中」，别无他意。
- **状态是一个点加一个词。** 从不只靠颜色：点总是紧挨着它代表的那个词，这样状态在色盲和灰度截图下也能读出来。
- **标识符用等宽字体。** 凡是你可能粘贴到终端里的东西——路径、端口、工具名、环境变量名、commit id——都用 JetBrains Mono。正文用 Figtree。
- **没有死路。** 每个空状态、错误状态和离线状态都指出下一步：一个按钮、一条可复制的命令，或一个指向修复位置的链接。
- **外框安静，内容密集。** 用细线代替方框，阴影只给浮起来的东西，13px 文字，4px 网格。开发者的数据才是屏幕上最显眼的东西。

## 颜色是角色，不是值 {#colours-are-roles-not-values}

组件从不索要一个颜色，它索要的是一个**角色**：页面底色、凸起的表面（卡片或输入框）、凹陷的底槽、悬停和选中的填充、边框和更细的细线、主要 / 次要 / 弱化文字、强调色及其浅色填充和文字形态、四种状态色（成功、警告、危险、中性）各自带一个浅色调，还有几个控件角色（标签和智能体徽章的底块、开关的轨道、代码底色、焦点环、对话框背后的遮罩）。

每个角色在每个主题下只在一个样式表里定义一次。这让切换主题毫无成本：组件里没有任何东西知道当前是哪个主题，因为它引用的角色在底下被重新指向了。这也是角色数量少、并按用途命名的原因。「次要文字」是一个已经做好的决定——它在两个主题的每个表面上都满足对比度——而一个灰色值则是每个组件都得重新做一次的决定。

由此有两个结果：

- **颜色只留给含义。** 强调色标记操作、焦点和选中。成功、警告和危险标记状态，从不借来做装饰，强调色也从不用来表示状态。因此健康的状态用次要文字显示；只有出问题时才上色。
- **写死的颜色就是 bug。** 组件里的十六进制值、`rgb()` 或 `hsl()` 值、Tailwind 调色板类，都是不会跟随主题的颜色。构建会拒绝出现在令牌样式表之外的任何一处（见[防止偏移](#keeping-it-from-drifting)）。

界面最初写的时候用的名字（shadcn 的 `background`、`card`、`primary`、`muted-foreground` 等）仍然可用：每个都是它现在所代表角色的别名。新代码用角色名。

## 浅色与深色 {#light-and-dark}

每个角色都有浅色值和深色值。深色主题是炭灰而不是纯黑，表面越高亮度越高——卡片比页面亮一级——所以不需要阴影也能看出层次。深色下强调色稍微深一点，让上面的白色文字保持对比度；强调色的文字形态则更浅，让链接依旧清晰可读。

默认情况下界面跟随操作系统的外观，系统切换时实时跟随。你可以在设置的「通用」标签页里覆盖它——「跟随系统」「浅色」或「深色」。这个选择和界面语言一样，是浏览器或应用窗口的显示偏好：它保存在本地，从不发给守护进程，所以两台机器、或者浏览器和桌面应用，可以各自按使用者的喜好显示。

## 字体 {#type}

应用只用一个基础字号 **13px**，层级靠字重和颜色建立，而不是靠字号跳跃。角色只有几个：页面标题（18，粗体）、详情页所讲对象的标题（20）、对话框或空状态标题（15）、分节标题（15，半粗，下方带一行可见的 12 号次要色说明）、正文（13）、按钮和行标题（13，中偏粗字重）、元信息行（12，次要色），以及表头和分组标签这类说明文字（11，半粗）。没有任何文字小于 11px。数字使用等宽数字，让一列计数能对齐。

用两套字体：界面用 **Figtree**，标识符用 **JetBrains Mono**。两者都开源（SIL Open Font License），也都**随应用打包**。桌面壳只允许加载应用自身源的字体，而且一个跑在你机器上的工具，不应该为了画自己的界面去连接字体服务，所以字体文件随构建一起发布。

## 几何 {#geometry}

一切都落在 **4px 网格**上。控件有三种高度——行内和工具栏里用 26，所有按钮、输入框和下拉框默认用 30，整页状态用 36——并共用一个圆角。圆角随表面变大：最小的标记（复选框、按键图标）最紧，控件稍圆，卡片再圆一些，对话框和命令面板最圆。

只有**一种真正的阴影**，它属于浮在页面之上的东西：菜单、弹出层、对话框、提示消息和命令面板。卡片和面板是平的，只有一条细线。页面需要更多区隔时，给它更多空间，而不是更高的层级。

动效用来确认因果，从不做装饰。有三种时长——快速用于悬停、按下和所有退出，基础用于菜单和页面淡入淡出，慢速用于对话框和提示消息进入——以及四条曲线。打开系统的减少动态效果设置后，变换会被去掉，淡入淡出缩短，循环动画停止。

键盘焦点总是可见，而且只在键盘聚焦时出现，鼠标点击时从不出现：一个带间隙的两像素强调色环，跟随控件形状；文本框则改为强调色边框加一圈柔和光晕。

等待只在发生的地方显示，而且只在持续一段时间时才显示。启动了某个操作的按钮保持宽度和文字，把图标换成一个小转圈，并标记为忙碌而不是禁用；正在加载的列表保留表头，用和真实行形状一样的骨架行填充。两者都在短暂延迟后才出现，所以很快就返回的结果永远不会闪一下转圈。工具提示只给纯图标控件命名（名称，有快捷键时再加上快捷键），或显示被截断内容的全文；带文字的按钮和菜单项不加工具提示，工具提示也从不解释「会发生什么」——那属于菜单项的第二行，或「?」提示之后。工具提示从不承载操作：悬停片刻后打开，键盘聚焦时立即打开，指针沿工具栏移动时下一个无需等待就打开。

## 共享组件 {#shared-components}

基础控件——按钮、输入框、下拉框、复选框、开关、标签页、对话框、工具提示、弹出层、表格、卡片、提示消息、骨架屏、横幅——是设计系统的原语，页面由它们搭建，而不是各自重新设计样式。在它们之上有几个组件，承载着整个产品反复出现的概念。每一个的存在，都是为了让同一个问题在所有地方只有一个答案。

**智能体徽章。** 智能体的紧凑显示方式：官方标志放在一个中性底块上——Claude Code 用 Claude Spark，Codex 用 OpenAI Blossom 并在旁边写上「Codex」——从不用字母。每个智能体都用同样的底块，所以标志之外的颜色仍然留给状态：健康的徽章是素的，只有出问题时才加标记（未连接到 Coffer 的智能体加一个警告点，未安装的加虚线轮廓）。旁边没有名字的徽章会在它的标签和工具提示里带上名字和状态。智能体总是按「智能体」页面的顺序出现，所以同一个位置在各处都代表同一个智能体。

**状态点加词。** 四种状态——运行中、降级、出错、已禁用——每种都是一个彩色点加它的词。在列表行里它是安静的；在详情页头部它变成一个带底色的胶囊。

**生效范围。** 「谁能用这个资源？」永远是三个答案之一：关闭、所有智能体，或指定的智能体。同一个控件出现在列表行、详情页头部和选择栏里，并显示所选智能体的徽章，不用打开就能读出答案。生效范围属于本机，从不同步。

**变更预览。** Coffer 在写入不归它所有的文件之前——修复偏移、连接智能体、解决同步冲突——可以先把变更展示出来，放在一个预览里：按智能体和文件分组，每个文件标出操作和行数，每个智能体用一句大白话说明将发生什么，底下附上 diff 作为证据。它对每个时刻都有对应状态——计算中、无需变更、就绪、应用中、已应用，以及中途失败。部分变更失败时，它保持打开，说明哪些已经应用了，只重试剩下的。

**空状态。** 一个图块、一个标题、一行原因，以及一个下一步操作。列表位置上出现的错误也用同样的形状，只是换成危险色调，带一个重试和一个排查入口。

**列表与表格。** 大多数页面是用细线分隔的行列表。只有在读者需要比较各列时才用表格——并排比较智能体、按提供商看用量、按时间看活动：表头用句首大写且无底色，行高足以容纳一行副标题，勾选的行显示为已选中，浮动的选择栏把安全操作排在破坏性操作之前，并且没有分页页码：长列表先显示前几行并标注「显示 x / y 条」，通过**再加载 N 条**增长，N 是设置里设定的每页条数。

**页面语法。**每个页面都由同样几种形状搭成，一眼就能读懂。带边框的盒子装的是*一组东西*——一个行列表、一张表、一组卡片；某个东西自己的属性则是用细线分隔的普通行，不加盒子。页面以标题开头，操作在右边，下面一行说明；其下每个分区有标题和一行可见的说明，分区之间留足空白。说明直接显示，不藏在「?」后面，「?」只留给过长说明的溢出部分。页面不带返回按钮：标题栏的后退和前进箭头是穿行历史的唯一方式。表示「需要你」的计数都是同一种红色，最多显示 9+。控件在你改动时即保存；只有文档编辑器才有明确的保存。

**分栏视图。** 每个列表加详情、树加文件、列表加会话串的页面，都能拖动分隔线调整宽度，侧边栏也可以。分隔线平时是一条细线，指针靠近时才显现；它是一个键盘停靠点，可用方向键移动，双击复位，并为当前使用者记住宽度。

**选择器。** 任何按时间统计的东西都有一个时间范围选择器（最近一段时间或自定义范围）；任何在某个目录里运行的东西都有一个文件夹选择器：所选路径用等宽字体显示在「选择…」按钮旁边；已被移走的文件夹以错误样式显示，旧路径仍然可见。

**Coffer 标志。** 一个开口的圆角方框，用和导航图标相同的笔触画成，中间围着一个强调色的点——用产品自己的界面画出产品本身。它是侧边栏的品牌标识，也是浏览器标签页的图标，并像其他一切一样跟随主题。

## 防止偏移 {#keeping-it-from-drifting}

设计系统是被一个又一个图方便的例外一点点腐蚀掉的，所以重要的规则由构建来强制，而不是靠评审：

- **不许写死颜色。** 前端源码里只要在令牌样式表之外出现十六进制值、颜色函数或 Tailwind 调色板类，`make lint` 就会失败。
- **组件要小。** 每个组件文件都有行数上限，所以一个长出第二个职责的组件会被拆开，而不是把它吞下去。
- **截图基线。** 每个顶层页面都会以浅色和深色截图，按需对比；对比时固定字体、关闭动画，保证结果稳定。移动了像素的改动会显示成一张待审的图像 diff，有意为之的改动在同一次变更里更新基线。

在代码里落实这一切的工程约定——令牌类名、该用哪个原语、测试怎样对组件做断言——写在仓库的贡献者说明里（`.agents/visual-language.md` 和 `.agents/frontend.md`）。
