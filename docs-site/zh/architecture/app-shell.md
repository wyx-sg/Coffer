# 应用框架 {#app-shell}

应用框架是 Web 界面每个页面所在的外框：侧边栏、命令面板、设置窗口、标题栏和分栏视图。它们本身都不是功能，但每个功能都要通过它们到达，所以它们的规则决定了产品用起来像一个整体，还是像十四个页面拼在一起。本页说明这些规则及其背后的原因。怎么使用这个框架，见 [Web 界面指南](/zh/guides/web-ui)。

## 原则 {#principles}

- **按意图分组，而不是按实现分组。** 侧边栏围绕人来这里要做什么来组织，而不是围绕 Coffer 如何存储东西。
- **一个名称、一个路由，处处一致。** 一个界面只命名和寻址一次，每个显示它的地方都读取这一份定义。
- **每个视图都是一个地址。** 你正在看的东西——一个页面、一个标签页、盖在页面上的设置窗口——都在 URL 里，所以刷新、书签或后退按钮都能把它带回来。
- **一个事实只有一个来源。** 重连横幅和离线页面读取同一个守护进程状态；命令面板读取页面所读的同一批列表。对同一事实的两次读取迟早会不一致。
- **框架负责绘制，能力负责决定。** 框架绘制待处理徽标、控制实验性入口、布局分栏，但某样东西是否需要处理、是否已开启，由拥有它的能力决定。

## 侧边栏按你来做什么分组 {#the-sidebar-is-grouped-by-what-you-come-to-do}

侧边栏有十四个入口：顶部不带标题的**总览**，下面是五个分组。

| 分组 | 入口 | 它回答的问题 |
| --- | --- | --- |
| 智能体 | 智能体、模型提供商 | 我有哪些智能体，它们跑在哪些模型上？ |
| 运行 | 对话、消息渠道 | 我怎么让智能体干活——直接交代，还是通过 IM？ |
| 能力 | MCP 服务器、自定义工具、技能、命令行工具 | 我的智能体能做什么？ |
| 上下文 | 知识、记忆 | 我的智能体知道什么？ |
| 系统 | 密钥、活动、同步 | 我怎么照看 Coffer 以及各部分共享的东西？ |

早先的侧边栏按角色分组——作为消费者的智能体、一个很大的装着它们所消费内容的资源组，以及系统。这样分没有错，但那是架构的视角：想找“在哪里添加工具”的人，得先知道工具、技能、知识和消息渠道都是资源。按意图分组，答案就放在问题下面。它还让每个分组都很短：没有哪组超过四个入口，每个标题一眼就能扫完；而“任何分组不超过五个”这条规则，也告诉下一次改动新入口该放哪里，或者何时该重新考虑分组。

有两处位置是由意图而不是类型决定的。**模型提供商**放在智能体组里，因为提供商就是每个智能体的模型配置，在智能体自己的更改模型表单里选择。经过提供商的请求花了多少，是它的第二个 tab **用量**，而不是单独的侧边栏入口。**对话**和**消息渠道**在同一组里仍是两个入口：对话是 Coffer 运行的所有对话，不管由什么发起；消息渠道只负责设置和连接状态。

**总览**不属于任何分组，因为它汇总所有分组，它也是位于 `/` 的首页。**设置**根本不是一个入口（见[下文](#settings-is-a-modal-with-an-address)）。

其他备选方案——保留按角色分组、一个大的资源组、平铺列表，或者更少的入口加更多的标签页——在决策记录 [The Sidebar Is Grouped by What the Person Comes to Do](https://github.com/wyx-sg/Coffer/blob/main/docs/decisions/sidebar-grouped-by-what-the-person-comes-to-do.md) 中有论证。

### 实验性入口 {#experimental-entries}

一个入口可以属于某个[实验功能](/zh/guides/experimental-features)。侧边栏自己不判断它是否开启，而是询问功能开关并照做。已关闭功能的入口被完全隐去，而不是变灰；一个分组没有入口了，就去掉它的标题；它的**实验**标记出现在页面标题旁和设置 › 功能里，而不在侧边栏的行上（收起的窄栏提示框里仍会写明）。知识属于 `knowledge`，记忆属于 `memory`，同步属于 `sync`，模型提供商（含它的用量标签页）属于 `models`；其他入口（包括对话和消息渠道）始终存在。指向已关闭功能页面的链接会落到“未找到”页面，它在其他页面里的部分也以同样方式被略去，没有提示，也没有“开启”按钮。设置里有专门放开关的标签页**功能**，每个构建里都有。

## 唯一一份名称与路由列表 {#one-list-of-names-and-routes}

有三处界面展示应用的地图：侧边栏、命令面板的“页面”组和设置窗口的标签栏。它们都读取同一份列表，这份列表定义了每个入口和每个设置标签页——它的路由、图标、标签文字，以及所属的实验功能（如果有）。

正是这一份列表，让“处处同一个名称”的原则不费力气就能成立。从侧边栏和从命令面板到达的同一个界面，不可能有两个名字，因为名字只写在一个地方。中文标签也一样：每个界面有一个英文名和一个中文名，在中文里 agent 始终叫智能体。重命名或新增一个界面，就是改这份列表，每个界面都会跟着变。

## 设置是一个带地址的弹窗 {#settings-is-a-modal-with-an-address}

设置以一个大窗口的形式盖在你当前的页面上，入口有三个：侧边栏页脚中的**设置**行、**⌘,**（**Ctrl+,**），或命令面板。它有六个标签页，按管理对象分组——通用、安全、数据、守护进程、功能和关于。每个标签页都遵循下面的页面语法：一个标题加一行介绍，然后是朴素的分区，每个控件改动即保存。

设置做成弹窗而不是页面，是因为人们只是进去一下就离开。做成页面时，它占了一个侧边栏位置，更糟的是会把你带走：改完主题后，你还得自己找路回到刚才在做的事。做成弹窗时，它把你来的那个页面留在下面，关掉它就是回去，而不是再走一趟。

可是，一个只有状态的弹窗无法被链接、刷新，也无法用后退到达。所以设置同时也是一个路由：每个标签页位于 `/settings/<tab>`，打开它时下面那个页面被记为**背景位置**。规则由此而来：

- **打开**时 URL 变为该标签页的地址，并记录下面的页面，那个页面继续按自己的路由渲染。
- **关闭**——用 **×**、**Escape**、点击外部，或浏览器的**后退**——回到背景页面自己的地址，完全保持原样。
- **直接加载** `/settings/<tab>` 时下面没有可返回的页面，所以它盖在总览上打开，关闭后落到 `/`。

**设置**行总是打开通用标签页，并且只在弹窗打开时高亮。它带文字标签，而不只是一个齿轮，因为长列表底部孤零零一个图标很容易被忽略；在收起的窄栏上没有地方放文字，就由齿轮加一个提示框来承担。

## 标题栏承载属于窗口的控件 {#the-title-bar-carries-the-controls-that-belong-to-the-window}

在桌面应用里，一条 44 像素高、与侧边栏同色的条带横贯整个窗口。它只放原生的红绿灯、**侧边栏开关**（**⌘\\**）和**后退/前进箭头**（**⌘[** 与 **⌘]**）。侧边栏展开时，侧边栏的边线穿过这条带子向上延伸；收起时，条带下面是 56 像素的图标窄栏，徽标缩成圆点。全屏时红绿灯隐藏，控件移到左边缘。浏览器里没有这条带子：Coffer 标志和开关在侧边栏顶部，导航交给浏览器自己的箭头。

箭头在应用自己的历史里前进后退，所以没有页面需要自带返回按钮。每页一个「返回列表」链接会给「返回」带来第二种相互竞争的含义——而且当你是从别处进来时，它会与箭头不一致——所以页面都不带，从列表打开的详情页用箭头返回。页面内容在条带下方留 16 像素、左右各留 32 像素，每个页面都一样。

侧边栏页脚不显示守护进程状态，也没有版本菜单。Coffer 会自己启动守护进程，常亮的运行圆点只是噪音；你需要知道的是出问题的时候，而这会直接显示在工作区里。主题和语言是偏好设置，和其他偏好一起放在**设置 › 通用**；版本和**检查更新**在**设置 › 关于**，可用的更新由页脚上方的一张卡片提示。

Web 界面每 30 秒轮询一次守护进程状态。框架里有一个部件盯着这次轮询：失败时按 1、2、4、8 秒重试，并发布唯一的连接阶段——正常、重连中或离线——供其他所有部件读取。重连横幅和离线页面读的就是这同一个阶段，自己不加计时器：两个计时器会在不同时刻采样守护进程，可能短暂地互相矛盾。只读一个来源，并在信任缓存答案之前先检查失败，就能杜绝这一点。

## 断开守护进程时页面保留 {#losing-the-daemon-keeps-the-page}

守护进程重启，或者笔记本从睡眠中唤醒，都会让连接断开几秒。第一次探测失败就把页面换成错误页，会为一个自己会愈合的间隙丢掉用户正在读和正在输入的内容。所以在失败的前 10 秒里，页面保持挂载，变暗且不可操作，上方是一条**正在重新连接…**的提示条，带**立即重试**；超过这个时间，才换成离线页面，给出所在环境的恢复方法——在浏览器里是 `coffer daemon start` 命令，在桌面应用里是**启动守护进程**。守护进程重新应答后，所有查询都会重新读取，并弹出**已重新连接**的提示。这两种状态都画在工作区里，而不是浮在它上面，所以侧边栏和设置窗口始终可用。

## 命令面板只做导航 {#the-palette-is-navigation-only}

**⌘K**（**Ctrl+K**）或**搜索或跳转…**控件会打开命令面板。它能找到**页面**——每个侧边栏入口和设置标签页——以及**对象**——智能体和每种已列出类型的资源，按名称匹配（在带标题的类型上也按标题匹配）。什么都没输入时，它在所有页面之上显示最近几次的选择（**最近**，保存在浏览器里）；输入查询后，最佳匹配排在最前，然后是页面，再是按类型分组的对象。

- **它只做导航。** 选中一项就打开一个页面；面板里没有任何东西会创建、删除或修改什么。操作留在拥有它们的页面上，挨着让操作变得安全的上下文。
- **它不新增搜索路由。** 每种类型的对象都来自该类型页面已经在用的同一个列表查询，所以面板复用已缓存的内容，只获取没缓存的。不存在一个可能落后于页面的聚合索引。
- **每种类型各自独立。** 每种类型单独加载；加载期间面板会说明，某一种失败时显示它自己的错误，其他类型照常工作。
- **页面从不依赖守护进程。** 页面来自那份唯一的名称与路由列表，所以即使守护进程离线，面板也有用；此时它只列出页面，并说明对象需要守护进程。
- **它遵守功能开关。** 已关闭的实验功能的页面和对象不会出现。

## 待处理信号归各自的能力所有 {#attention-signals-belong-to-their-capability}

某个入口对应的类型需要你处理时，会带一个计数徽标——总是同一种红色，最多显示 **9+**——在收起的窄栏上则是一个同色圆点，计数放在图标的提示框里。侧边栏只通过这些徽标说话，而且只为需要你处理的事：失败、偏移、被保留的保险库、缺失的必需命令行工具；在总览里被你忽略的项不计入。信息性的计数——有多少个服务器、一个知识集的收件箱里有多少文档在等待——永远不会变成徽标，因为满是数字的侧边栏就不再能告诉你该看哪里。

框架只负责绘制。某种类型是否需要处理、什么能清除它，由拥有该类型的能力决定：智能体、MCP 服务器、技能和消息渠道统计守护进程的跨类型待处理列表（总览的**需要你处理**所显示的那个列表）为它们报告的内容——对智能体来说，是需要修复的、配置目录残留的，以及记忆 Hook 没被智能体批准或从未运行过的，不包括仅仅是未连接的；同步保有自己的信号，访问同步页面即清除；命令行工具统计需要你处理的必需命令。框架维护一张从侧边栏入口到信号的映射，想要徽标的类型把自己的信号加进这张映射，侧边栏就会用同样的徽标标出它，别的什么都不用改。尚未加载或读取失败的信号就不显示徽标——侧边栏从来不是暴露错误的地方。

## 分栏可调整，按浏览器保存 {#split-views-are-resizable-per-browser}

侧边栏与页面、对话列表与打开的对话、知识树与其阅读窗格、记忆分区的列表与打开的记忆，都是由一条可拖动细线分开的分栏视图。每个分栏的行为都一样：

- 分隔线的不可见拖拽区比画出的线更宽，悬停或拖动时以强调色高亮。
- 双击恢复默认值，方向键能以小步长移动获得焦点的分隔线，所以调整大小不需要鼠标。
- 限制让两边都保持可用：侧边栏在 200 到 300 像素之间，列表至少 240 像素、最多占分栏的一半，详情窗格至少 480 像素。
- 宽度只在当前浏览器中按页面记住。

宽度是按浏览器保存的便利设置，不是状态。它们从不发送给守护进程，从不同步；如果浏览器阻止存储，分栏就以默认值打开。你看到的内容不依赖于它们。侧边栏的另一项便利设置——用标题栏开关收起为 56 像素的图标窄栏——也以同样的方式记住。

## 标签页在路径里 {#tabs-live-in-the-path}

详情页的标签页是其地址的一部分：默认标签页是不带后缀的路径，其他每个标签页加上自己的名字，即 `/<kind>/<id>/<tab>`。标签页是你可以待的一个地方，所以按地方来寻址——链接可以直接落在它上面，后退能在访问过的标签页之间切换。次要状态，比如树里打开了哪个文件，仍用查询参数。

`<id>` 用哪个标识符，取决于该类型能否重命名：

- **技能和 MCP 服务器**用**名称**寻址，因为名称一经注册就固定，也是你已经认得的——`/mcp-servers/github/tools`。
- **可以重命名的类型**——模型提供商、消息渠道、知识集、记忆分区——用不可变的 **uid** 寻址，这样重命名永远不会让链接失效。

未知的标签页片段会回退到不带后缀的地址。知识集的窗格也按同样方式寻址——某篇文档的“历史”是 `/knowledge/<uid>/history?file=<document>`，它的收件箱是 `/knowledge/<uid>/inbox`——记忆分区的“投递内容”标签页是 `/memory/<uid>/delivered`。没有详情页可嵌套的列表页，比如同步和活动，改用 `?tab=` 携带标签页；默认标签页就是不带后缀的地址。

列表的筛选条件也是查询参数，因为筛选后的列表是你会去链接的东西。最需要这一点的是对话列表：`/conversations?source=seatalk&agent=codex` 按来源和智能体筛选，消息渠道则以 `/conversations?channel=<uid>` 链接到自己的对话。在列表旁打开一个对话时，筛选条件仍留在地址上（`/conversations/<id>?channel=<uid>`）；**新建对话**打开的草稿是 `/conversations/new`——它是一个地方，但还不是一个对话：第一次发送时才创建这一行，并把地址换成它的 id。
