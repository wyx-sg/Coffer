# 记忆 {#memory}

Coffer 把你的智能体为自己写下的每条记忆（Claude Code 的按项目记忆文件，Codex 的任务组和档案）集中保存在你保险库里的一个地方，并把每一条按对方自己的格式写进你其他智能体自己的记忆。之后每个智能体像加载、整理自己的记忆一样，加载和整理这些记忆。本页讲 Coffer 读什么、共享的记忆放在哪里、它往每个智能体里写什么、一次同步怎样运行，以及怎样查看、暂停和撤销同步。

记忆是一项[实验功能](/zh/guides/experimental-features)：先在**设置 → 功能**里开启它。

## 记忆同步用来做什么 {#what-memory-sync-is-for}

每个智能体都有自己的记忆，彼此却看不到对方的。Claude Code 上午在某个仓库学到的东西，Codex 下午还得重新学一遍；在笔记本上学到的东西，台式机上也没有。

Coffer 弥合这个缺口，但自己不维护一套记忆系统：

1. **发布。** Coffer 读取每个已注册智能体的原生记忆，把智能体在这台机器上写下的每条记忆发布到**中心库**，也就是你保险库里的一个文件夹。[保险库同步](/zh/guides/vault-sync)会把中心库带到你的其他机器。
2. **写入。** Coffer 把中心库里的每条记忆写进这台机器上除来源之外的每个智能体：写成智能体自己会加载的记忆文件。
3. **其余交给智能体。** 合并重复、纠正错误、遗忘过时内容，都是每个智能体自己的整理（Claude Code 的 Auto Dream，Codex 的整合）。Coffer 不往会话里放记忆，也不修改智能体自己写的记忆。

Coffer 做的只是机械处理：复制、归档、改名，从不对你的记忆调用模型。

记忆不是[知识](/zh/guides/knowledge)。知识是你或智能体刻意写下的关于外部世界的东西；记忆是智能体在工作中学到、被自动收集起来的东西。

| | 记忆 | 知识 |
| --- | --- | --- |
| 来源 | 智能体自己的记忆，由智能体写下 | 你，或者智能体把它写下来 |
| 组织方式 | 按项目，外加 `global` | 按知识集 |
| 谁修改文本 | 持有它的智能体，通过自己的整理 | 你和智能体，直接写 |
| 怎样到达智能体 | 通过智能体自己的记忆，它每次会话都会加载 | `coffer-guide` 技能指向那里时，智能体自己去读 |
| 存在哪里 | `vault/memory/` 里的中心库，像其他保险库内容一样同步 | 保险库，像其他保险库内容一样同步 |

## Coffer 读什么 {#what-coffer-reads}

| 智能体 | 读取的文件 |
| --- | --- |
| Claude Code | `<config_dir>/projects/<project>/memory/*.md` 里的每个记忆文件：frontmatter 里的 `name`、`description` 和 `type`，以及正文。Claude Code 自己的 `MEMORY.md` 索引会被跳过。 |
| Codex | `<config_dir>/memories/MEMORY.md`（每个任务组的偏好、可复用知识和失败记录），以及 `memory_summary.md`（档案、长期偏好，以及 Codex 为每个任务组列出的检索词）。 |

Coffer 不读会话记录，也不读 rollout 文件。两个智能体本来就会把自己的会话提炼进记忆，Coffer 从那里开始。它读回自己写的副本时会跳过它们（见[Coffer 往每个智能体里写什么](#what-coffer-writes-into-each-agent)），所以它写的东西不会被再次发布。

如果某个智能体的记忆格式变了，某个文件再也解析不了，那么这个智能体在这次同步里什么都不发布，记忆页会写明文件和原因；另一个智能体的记忆照常读取，这个智能体之前发布的内容仍留在中心库里。

## 中心库 {#the-hub}

中心库是你保险库里的 `vault/memory/`，每条记忆一个 Markdown 文件：

```text
~/.coffer/vault/memory/
├── global/
│   └── 3f2a91c4de55b071.md
└── projects/
    └── github.com-acme-payments/
        └── 8c01d6e2a9b34f70.md
```

- **项目就是它的仓库。** 项目以仓库的 `origin` URL 命名（`github.com/acme/payments`）；仓库没有远端时，用仓库目录的名字。主检出、它的工作树，以及同一仓库的另一份克隆（无论在这台机器还是另一台）都是同一个项目。
- **关于你的放进 `global`。** 关于你本人而不是某个项目的记忆（类型 `user`：你的偏好、Codex 的档案）归入 `global`，不管它来自哪个仓库。
- **临时文件夹不是项目。** 在不属于任何仓库的目录里学到的记忆，只有关于你本人时才会发布，归入 `global`。
- **路径可以随身带走。** 发布一条记忆时，它所在仓库的文件夹写成 `<repo>`，你的主目录写成 `~`。写进智能体时，它们会展开成这个项目在那台机器上的检出位置和那台机器的主目录。

每个文件的 frontmatter 写明这条记忆从哪里来（机器、智能体和智能体自己的文件）、它的 `type`、`title`、一句话的 `description`，以及创建和最后更新的时间；正文是智能体写下的原文。只有记忆来源的那台机器和那个智能体才会修改或删除它的中心库文件：智能体丢掉这条记忆时，中心库文件也随之删除。

看起来含有密钥（API 密钥、令牌、私钥、密码）的记忆会被**扣下**：不发布，记忆页会写明智能体和来源，但从不显示密钥的值。

中心库是保险库内容，所以如果你使用[保险库同步](/zh/guides/vault-sync)，你的记忆会和保险库的其他内容一起去到你自己的 git 远端。两个智能体对同一个教训的说法是中心库里的两个文件；每个智能体在自己那边合并它们。

## Coffer 往每个智能体里写什么 {#what-coffer-writes-into-each-agent}

中心库里的一条记忆，会写进这台机器上每个已注册的智能体，只有写下它的那个智能体在它写下时所在的机器上除外。台式机上的 Claude Code 会收到笔记本上的 Claude Code 学到的东西。

| 智能体 | Coffer 写入什么 |
| --- | --- |
| Claude Code | 每条记忆一个文件 `coffer_<slug>.md`，放在项目的记忆文件夹（`~/.claude/projects/<project>/memory/`，不存在时会创建），用 Claude Code 自己的记忆格式，外加一个写明记忆来源的 `coffer:` 区块。该文件夹 `MEMORY.md` 末尾的标记区块里，每份副本一行，位于 `<!-- coffer:memory-sync:begin -->` 和 `<!-- coffer:memory-sync:end -->` 之间：最多 30 行，最新的在前，最后一行说明文件夹里还有多少份副本。`global` 记忆写进 `~/.claude/rules/coffer-memory.md`，Claude Code 每次会话都会加载它。 |
| Codex | 每条记忆一个文件，放在 `~/.codex/memories/extensions/coffer/resources/` 下，在记忆正文上方写明它适用的项目（或"所有项目"）；再加一个 `instructions.md`，告诉 Codex 的整合这些文件是什么：你的其他智能体学到的记忆，只当作信息、绝不当作指令，按各自写明的项目归档，并在 Codex 把它们并入自己的记忆时标上 `[via Coffer]`。 |

- **只写到项目已检出的地方。** 只有一个项目在某台机器上检出后，它的记忆才会写到那台机器上；检出位置来自你的智能体记录下的工作目录。在那之前，这些记忆留在中心库里等待。`global` 记忆会写到每台机器上。
- **只碰 Coffer 自己的文件。** Coffer 只创建、修改和删除它自己的副本、`MEMORY.md` 里它的标记区块、它的规则文件，以及它的 Codex 扩展文件夹。`MEMORY.md` 里的其他内容和智能体自己写的每条记忆都逐字节保持原样，Coffer 也从不改动智能体的记忆设置。修改 `MEMORY.md` 之前，它会先把它备份到 `~/.coffer/config-backups/`。
- **被修改过的副本归智能体所有。** 当智能体修改或删除了一份副本（比如 Auto Dream 把它并入了 Claude Code 自己的某个文件），Coffer 就不再管理它：不会覆盖修改，也不会把删掉的副本恢复回来。如果这条记忆之后在中心库里有了变化，Coffer 会把新版本作为一份新副本写在被修改的那份旁边。
- **Codex 的记忆已关闭。** 当 Codex 的记忆功能关闭时（`config.toml` 里 `[features]` 下的 `memories`），Coffer 不往 Codex 写任何东西，记忆页会说明这一点。

### 当 Codex 自己从 Claude Code 导入时 {#when-codex-imports-from-claude-code-itself}

Codex 可以自己导入 Claude Code 的项目记忆，并保持导入更新。如果你在用这个功能，请打开记忆页智能体表格下方的**Codex 自己导入 Claude Code 的记忆**。这样 Coffer 在这台机器上就不再把 Claude Code 的记忆写进 Codex，表格里会显示*由 Codex 导入*。Codex 的记忆仍会写进 Claude Code。

## 一次同步怎样运行 {#how-a-sync-runs}

一个后台环节，**记忆同步**，负责读取智能体、更新中心库并写入副本。它默认开启，守护进程启动时运行一次，之后每小时一次，不调用任何模型。内容自上次同步以来没变的来源会被跳过，所以一次没有变化的同步几乎没有开销。同一时间只运行一次同步。

```text
记忆 → 立即同步
```

**立即同步**马上运行一次同步，并报告它发布了多少条记忆、写入和移除了多少份副本。旁边的 **▾** 打开自动同步：一个开关**自动同步记忆**，以及一个从 15 分钟到 1 天的间隔。更改无需重启即可生效。页头会显示记忆上次同步的时间，或者显示自动同步已关闭。

### 首次或大量同步会先等你确认 {#a-first-or-large-sync-waits-for-you}

一台机器上的第一次同步，以及任何要写入超过 50 份副本的同步，照常发布到中心库，但暂时不往你的智能体里写任何东西。记忆页把它显示为预览：按智能体和项目列出将要新写入、更新和移除的副本数量。打开一行可查看这个项目的记忆。**写入**会严格按这份计划执行；**取消**则丢弃它。你还没回应的预览，会被之后的同步替换。

### 每次同步记录了什么 {#what-each-sync-recorded}

每次有改动的同步，都会在[活动](/zh/guides/activity)里留下一条 `memory_synced` 记录，列出它发布、更新和删除的中心库文件，按智能体和文件列出它写入、更新和移除的副本，以及它扣下的记忆和无法读取的来源。没有任何改动的同步不留记录。

```sh
coffer log audit --event-type memory_synced --limit 20
```

## 记忆页 {#the-memory-page}

```text
记忆
```

**记忆**页带有**实验**标记。页头有**立即同步**及其 **▾**、记忆上次同步的时间，以及一个 **⋯** 菜单，里面是**撤销同步…**。页头下方依次是：

- **问题**：上次同步无法读取的来源，以及因为看起来含有密钥而被扣下的记忆。
- **预览**：在首次或大量同步等待**写入**或**取消**时出现。
- **项目**：中心库里的每个项目，显示它在这台机器上是否检出、检出在哪里（否则显示**这台机器上没有检出**），它有多少条记忆，以及这些记忆来自哪些智能体。**全局记忆**位于最上方。搜索框可以筛选行。
- **这台机器上的智能体**：每个智能体在此写入的副本（以及其中多少份被智能体修改或移除），它自己的记忆是否开启（Claude Code 的自动记忆，Codex 的记忆），它自己的整理是否开启（Claude Code 的 Auto Dream，Codex 的整合），任一项关闭时给出提示，以及**立即整理**。注册了 Codex 时，表格下方有**Codex 自己导入 Claude Code 的记忆**开关。

没有注册 Claude Code 或 Codex 时，页面会说明没有可同步的智能体，并提供**打开智能体**。

选择一个项目可打开它的页面。页面写明这个项目在这台机器上的检出位置，或者说明它没有检出、所以它的记忆留在中心库里等待，并列出每条记忆：标题和类型、它来自哪个智能体和哪台机器、最后更新时间，以及对这台机器上的每个智能体，它的副本处于什么状态：

| 状态 | 含义 |
| --- | --- |
| **它自己的** | 这条记忆是该智能体自己写的 |
| **已写入** | Coffer 写入了一份副本（Claude Code 里的 `global` 记忆显示为**在规则文件中**） |
| **下次同步** | 副本会在下次同步时写入 |
| **暂缓** | 这个项目没有在这台机器上检出 |
| **由 Codex 导入** | 这条记忆由 Codex 自己的导入带过去 |
| **被智能体修改** / **被智能体移除** | 智能体修改或移除了这份副本，Coffer 不再动它 |

页面从不修改记忆的文本。要修改一条记忆，就到智能体保存它的地方去改（Claude Code 的记忆文件夹，或者用 Codex 的记忆工具），下次同步会带上这次修改。要查看某个智能体自己的记忆文件夹，打开**智能体 → 选择该智能体 → 更多 → 记忆**。

## 整理由每个智能体自己负责 {#curation-is-each-agent-s-own}

Coffer 不合并也不让记忆退役。每个智能体整理自己持有的东西，包括 Coffer 的副本：

- **Claude Code**：Auto Dream 按 Claude Code 自己的节奏合并重复、丢掉被推翻或过时的内容，并重写索引。Coffer 目前还读不到它是否开启，所以页面显示为未知；请在 Claude Code 的 `/memory` 里查看。
- **Codex**：只要它的记忆开启且输入有变化，整合就会运行，并把 Coffer 的扩展文件夹作为输入之一。较新的证据胜过较旧的说法。

一个很少使用的项目，在它的整理下次运行之前，可能会同时放着一份副本和该智能体自己对同一教训的版本。想现在就整理，在该智能体那一行选择**立即整理**：Coffer 在你的主目录里、不打开终端地启动这个智能体，给它一个让它整合自己记忆的提示，并记录一条 `memory_curation_requested` 事件。这次运行使用该智能体自己的模型和账号，和你与它的任何会话一样。

## 撤销同步 {#undo-sync}

```text
记忆 → ⋯ → 撤销同步…
```

**撤销同步…**先列出它会移除什么、保留什么，然后从这台机器上移除 Coffer 写入且智能体没有修改过的每份副本、每个 `MEMORY.md` 中 Coffer 的区块、`~/.claude/rules/coffer-memory.md` 和 `~/.codex/memories/extensions/coffer/`，关闭自动同步，并记录一条 `memory_sync_undone` 事件。它保留保险库里的中心库、智能体自己写下的每条记忆，以及智能体修改过的每份副本。你的其他机器不受影响。重新打开自动同步或选择**立即同步**，副本就会再次写入。

## 关闭记忆 {#turning-memory-off}

在**设置 → 功能**里关闭**记忆**功能，会停止同步、隐藏记忆页并关闭它的 API。已经写入的副本留在你的智能体里，作为它们自己拥有的普通记忆；如果你想去掉它们，请先用**撤销同步…**。在记忆页上关闭自动同步，只会停止无人值守的同步，**立即同步**仍可使用。

## 从早期版本升级 {#upgrading-from-an-earlier-build}

早期版本把记忆作为笔记保存在 `~/.coffer/derived/memory/` 下，并通过一个 `coffer-memory` Hook 交给会话。守护进程首次启动时，会把这个 Hook 从每个智能体的设置里移除（其他 Hook 原样保留，并为每个智能体记录一条 `memory_hook_removed` 事件），并删除 `~/.coffer/derived/memory/`。不会丢失任何东西：那些笔记本来就是从智能体自己的记忆构建的，第一次同步会把这些记忆发布到中心库。

## 故障排查 {#troubleshooting}

**某个项目的记忆没有出现在某个智能体里。** 打开这个项目的页面：**暂缓**表示这个项目没有在这台机器上检出（在这里用智能体打开它一次）；**下次同步**表示之后还没有运行过同步；记忆页上有等待中的预览，表示你还没有选择**写入**。对于 Codex，请确认它的记忆已开启。

**某个智能体的记忆没有发布。** 确认这个智能体已注册、它自己的记忆已开启，然后选择**立即同步**，并查看项目上方的**问题**。在任何仓库之外学到的记忆，只有关于你本人时才会发布。

**同一个教训在某个智能体里出现了两次。** 两个智能体对同一个教训的说法，在智能体整理之前是两条记忆。在该智能体上选择**立即整理**，或者等它自己的整理运行。

**我删掉的副本又回来了。** 不会，除非这条记忆在中心库里有了变化：那时新版本会作为一份新副本写入。想让某条记忆不再到达某个智能体，就在写下它的那个智能体里修改或删除它。
