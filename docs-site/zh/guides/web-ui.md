# Web 界面 {#web-ui}

Coffer 的 Web 界面是你管理保险库里一切的地方：智能体、MCP 服务器、技能、知识、记忆、提供商、消息渠道，也是你和智能体对话的地方。本页讲界面是怎么提供的，带你看一遍侧边栏、命令面板和设置窗口，并列出各页面共有的约定。[桌面应用](/zh/guides/desktop-app)在一个原生窗口里承载同一个界面。

## 打开界面 {#open-the-ui}

```sh
coffer open
```

```text
opened http://127.0.0.1:8000/ in your browser
```

`coffer open` 在没有守护进程运行时会启动一个，从 `~/.coffer/daemon.json` 读取守护进程的端口，然后用浏览器打开那个地址。它不传任何凭据：页面由守护进程提供，这本身就是认证。

| 选项 | 效果 |
| --- | --- |
| `--no-browser` | 打印 URL，而不是打开浏览器。 |
| `--json` | 打印 `{"url": …, "port": …}`。 |

守护进程默认监听 8000 端口，所以 `http://127.0.0.1:8000/` 足够稳定，可以加书签。如果别的程序需要 8000，用 `coffer config set daemon.port <port>` 把 Coffer 挪开；见[运行守护进程](/zh/guides/daemon)。

## 界面是怎么提供的 {#how-the-ui-is-served}

守护进程自己在它的回环地址上提供构建好的前端，所以页面和 API 同源。没有单独的 Web 服务器，也没有登录页。

- **令牌就在页面里。**守护进程每次提供 `index.html`（无论是 `/` 还是 `/agents` 这样的前端路由），都会把当前的 API 令牌作为 `window.__COFFER_TOKEN__` 写进文档。守护进程提供的任何页面都能调用 API；浏览器里什么都不保存。
- **页面从不缓存。**`index.html` 带 `Cache-Control: no-store` 提供，所以重启后的守护进程的新令牌总能到达页面。`/assets` 下带哈希的文件照常缓存。
- **只回应守护进程自己的地址和页面。**`Host` 不是其端口上的 `127.0.0.1`、`localhost` 或 `[::1]` 的请求会被拒绝（`403 HOST_NOT_ALLOWED`），这可以阻止恶意网页用 DNS rebinding 读到令牌。来自其他任何源的页面发出的请求也会被拒绝（`403 ORIGIN_NOT_ALLOWED`）。守护进程自己的源和桌面应用总是被允许。要用开发服务器，启动守护进程时设置 `COFFER_DEV_CORS=1` 以允许端口 5173 上的 Vite，或者把源列在 `COFFER_CORS_ORIGINS` 里。见[安全模型](/zh/architecture/security#allowing-a-development-origin)。

::: warning
任何能从你机器的回环地址加载这个页面的人都能使用保险库。Coffer 是单用户的本地应用：不要把守护进程的端口转发给其他机器。
:::

桌面应用无法用这种方式拿到令牌，因为它从自己的包里加载界面，而不是从守护进程加载。它通过 IPC 把同样的两个值交给页面；见[桌面应用](/zh/guides/desktop-app#how-it-connects)。

## 侧边栏 {#the-sidebar}

侧边栏按你来 Coffer 要做的事分组。**总览**在最上面，不属于任何分组，因为它汇总下面的一切；其后是五个分组。

| 分组 | 入口 | 路由 | 用途 |
| --- | --- | --- | --- |
| — | **总览** | `/` | 落地页：需要你处理的事、每个领域的健康状况，以及最近几次改动。见下面的[总览](#overview)。 |
| 智能体 | **智能体** | `/agents` | 这台机器上装的、由 Coffer 管理的 AI 智能体。每个智能体的页面有**总览**、**模型**、**技能**、**MCP 服务器**、**插件**、**Hooks**、**配置文件**、**记忆**和**会话**标签页。见[智能体](/zh/guides/agents)。 |
| 智能体 | **模型提供商** | `/model-providers` | 厂商的接入地址和它们的 API 密钥，也就是智能体所用的模型。见[模型提供商](/zh/guides/providers)。 |
| 运行 | **对话** | `/conversations` | Coffer 运行的每个对话（在这里开始的或来自消息渠道的），带来源、按来源和智能体的筛选，以及一个可以继续任何对话的回复框。见[对话](/zh/guides/chat)。 |
| 运行 | **消息渠道** | `/channels` | 让你在 IM 里和智能体对话的 Telegram 和 SeaTalk 机器人：配置、连接状态和设置；每个都链接到它的对话。见[消息渠道](/zh/guides/channels)。 |
| 能力 | **MCP 服务器** | `/mcp-servers` | Coffer 聚合在一个端点后面的上游 MCP 服务器。见 [MCP 服务器](/zh/guides/mcp-servers)。 |
| 能力 | **自定义工具** | `/custom-tools` | 智能体作为工具调用的 HTTP API 请求，见[自定义工具](/zh/guides/custom-tools)。 |
| 能力 | **技能** | `/skills` | Coffer 投递给智能体的技能库。见[技能](/zh/guides/skills)。 |
| 能力 | **命令行工具** | `/clis` | 你的技能需要的命令行工具，以及每个是否已安装，见[命令行工具](/zh/guides/clis)。 |
| 上下文 | **知识** | `/knowledge` | `~/.coffer/vault/knowledge/` 下的文档知识集：一棵树旁边是阅读器和编辑器，还有每个知识集的收件箱、每篇文档的历史和最近改动。见[知识](/zh/guides/knowledge)。 |
| 上下文 | **记忆** | `/memory` | 智能体学到的东西，从它们自己的记忆里读出来，并按主题提炼成每个主题一份记忆：最近 7 天会话开始时的投递，以及各个分区。分区页面有**记忆条目**和**投递内容**标签页。见[记忆](/zh/guides/memory)。 |
| 系统 | **密钥** | `/secrets` | 每个已保存的密钥及其使用者：添加、更换、删除，找出文件里的明文密钥并移进保险库。见[密钥](/zh/guides/secrets)。 |
| 系统 | **活动** | `/activity` | 改了什么、智能体调用了什么、守护进程记录了什么：**全部**合并成一条流，然后是**变更**、**MCP 调用**和**守护进程日志**。见[活动与审计](/zh/guides/activity)。 |
| 系统 | **用量** | `/usage` | 各订阅由其智能体报告的额度，以及经过 Coffer 本地代理的 API 密钥请求的 token 数和估算费用。见[用量](/zh/guides/usage)。 |
| 系统 | **同步** | `/sync` | 让这个保险库和你自己的 git 远端收敛，分为**状态**、**机器**和**远端**标签页，另有**解决冲突**（`/sync/conflicts`）和**审阅暂停的删除**（`/sync/deletions`）视图。见[保险库同步](/zh/guides/vault-sync)。 |

中文界面里的分组名是 智能体 · 运行 · 能力 · 上下文 · 系统，agent 一律叫作智能体。

属于[实验功能](/zh/guides/experimental-features)的入口，在功能打开时带一个**实验**标签。功能关闭时它看起来就像不存在：入口不出现在侧边栏里；一个分组的入口全部关闭时，分组标题也一并去掉；点链接进入它的页面会看到标准的「未找到」页面。这样的功能共四个：知识、记忆、同步和模型提供商（含用量）。

**提醒徽标。**入口旁边的数字统计那里**有待处理的事项**：出错或偏离了 Coffer 所写内容的 MCP 服务器、智能体、技能和消息渠道（和总览的**需要你处理**是同一批），被暂停或失败的一轮同步（访问同步页面后清除），以及缺失、版本过旧或未登录的必需命令行工具。只要其中有一项是失败，徽标就是红色。信息性的计数从不变成徽标：在知识集收件箱里等待的条目只作为树里的**收件箱**计数显示。在折叠的图标栏上，徽标缩成同色的小圆点，图标的提示里带着计数（**MCP servers · 1 failing**）。

**折叠和调整宽度。**用 Coffer 标志旁的**折叠侧边栏**把侧边栏折叠成 56 像素的图标栏；图标栏的**展开侧边栏**按钮在底部，位于齿轮和守护进程圆点之间，选择会被记住。展开时，拖动右边缘的细线可以调宽或调窄（见[调整分栏宽度](#resizing-split-views)）。


## 总览 {#overview}

**总览**是应用打开时显示的页面。它分三部分回答「一切正常吗，有什么需要我？」：

- **需要你处理**：每个领域的每个问题一行，按严重程度排序，再按时间从早到晚。每一行写明它涉及的对象（一个服务器、一个智能体、一个消息渠道、保险库的同步），用一句话给出原因和开始时间，并有一个按钮，打开你处理它的页面或标签页。如果智能体设置里的记忆 Hook 被手动改过，而 Coffer 无法重写它，这一行会打开那个智能体的**钩子**标签页，那里有**修复钩子**。这个列表就是守护进程的待处理列表（`GET /api/v1/attention`，或在终端里运行 `coffer attention`）。行会自己消失：页面跟随守护进程的事件流，问题一解决，对应的行就不见了。如果某个领域检查失败，页面会在行上方说明，因为那个领域本该报告的内容都缺了。如果某行的修复是交给智能体的杂事（安装缺失的启动器、诊断出错的服务器、解包 SeaTalk SDK），它还有一个 **⋯** 菜单，里面有**复制提示词**，以及在有 Coffer 托管的智能体可用时的**交给智能体**：和该项页面上提供的是同一个提示词（`coffer attention --prompt <key>` 会打印它）。只是没连接的智能体也有一个 **⋯** 菜单，里面有**忽略**。被忽略的项离开列表，在列表下方计数（**已忽略 1 项 · 显示**），**显示**会重新列出它们，并带**不再忽略**。忽略状态由 Coffer 记在这台 Mac 上（不同步到你的其他机器），对智能体本身没有任何改动。被忽略的项也会从侧边栏徽标和菜单栏计数里去掉。只有值得知道但没出问题的项才能忽略。没有需要你处理的事时，会有一张平静的卡片说明这一点，并写明上次检查的时间。
- **健康状况**：每个领域一块：智能体、MCP 服务器、技能、知识、记忆、模型提供商、消息渠道、同步、自定义工具、命令行工具、密钥和用量。每块显示一个状态词、一个数量和一行摘要（MCP 服务器是最近 24 小时的调用和错误；用量是今天的 token 数、费用和各提供商的占比），点击打开该领域的页面。加载失败的块会说明这一点，带**重试**和到它页面的链接，页面其余部分照常工作。
- **最近活动**：最近几次改动，带一个到[活动](/zh/guides/activity)的链接。

在登记任何智能体之前，总览会先引导你连接一个。它列出 Coffer 支持的智能体，每个带配置文件夹，以及是否在这台机器上找到。找到的会打勾，**查看并连接**会在 Coffer 写入任何东西之前展示每一处文件改动。如果一个都没找到，它会说明，并提供**重新扫描**；**复制提示词**会复制一段 Coffer 写好的提示词，让你的助手在这台 Mac 上安装其中一个；Coffer 自己不指定安装程序。**手动添加智能体**打开智能体页面，下面还有智能体之间共享的每样东西的第一步。

## 搜索或跳转 {#search-or-jump-to}

侧边栏顶部的**搜索或跳转…**控件打开命令面板；在任何地方按 **⌘K**（**Ctrl+K**）也可以。输入几个字母，用方向键移动，按 **Enter** 前往，按 **Escape** 关闭并回到原处。

命令面板只用于导航：它带你去页面和对象，从不执行操作；操作留在各自的页面上。它能找到：

- **页面**：每个侧边栏入口和每个设置标签页。页面总是可用，即使守护进程离线。
- **对象**：你的智能体、模型提供商、对话、消息渠道、MCP 服务器、自定义工具、技能、命令行工具、知识集、记忆分区和密钥，按名称匹配（有标题的类型也按标题匹配），列表里有状态词的会带上状态词（**异常**、**已关闭**、**缺失**）。每种类型各自加载：加载中时面板会说明，某一种加载失败只有那一种显示错误。守护进程无法访问时，面板只列出页面，并说明对象需要守护进程。

什么都没输入时，它在所有页面上方显示**最近**：你最近从面板打开过的几样东西，记在这个浏览器里。一旦开始输入，唯一的最佳结果以**最佳匹配**打头（名称完全一致的优先），然后是其他匹配的页面，再是按类型分组、按侧边栏顺序排列的匹配对象。什么都没匹配到时会说明。

已关闭的[实验功能](/zh/guides/experimental-features)的页面和对象不会出现，界面其他地方也是如此。

## 侧边栏底部 {#the-sidebar-footer}

侧边栏底部从上到下是：

- **更新已就绪**：在桌面应用里，发现新版本时出现：一张写明版本的卡片，带**重启**（下载新版本、校验签名、安装并重新打开 Coffer）和**新内容**（设置 › 关于）。关掉它，下次启动时还会出现；它从不是弹窗。
- **设置**：带齿轮的一行。它打开设置窗口（见下文），窗口打开时这一行高亮。在折叠的图标栏上只有齿轮，提示是 **Settings ⌘,**。
- **守护进程状态和应用版本**：**正在连接守护进程…**、**守护进程运行中**、**守护进程正在停止**、**正在重新连接…** 或**守护进程离线**，版本号在右边。它和下面的连接状态始终一致：守护进程不在时，它从不显示为运行中。在折叠的图标栏上，它是一个彩色圆点，提示内容相同。

点击守护进程状态打开**版本菜单**。第一行写着版本号和守护进程应答的地址（`127.0.0.1:8000`），点击打开**设置 → 守护进程**。下面是：

- **主题**：**浅色**、**深色**或**跟随系统**，立即生效。
- **语言**：**English** 或**简体中文**，各用自己的语言命名，立即生效。
- **文档**：就是本站。
- **检查更新**：打开**设置 › 关于**；在桌面应用里会立即检查。

## 设置 {#settings}

设置以一个大窗口的形式打开在当前页面上方，所以关掉它会让你回到原来的位置。用**设置**这一行打开，或者在没有输入框聚焦时按 **⌘,**（**Ctrl+,**），或者从命令面板打开。除了守护进程标签页上的**端口**，每个字段改完即保存，没有保存按钮。

发布构建有五个标签页，顺序如下；`dev` 构建在最后多一个**功能**标签页：

| 标签页 | 地址 | 包含内容 |
| --- | --- | --- |
| **通用** | `/settings/general` | **外观**：**语言**和**主题**（浅色、深色或跟随系统）；**表格与文件**：**每页行数**（列表在显示「再加载 N 条」之前显示多少行）和**打开文件的方式**（Coffer 用哪个应用打开托管的文件）；**Coffer 自用模型**：为 **Coffer 引擎**和**语音转文字**各选一个提供商和模型，各带**测试**和一个内联的未设置 / 正常应答 / 失败状态。Coffer 自己运行的各轮处理，由知识和记忆页面上的**自动**控件开关。「模型」功能关闭时，连接选项不会出现。 |
| **安全** | `/settings/security` | 只放属于这台 Mac 的东西。**加密**：主密钥存在哪里（签名的正式版把它放在钥匙串里，无需迁移），以及**备份主密钥**（仅桌面应用）。**访问**：守护进程的访问令牌，点**显示**之前隐藏，带**复制**和**轮换…**。**审批**：密钥首次发往新地方前是否等你批准，以及查看待批准项的**查看**。已保存的密钥在[密钥](/zh/guides/secrets)页面，不在这里。 |
| **数据** | `/settings/data` | Coffer 保存的内容，按类型分。**保险库**：保存你的配置、技能、知识和加密密钥的 git 仓库：它的大小、有多少个版本、位置，以及**打开文件夹**。每个文件的版本用 `coffer vault history` 查看，技能的版本在它的**历史**标签页（见[手动编辑保险库](/zh/guides/vault-files)）。**本地内容**：聊天和消息渠道的附件，不会同步，请自己备份那个文件夹。**历史**：**变更**、**MCP 调用**和**对话**保留多久（**永久保留**或一个天数；缩短会先询问，并说明下次清理会删除多少条记录），每六小时清理一次，带**立即清理过期数据**。**可重建的缓存**：记忆树和对话记录摘要缓存：**清除**会先询问，记忆会在下次更新时从智能体自己的记忆重建。 |
| **守护进程** | `/settings/daemon` | 守护进程的状态：它的状态和地址、运行了多久、pid，以及有多少个智能体连接到 Coffer；带**重启**：在桌面应用里由应用重启它，在浏览器里守护进程自己重启，页面从新进程重新加载。**启动**：**开机自启动**（macOS）和**端口**（1024–65535，默认 8000；被其他程序占用或超出范围的端口会就地被拒绝，在你改掉之前保存按钮保持禁用）。已保存的端口会显示 **Coffer 重启后生效**，带**立即重启**，在浏览器里它会从新端口重新加载页面；智能体会自己重新连接到新端口。守护进程离线时，这个标签页会说明如何让它恢复，控件都被禁用。这里没有令牌（在安全标签页里），也没有停止控件。 |
| **关于** | `/settings/about` | 版本号，旁边是**复制诊断信息以报告问题**（版本、宿主、守护进程状态和端口、已启用的功能，从不包括令牌或密钥）；**详细信息**：版本号和正式版构建所用的提交、许可证、源代码和数据文件夹。在桌面应用里还有**更新**：Coffer 上次检查的时间、**检查更新**、有新版本时的**下载并重启**，以及**自动检查**（见[桌面应用 → 更新](/zh/guides/desktop-app#update)）。在浏览器里，它说明更新由桌面应用安装，并提供**复制提示词** / **交给智能体**，把升级这份 Coffer 的工作交给你的智能体。 |
| **功能** | `/settings/features` | 四个[实验功能](/zh/guides/experimental-features)——知识、记忆、同步和模型提供商——每个带**实验**标记、一行说明和一个开关。被 `COFFER_FEATURES` 固定的功能，开关不可用。这个标签页在每个构建中都有。 |

**每个标签页都有自己的地址。**打开一个标签页会把 URL 改成 `/settings/<tab>`，所以书签或分享的链接能直接打开那个标签页。用 **×**、**Escape**、点击窗口外部或浏览器的**后退**按钮关闭窗口：你会回到下面的页面，地址也是它自己的。如果你直接加载一个 `/settings/<tab>` 地址，它会打开在**总览**上方，关掉后落在 `/`。

主题、每页行数和首选编辑器保存在你的浏览器里，从不发给守护进程，除非是打开文件时作为目标应用。停止守护进程只能用 CLI（`coffer daemon stop`）：在页面上停掉它，页面也会跟着挂掉。轮换访问令牌在**设置 › 安全**里（或用 `coffer daemon rotate-token`）；页面会装上新令牌并继续工作，其他打开的标签页和使用旧令牌的客户端会停止工作，直到它们加载新令牌。查看或复制密钥、备份主密钥，以及批准待处理的[审批](/zh/guides/secrets#approvals)，都只在[桌面应用](/zh/guides/desktop-app#presence-checks-and-approvals)里提供，因为每一项都需要浏览器做不到的 Touch ID 或密码验证；浏览器标签页在这些位置显示 **Open in Coffer app**。

## 调整分栏宽度 {#resizing-split-views}

窗口左右分栏的地方（侧边栏和页面之间，对话列表和打开的对话之间），两半由一条可以拖动的细线隔开。鼠标悬停或拖动时，这条线以强调色高亮。

- **拖动**它调整宽度。**双击**它恢复默认宽度。
- **用键盘**：用 Tab 移到这条线上，按 **←** 或 **→** 小步移动。
- **限制保证两边都可用。**侧边栏宽度保持在 200 到 300 像素之间（默认 220）。列表至少 240 像素，最多占分栏的一半，旁边的详情至少保留 480 像素。
- **宽度按页面记在这个浏览器里。**这只是个便利：另一个浏览器、桌面应用或无痕窗口都从默认值开始，什么都不发给守护进程。

## 浅色和深色 {#light-and-dark}

界面跟随系统的浅色或深色外观，系统切换时也跟着切换。要自己选，在版本菜单（点侧边栏底部的守护进程状态）或**设置 → 通用 → 主题**里选**浅色**或**深色**；**跟随系统**会恢复跟随系统。选择立即生效，保存在 `localStorage` 的 `coffer.theme` 下，所以每个浏览器和桌面应用各自保存自己的选择。两套主题是怎么构建的见[设计系统](/zh/architecture/design-system)。

## 语言 {#language}

在侧边栏底部的版本菜单，或**设置 → 通用 → 语言**里，在 **English** 和**简体中文**之间切换。所有标签立即改变，不需要重新加载，选择保存在 `localStorage` 的 `coffer.language` 下。关于标签页没有语言控件。

## 所有页面共有的约定 {#conventions-every-page-shares}

**URL 描述你正在看的东西。**刷新、书签或分享的链接会重新打开同一个视图。详情页的标签页是路径的一部分：默认标签页是不带后缀的地址，其他标签页加上自己的名字，比如 `/mcp-servers/github` 和 `/mcp-servers/github/tools`。技能和 MCP 服务器按名称寻址，名称在登记后就固定了（`/skills/release-notes`）；智能体按类型寻址，因为每种类型只有一个（`/agents/claude_code/skills`）。可以改名的类型（模型提供商、消息渠道、知识集、记忆分区）按不可变的 uid 寻址（`/channels/<uid>/<tab>`），所以改名不会让链接失效。活动和同步仍然用 `?tab=` 表示标签页（`/activity?tab=mcp`，全部是不带参数的 `/activity`；`/sync?tab=remote`），树里打开的文件是 `?file=`。打开的对话是 `/conversations/<id>`，**新建对话**打开的草稿是 `/conversations/new`；列表的筛选条件是查询参数（`/conversations?source=seatalk&agent=codex`、`?channel=<uid>`）。

**列表的外观和行为一致。**每个列表页都用同一种表格，带搜索、筛选、分页和批量选择，点击一行打开它的详情页。每个行操作都有文字标签。

**生效范围是同一个控件。**智能体消费的资源在详情页上，以及在表格里的行上，都带一个**生效范围**按钮（MCP 服务器和技能列表读取每一行的生效范围，把按钮放在打开的项上）：**所有智能体**、**只限选中的**，或一个都不选（休眠）。选择在面板关闭时写入一次，只对这台机器生效。选中多行可以一次为它们全部设置生效范围。对消息渠道来说，生效范围指它可以驱动的智能体；见[消息渠道](/zh/guides/channels#default-agent-and-scope)。知识集和记忆分区完全没有生效范围或状态控件：它们总是提供给所有智能体。

**空、加载中和出错状态都明确显示。**空列表显示一张欢迎卡片，给出下一步，比如**添加服务器**。加载中的列表保留表头，下面是骨架行。请求失败时显示可读的说明，从不是笼统的错误码。

**未知路径显示未找到页面。**应用不认识的任何地址都会显示一个未找到页面，侧边栏保持完整：它写明这个地址，在有相近页面时给出建议（**你是不是要找 /mcp-servers**），并提供**返回总览**和**搜索 Coffer**（即命令面板）。

文件树和预览（在技能、知识和智能体页面，以及记忆分区的列表里）会填满窗口直到底部，并在内部滚动。在文件查看器里，**Cmd+F**（**Ctrl+F**）搜索文件内容。

## 守护进程无法访问时 {#when-the-daemon-is-not-reachable}

界面每 30 秒检查一次守护进程。它不再应答时，界面会在 1、2、4、8 秒后重试，并在工作区顶部显示正在发生什么，侧边栏保持可用：

| 状态 | 何时 | 你看到的 |
| --- | --- | --- |
| **正在重新连接守护进程…** | 停止应答后的前 10 秒（如果从未应答过，则是**正在连接守护进程…**）。 | 页面停在原处，变暗并暂停，上方是一条横幅，计数重试次数并说明没有丢失任何东西，带**立即重试**。底部显示**正在重新连接…**。 |
| **Coffer 的守护进程没有运行** | 之后。 | 页面让位给一个屏幕，写明界面访问的地址、下次检查的时间和守护进程上次应答的时间，带**重试**。底部显示**守护进程离线**。 |
| **守护进程版本过旧** | 桌面应用连上了一个由早期版本留下、仍在运行的守护进程。仅桌面应用。 | 页面上方一条横幅，带**重启守护进程**。 |

离线屏幕提供的恢复方式取决于宿主。在浏览器里，它显示要运行的命令 `coffer daemon start`，因为页面无法启动守护进程。在桌面应用里，它显示**启动守护进程**。无论哪种，守护进程重新应答时屏幕会自己消失，不需要重新加载：每个列表都会重新读取，并出现一条**已重新连接**提示。
