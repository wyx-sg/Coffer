# Web 界面 {#web-ui}

Coffer 的 Web 界面是你管理保险库里一切的地方：智能体、MCP 服务器、技能、知识、记忆、提供商、消息渠道，也是你和智能体对话的地方。本页讲界面是怎么提供的，带你看一遍侧边栏、命令面板和设置窗口，并列出各页面共有的约定。[桌面应用](/zh/guides/desktop-app)在一个原生窗口里承载同一个界面。

## Web 界面与命令行各做什么 {#what-the-web-ui-and-the-command-line-each-do}

所有管理操作都在 Web 界面里。命令行只承载确实需要它的：程序要运行它（记忆钩子、智能体的密钥助手）、守护进程停着时也必须能用（`coffer daemon start|stop|restart|status`、`coffer path logs`、`coffer config` 里守护进程自己的端口）、Coffer 交接给智能体的提示词让它运行（`coffer run`、`coffer secret list|set`、`coffer log audit|mcp|daemon`、`coffer mcp test`），或者 Web 界面做不到（`coffer vault problems`，列出保险库拒绝的手工编辑）。其余一切——添加服务器、连接智能体、切换提供商、查看用量——都是这里的一个页面。

## 打开界面 {#open-the-ui}

先启动守护进程（[桌面应用](/zh/guides/desktop-app)会替你做，或运行 `coffer daemon start`），然后在浏览器里访问 `http://127.0.0.1:<port>/`，`<port>` 是 `~/.coffer/daemon.json` 里的端口。页面不传任何凭据：由守护进程提供，这本身就是认证。

守护进程默认监听 38470 端口，所以 `http://127.0.0.1:38470/` 足够稳定，可以加书签。如果别的程序需要 38470，用 `coffer config set daemon.port <port>` 把 Coffer 挪开（这是命令行唯一能改的设置，因为它在页面加载之前就要读取）；见[运行守护进程](/zh/guides/daemon)。

## 界面是怎么提供的 {#how-the-ui-is-served}

守护进程自己在它的回环地址上提供构建好的前端，所以页面和 API 同源。没有单独的 Web 服务器，也没有登录页。

- **令牌就在页面里。**守护进程每次提供 `index.html`（无论是 `/` 还是 `/agents` 这样的前端路由），都会把当前的 API 令牌作为 `window.__COFFER_TOKEN__` 写进文档。守护进程提供的任何页面都能调用 API；浏览器里什么都不保存。
- **页面从不缓存。**`index.html` 带 `Cache-Control: no-store` 提供，所以重启后的守护进程的新令牌总能到达页面。`/assets` 下带哈希的文件照常缓存。
- **只回应守护进程自己的地址和页面。**`Host` 不是其端口上的 `127.0.0.1`、`localhost` 或 `[::1]` 的请求会被拒绝（`403 HOST_NOT_ALLOWED`），这可以阻止恶意网页用 DNS rebinding 读到令牌。来自其他任何源的页面发出的请求也会被拒绝（`403 ORIGIN_NOT_ALLOWED`）。守护进程自己的源和桌面应用总是被允许。要用开发服务器，启动守护进程时设置 `COFFER_DEV_CORS=1` 以允许端口 5173 上的 Vite，或者把源列在 `COFFER_CORS_ORIGINS` 里。见[安全模型](/zh/architecture/security#allowing-a-development-origin)。

::: warning
任何能从你机器的回环地址加载这个页面的人都能使用保险库。Coffer 是单用户的本地应用：不要把守护进程的端口转发给其他机器。
:::

桌面应用无法用这种方式拿到令牌，因为它从自己的包里加载界面，而不是从守护进程加载。它通过 IPC 把同样的两个值交给页面；见[桌面应用](/zh/guides/desktop-app#how-it-connects)。

## 侧边栏 {#the-sidebar}

侧边栏按你来 Coffer 要做的事分组。**总览**在最上面，不属于任何分组，因为它汇总下面的一切；其后是五个分组。

| --- | --- | --- | --- |
| — | **总览** | `/` | 落地页：需要你处理的事、每个领域的健康状况，以及最近几次改动。见下面的[总览](#overview)。 |
| 智能体 | **智能体** | `/agents` | 这台机器上装的、由 Coffer 管理的 AI 智能体。每个智能体的页面有**总览**、**技能**、**MCP 服务器**、**Hooks**、**配置文件**和**会话**标签页，**插件**和**记忆**收在**更多**里；它的模型在总览里更改。见[智能体](/zh/guides/agents)。 |
| 智能体 | **模型提供商** | `/model-providers` | 厂商的接入地址和它们的 API 密钥，也就是智能体所用的模型，在**提供商** tab 里；经过它们的请求花了多少，在**用量** tab 里（`?tab=usage`）。见[模型提供商](/zh/guides/providers)和[用量](/zh/guides/usage)。 |
| 运行 | **对话** | `/conversations` | 你的消息渠道发起的对话，以列表呈现：标题、智能体、目录、最近活动和消息渠道；带搜索、按消息渠道和智能体的筛选，以及一个在你的终端里恢复会话的行。见[对话](/zh/guides/chat)。 |
| 运行 | **消息渠道** | `/channels` | 让你在 IM 里和智能体对话的 Telegram 和 SeaTalk 机器人：配置、连接状态和设置；每个都链接到它的对话。见[消息渠道](/zh/guides/channels)。 |
| 能力 | **MCP 服务器** | `/mcp-servers` | Coffer 聚合在一个端点后面的上游 MCP 服务器。见 [MCP 服务器](/zh/guides/mcp-servers)。 |
| 能力 | **自定义工具** | `/custom-tools` | 智能体作为工具调用的 HTTP API 请求，见[自定义工具](/zh/guides/custom-tools)。 |

| 能力 | **命令行工具** | `/clis` | 你的技能需要的命令行工具，以及每个是否已安装，见[命令行工具](/zh/guides/clis)。 |
| 上下文 | **知识** | `/knowledge` | `~/.coffer/vault/knowledge/` 下的文档知识集：一棵树旁边是只读的阅读器，可以在你的编辑器里打开文档，还有每个知识集上的**整理**按钮和**整理全部**，以及每篇文档上的**历史…**。见[知识](/zh/guides/knowledge)。 |

| 系统 | **密钥** | `/secrets` | 每个已保存的密钥及其使用者：添加、更换、删除，补上这台 Mac 上缺失的值、答复审批。见[密钥](/zh/guides/secrets)。 |
| 系统 | **活动** | `/activity` | 改了什么、智能体调用了什么、守护进程记录了什么：**全部**合并成一条流，然后是**变更**、**工具调用**和**守护进程日志**。见[活动与审计](/zh/guides/activity)。 |
| 系统 | **同步** | `/sync` | 让这个保险库和你自己的 git 远端收敛，分为**状态**、**机器**和**远端**标签页，另有**解决冲突**（`/sync/conflicts`）和**审阅暂停的删除**（`/sync/deletions`）视图。见[保险库同步](/zh/guides/vault-sync)。 |

中文界面里的分组名是 智能体 · 运行 · 能力 · 上下文 · 系统，agent 一律叫作智能体。

属于[实验功能](/zh/guides/experimental-features)的入口，**实验**标记出现在页面标题旁和**设置 › 功能**里；侧边栏的行本身不带标签，折叠的图标栏上它的提示写着 **Knowledge · Experimental**。功能关闭时它看起来就像不存在：入口不出现在侧边栏里；一个分组的入口全部关闭时，分组标题也一并去掉；点链接进入它的页面会看到标准的「未找到」页面。这样的功能共四个：知识、记忆、同步和模型提供商（含它的用量标签页）。

**没有徽标。**侧边栏不带任何计数或圆点：所有需要你处理的事都列在**总览**的**需要你处理**下，桌面应用的菜单栏显示同一个计数。

**标题栏。**在桌面应用里，窗口顶部有一条与侧边栏同色的细条，只放窗口的红绿灯、**侧边栏开关**和**前进/后退箭头**——只有打开的[对话](/zh/guides/chat)是例外：它的标题、来源和 **⋯** 菜单放在侧边栏右侧的这一段里。在浏览器里没有这一条：Coffer 标志和侧边栏开关在侧边栏顶部，前进后退交给浏览器自己。

**后退和前进。**箭头（**⌘[** 和 **⌘]**）在你访问过的应用页面间移动，没处可去时变灰。页面本身没有返回按钮或「返回列表」链接；箭头是唯一的返回方式，从列表打开的详情页也用它退出。

**折叠和调整宽度。**侧边栏开关（**⌘\\**，其他系统是 **Ctrl+\\**）把侧边栏折叠成 56 像素的图标栏，或再展开；选择会被记住。展开时，拖动右边缘的细线可以调宽或调窄（见[调整分栏宽度](#resizing-split-views)）。

**页面布局。**每个页面上方留 16 像素、左右各留 32 像素。页面头部左边是标题，右边是操作，标题下面一行说明。页面内部，带边框的盒子装的是一组东西（一个行列表、一张表），而某个东西自己的属性则是用细线分隔的普通行，外面不加盒子。


## 总览 {#overview}

**总览**是应用打开时显示的页面。它分三部分回答「一切正常吗，有什么需要我？」：

- **需要你处理**：每个领域的每个问题一行，按严重程度排序，再按时间从早到晚。每一行写明它涉及的对象（一个服务器、一个智能体、一个消息渠道、保险库的同步），用一句话给出原因和开始时间，并有一个按钮，打开你处理它的页面或标签页。按钮会按问题的类型说明它要做什么（**重新连接渠道**、**查看被暂缓的变更**、**添加密钥**、**修复钩子**），前面带一个小图标；较长的原因最多折成两行，悬停可看全文。如果智能体设置里的记忆 Hook 被手动改过，而 Coffer 无法重写它，这一行会打开那个智能体的**钩子**标签页，那里有**修复钩子**。重新测试 MCP 服务器、重新检查某个命令会直接在这一行里进行：按钮变成禁用的**重试中…**或**检查中…**，下方出现一行蓝色说明，问题消失后这一行就离开列表（问题还在则按钮恢复原样）。连接智能体、修复它的文件等会改动 Coffer 之外内容的操作，仍然打开各自的页面，在那里先预览再改动。这个列表就是守护进程的待处理列表（`GET /api/v1/attention`）。行会自己消失：页面跟随守护进程的事件流，问题一解决，对应的行就不见了。如果某个领域检查失败，页面会在行上方说明，因为那个领域本该报告的内容都缺了。提示词和该项页面上提供的是同一个；**交给 &lt;Agent&gt;**需要有 Coffer 托管的智能体。每一行无论严重程度，都有一个主按钮、一个拆分按钮**交给 &lt;Agent&gt; ▾**（在你的首选终端里启动交接智能体，提示词作为它的第一条消息；它的菜单里是**交给**另一个智能体和**复制提示词**，后者是给 Coffer 之外的智能体用的修复提示词）和一个装着**忽略**的 **⋯** 菜单。被忽略的项会从总览和菜单栏计数里消失；Coffer 把这个选择记在这台 Mac 上（不同步到你的其他机器），对智能体本身没有任何改动。被忽略项自己的页面在标题下有一行淡色说明（“… — ignored on Overview”），带**重新显示**，可把它放回总览。页面横幅的 **×** 就是这同一个**忽略**，被忽略的内容在情况变化时（比如冲突的文件换了一批）会自己回来。密钥增加两行：“N 个密钥在这台 Mac 上没有值”（**打开密钥**）和“N 项改动等待批准”（**查看**，打开审批对话框）。列表大约显示六行，在自己的框内滚动。没有需要你处理的事时，会有一张平静的卡片说明这一点，用一句话说出哪些是正常的（“两个智能体都已连接，12 个服务器在正常响应，你的 vault 已同步。”），并写明上次检查的时间。**最近活动**不显示已关闭的实验功能所涉及的变更。
- **健康状况**：每个领域一块：智能体、MCP 服务器、技能、知识、记忆、模型提供商、消息渠道、同步、自定义工具、命令行工具、密钥和用量（它打开模型提供商的用量 tab）。每块显示一个状态词、一个数量和一行摘要，点击打开该领域的页面。智能体和消息渠道显示“1 / 2 已连接”（重新连接中的渠道会带上时间）；MCP 服务器显示最近 24 小时的调用和错误；知识显示集合数和最近一次编辑；记忆显示最近更新；同步显示上一轮结束的时间以及落后、领先的提交数；需要处理的命令行工具按原因说明（“1 个未登录”）；没有被使用的密钥只显示“2 个未使用”；用量显示最近 24 小时的 token 数、费用和各提供商的占比。加载失败的块会说明失败的原因并显示失败的请求，带**重试**和到它页面的链接，页面其余部分照常工作。
- **最近活动**：最近几次改动，带一个到[活动](/zh/guides/activity)的链接。

在登记任何智能体之前，总览会先引导你连接一个。它列出 Coffer 支持的智能体，每个带配置文件夹，以及是否在这台机器上找到。找到的会打勾，**查看并连接**会在 Coffer 写入任何东西之前展示每一处文件改动。如果一个都没找到，它会说明，并提供**重新扫描**；每个没找到的智能体一行显示**未找到**，并带一个指向该智能体官方安装页面的**安装 ↗**链接。**手动添加智能体**打开智能体页面，下面还有智能体之间共享的每样东西的第一步。

## 搜索或跳转 {#search-or-jump-to}

侧边栏顶部的**搜索或跳转…**控件打开命令面板；在任何地方按 **⌘K**（**Ctrl+K**）也可以。输入几个字母，用方向键移动，按 **Enter** 前往，按 **Escape** 关闭并回到原处。

命令面板只用于导航：它带你去页面和对象，从不执行操作；操作留在各自的页面上。它能找到：

- **页面**：每个侧边栏入口和每个设置标签页。页面总是可用，即使守护进程离线。
- **对象**：你的智能体、模型提供商、对话、消息渠道、MCP 服务器、自定义工具、技能、命令行工具、知识集、记忆分区和密钥，按名称匹配（有标题的类型也按标题匹配），列表里有状态词的会带上状态词（**异常**、**已关闭**、**缺失**）；技能的行还会写出它被投递到哪些智能体（**技能 · Claude Code · Codex**）。每种类型各自加载：加载中时面板会说明，某一种加载失败只有那一种显示错误。守护进程无法访问时，面板只列出页面，并说明对象需要守护进程。

什么都没输入时，它在所有页面上方显示**最近**：你最近从面板打开过的几样东西，记在这个浏览器里。一旦开始输入，唯一的最佳结果以**最佳匹配**打头（名称完全一致的优先），然后是其他匹配的页面，再是按类型分组、按侧边栏顺序排列的匹配对象。什么都没匹配到时会说明。

已关闭的[实验功能](/zh/guides/experimental-features)的页面和对象不会出现，界面其他地方也是如此。

## 侧边栏底部 {#the-sidebar-footer}

侧边栏底部从上到下是：

- **更新已就绪**：在桌面应用里，发现新版本时出现：一张写明版本的卡片，带**重启**（下载新版本、校验签名、安装并重新打开 Coffer）和**新内容**（设置 › 关于）。关掉它，下次启动时还会出现；它从不是弹窗。
- **设置**：一个齿轮加「设置」二字（提示 **Settings ⌘,**）。它总是打开**设置 › 通用**，窗口打开时高亮。折叠的图标栏上只有齿轮。

底部不显示任何守护进程状态，也没有版本菜单。守护进程出问题时，会在你不可能错过的地方提示：连接恢复期间页面上方有一条**正在重新连接…**横幅，守护进程消失后是整页离线页面（桌面应用里带**重启守护进程**）。主题和语言只在**设置 › 通用**里；版本和**检查更新**在**设置 › 关于**里。

## 设置 {#settings}

设置以一个大窗口的形式打开在当前页面上方，所以关掉它会让你回到原来的位置。用**设置**这一行打开，或者在没有输入框聚焦时按 **⌘,**（**Ctrl+,**），或者从命令面板打开。每个字段改完即保存，没有保存按钮。每个标签页以标题和一行说明开头，各区块是带一行描述的普通标题，行之间用细线分隔，区块之间留足空白，而不是盒子。对话框里主操作旁是一个朴素的**取消**。

共有六个标签页，顺序如下：

| 标签页 | 地址 | 包含内容 |
| --- | --- | --- |

**每个标签页都有自己的地址。**打开一个标签页会把 URL 改成 `/settings/<tab>`，所以书签或分享的链接能直接打开那个标签页。用 **×**、**Escape**、点击窗口外部或浏览器的**后退**按钮关闭窗口：你会回到下面的页面，地址也是它自己的。如果你直接加载一个 `/settings/<tab>` 地址，它会打开在**总览**上方，关掉后落在 `/`。

主题、每页行数、首选编辑器、首选终端和交接智能体保存在你的浏览器里，从不发给守护进程，除非是打开文件时作为目标应用。停止守护进程只能用 CLI（`coffer daemon stop`）：在页面上停掉它，页面也会跟着挂掉。轮换访问令牌在**设置 › 安全**里；页面会装上新令牌并继续工作，其他打开的标签页和使用旧令牌的客户端会停止工作，直到它们加载新令牌。查看或复制密钥、备份主密钥，以及批准待处理的[审批](/zh/guides/secrets#approvals)，都只在[桌面应用](/zh/guides/desktop-app#presence-checks-and-approvals)里提供，因为每一项都需要浏览器做不到的 Touch ID 或密码验证；浏览器标签页在这些位置显示 **Open in Coffer app**。

### 首选终端与交接智能体 {#preferred-terminal}

**设置 › 通用 › 表格与文件**下的两个选项决定 Coffer 把你交给智能体时它在哪里打开：对话或会话行（**在终端中打开**）、交接按钮（**交给 &lt;Agent&gt;**），以及知识和记忆页面上的**整理**与**整理全部**。两者都和**打开文件的方式**一样保存在这个浏览器里。

**首选终端**的做法和首选编辑器一样：

- **系统默认**是平台自带的终端。在 macOS 上是 Terminal；在 Linux 上 Coffer 依次尝试 `x-terminal-emulator`、`gnome-terminal` 和 `konsole`。
- Coffer 在这台机器上检测到的终端按名字列出：macOS 上是 Terminal、iTerm、Warp 和 Orca，Linux 上是 GNOME Terminal 和 Konsole。
- **自定义命令**接受一个命令模板，用于 Coffer 没有列出的终端。在工作目录的位置写 `{cwd}`，在智能体命令的位置写 `{command}`，例如 `mycterm --workdir {cwd} -e {command}`。Coffer 把模板拆成参数后直接运行，不经过 shell，所以占位符不需要再加引号。

第一次由 Coffer 控制 Terminal 或 iTerm 时，macOS 会询问是否允许 Coffer 控制它（自动化权限）。请选择允许。如果拒绝过，可以到**系统设置 › 隐私与安全性 › 自动化**里重新打开，或者换一个终端。

**交接智能体**是交接按钮启动的智能体：Claude Code 或 Codex。按钮上写着**交给 &lt;Agent&gt;**，带着该智能体的名字；▾ 菜单里有另一个智能体（已安装时）和**复制提示词**。没有托管智能体时只提供**复制提示词**。按下按钮无需确认：终端在正确的目录里打开，智能体启动并把提示词作为第一条消息。提示词通过私有的临时文件交给智能体，从不出现在命令行或 shell 历史里；智能体按它自己的权限模式运行，所以你能看到它被要求做什么，并用 Esc 或 Ctrl-C 随时停下它。

终端无法启动时，会弹出提示说明原因。**复制提示词**以及会话行上的**复制命令**始终可用。

## 调整分栏宽度 {#resizing-split-views}

窗口左右分栏的地方（侧边栏和页面之间，对话列表和打开的对话之间），两半由一条可以拖动的细线隔开。鼠标悬停或拖动时，这条线以强调色高亮。

- **拖动**它调整宽度。**双击**它恢复默认宽度。
- **用键盘**：用 Tab 移到这条线上，按 **←** 或 **→** 小步移动。
- **限制保证两边都可用。**侧边栏宽度保持在 200 到 300 像素之间（默认 220）。列表至少 240 像素，最多占分栏的一半，旁边的详情至少保留 480 像素。
- **宽度按页面记在这个浏览器里。**这只是个便利：另一个浏览器、桌面应用或无痕窗口都从默认值开始，什么都不发给守护进程。

## 浅色和深色 {#light-and-dark}

界面跟随系统的浅色或深色外观，系统切换时也跟着切换。要自己选，在**设置 → 通用 → 主题**里选**浅色**或**深色**；**跟随系统**会恢复跟随系统。选择立即生效，保存在 `localStorage` 的 `coffer.theme` 下，所以每个浏览器和桌面应用各自保存自己的选择。两套主题是怎么构建的见[设计系统](/zh/architecture/design-system)。

## 语言 {#language}

在**设置 → 通用 → 语言**里，在 **English** 和**简体中文**之间切换。所有标签立即改变，不需要重新加载，选择保存在 `localStorage` 的 `coffer.language` 下。关于标签页没有语言控件。

## 所有页面共有的约定 {#conventions-every-page-shares}

**URL 描述你正在看的东西。**刷新、书签或分享的链接会重新打开同一个视图。详情页的标签页是路径的一部分：默认标签页是不带后缀的地址，其他标签页加上自己的名字，比如 `/mcp-servers/github` 和 `/mcp-servers/github/tools`。技能和 MCP 服务器按名称寻址，名称在登记后就固定了（`/skills/release-notes`）；智能体按类型寻址，因为每种类型只有一个（`/agents/claude_code/skills`）。可以改名的类型（模型提供商、消息渠道、知识集、记忆分区）按不可变的 uid 寻址（`/channels/<uid>/<tab>`），所以改名不会让链接失效。活动、同步和模型提供商的用量仍然用 `?tab=` 表示标签页（`/activity?tab=mcp`，全部是不带参数的 `/activity`；`/sync?tab=remote`、`/model-providers?tab=usage`），活动和用量还把搜索、时间范围和筛选也保存在地址里，树里打开的文件是 `?file=`。对话列表的筛选条件是查询参数（`/conversations?source=coffer,<channel uid>&agent=codex&q=sentry`）。

**列表的外观和行为一致。**每个列表页都用同一种表格，点击一行打开它的详情页。每个行操作都有文字标签。

- **筛选**在一行里：先是搜索框（按 `/` 跳进去），然后是各个筛选标签，只要设置了任何一项就有**清除筛选**。它们不显示结果数量。
- **排序**只在数字和时间列上，三态：点一次表头是一个方向，再点是另一个方向，第三次回到页面自己的顺序。
- **长列表**只显示几行，并写着“Showing 5 of 23 · Show all”；随滚动加载更多的页面会说明已显示多少、一共多少，并提供下一页的按钮。
- **时间**在较近时用相对时间（“3 h ago”），之后用日期（“Aug 12”）。
- **选择**行时用表头复选框选中整个列表。表格上方的操作栏显示“N of M selected”和适用的操作，其中没有全选，按 **Esc** 清除选择。
- 在列表旁边打开的**详情**都用同一个右侧抽屉，页面变暗；默认 640 像素宽，拖动左边缘可调宽窄（双击边缘恢复）；**Esc**、点击外部或 ✕ 关闭它，焦点回到那一行。

**把问题交给智能体。**安装、设置、登录和排障都取决于机器，所以 Coffer 把它们交给智能体，而不是打印命令。交接是一个拆分按钮**交给 &lt;Agent&gt; ▾**：按钮本身在你的首选终端里启动默认的交接智能体（**设置 › 通用 › 交接智能体**，Claude Code 或 Codex），并把提示词作为第一条消息发出，无需确认。提示词通过一个私有的临时文件交给智能体，从不出现在命令行或 shell 历史里。▾ 菜单里有**交给**另一个智能体（它可用时）和用于 Coffer 之外智能体的**复制提示词**，复制后会弹出“已复制提示词”。没有 Coffer 托管的智能体时只提供**复制提示词**。Coffer 自己能做的事保持为按钮（**重试**、**再检查一次**、**测试**）。

**横幅可以忽略。**页面顶部提示需要你处理的事情的横幅带一个 **×**。它和总览上的**忽略**是同一件事：这一项从页面、总览和菜单栏计数里消失，页面标题下随后写着“… — ignored on Overview. Show it again”，情况变化时它会自己回来。

**生效范围是同一个控件。**智能体消费的资源在详情页上有一个**生效范围**按钮，在表格里则是行上的一个徽标（MCP 服务器和技能列表把按钮放在打开的项上）：**关闭**、**所有智能体**或**指定智能体**（一个都不选就是休眠）。**所有智能体**也包括以后新增的智能体。选择在你修改的那一刻就保存，面板里先显示“正在应用…”再显示“✓ 已保存”，只对这台机器生效。选中多行可以一次为它们全部设置生效范围。对消息渠道来说，生效范围指它可以驱动的智能体；见[消息渠道](/zh/guides/channels#default-agent-and-scope)。知识集和记忆分区完全没有生效范围或状态控件：它们总是提供给所有智能体。

**改动即保存。**设置、生效范围和模型提供商在你一选择时就生效。Web 界面没有文档编辑器，所以没有**保存**按钮，离开页面时也不会询问：技能的 `SKILL.md`、知识文档、记忆条目和智能体的配置文件都以只读方式显示，带**在编辑器中打开**和**在访达中显示**，你在自己的编辑器里改它们（**设置 › 通用**），或者让你的智能体去改。

**列表的搜索只匹配名字。**列表（服务器、工具、技能、渠道、模型提供商、密钥……）上方的搜索框只匹配每一项的名字，有标题的也匹配标题——从不匹配描述、端点或路径——所以搜到的就是你在行里看到的。对记录的搜索，比如活动和对话，匹配的是记录的文字。

**空、加载中和出错状态都明确显示。**空列表显示一张欢迎卡片，给出下一步，比如**添加服务器**。加载中的列表保留表头，下面是骨架行。请求失败时显示可读的说明，从不是笼统的错误码。在列表与详情并排的页面（MCP 服务器、技能、命令行工具、消息渠道、自定义工具、模型提供商、知识）上，每种状态都出现在它所属的位置：列表加载不出来时，列表面板里、筛选框下方显示**无法加载……**，带**重试**、**打开守护进程日志**（活动 › 守护进程日志）和失败的请求（`GET 路径 · 状态 · trace id`），可以直接贴进问题报告；筛选没有匹配时显示**没有服务器匹配“terraform”**和**清除筛选**；地址指向的对象已不存在时显示**这个服务器已不存在**，带该地址、它在审计日志里最后出现的时间、**返回 MCP 服务器**和**在活动中查看**。

**未知路径显示未找到页面。**应用不认识的任何地址都会显示一个未找到页面，侧边栏保持完整：它写明这个地址，在有相近页面时给出建议（**你是不是要找 /mcp-servers**），并提供**返回总览**和**搜索 Coffer ⌘K**（即命令面板）。

文件树和预览（在技能、知识和智能体页面，以及记忆分区的列表里）会填满窗口直到底部，并在内部滚动。在文件查看器里，**Cmd+F**（**Ctrl+F**）搜索文件内容。

## 守护进程无法访问时 {#when-the-daemon-is-not-reachable}

界面每 30 秒检查一次守护进程。它不再应答时，界面会在 1、2、4、8 秒后重试，并在工作区顶部显示正在发生什么，侧边栏保持可用：

| 状态 | 何时 | 你看到的 |
| --- | --- | --- |
| **正在重新连接守护进程…** | 停止应答后的前 10 秒（如果从未应答过，则是**正在连接守护进程…**）。 | 页面停在原处，变暗并暂停，上方是一条横幅，计数重试次数并说明没有丢失任何东西，带**立即重试**。 |
| **Coffer 的守护进程没有运行** | 之后。 | 页面让位给一个屏幕，写明界面访问的地址、下次检查的时间和守护进程上次应答的时间，带**重试**、可复制的 `coffer daemon start` 命令；在桌面应用里还有**打开守护进程日志**，直接用系统查看器打开日志文件，在浏览器里则改为显示可复制的 `coffer log daemon`（活动页需要守护进程）。 |
| **守护进程版本过旧** | 桌面应用连上了一个由早期版本留下、仍在运行的守护进程。仅桌面应用。 | 页面上方一条横幅，带**重启守护进程**。 |
| **Coffer 需要 git** | 守护进程有响应，但在等 git：没有安装，或版本低于 2.40。 | 每个页面都换成同一个界面，说明问题所在以及保险库用 git 保存历史并同步，带**复制提示词**（让你的智能体安装或更新 git 的提示词）和**重新检查**；git 就绪后它会重启守护进程并进入应用。见 [Coffer 需要 git](/zh/guides/troubleshooting#coffer-needs-git)。 |

离线屏幕提供的恢复方式取决于宿主。两种宿主都显示要运行的命令 `coffer daemon start`（**或者在终端里启动它**），因为页面无法启动守护进程；桌面应用还会显示**启动守护进程**。无论哪种，守护进程重新应答时屏幕会自己消失，不需要重新加载：每个列表都会重新读取，并出现一条**已重新连接**提示。
