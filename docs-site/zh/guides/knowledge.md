# 知识 {#knowledge}

知识是一个存放工作环境相关 Markdown 的目录：服务、仓库、约定、决策、坑，这台机器上的每个智能体都会读。每个知识集都是一个文件夹，用它自己的**规则文件**决定自己的格式，就像一个 Obsidian 库怎么组织由你自己定；新建的知识集可以从 LLM wiki 起步，页面由保留下来的来源编译而成。本页讲如何创建知识集、添加文件、你和你的智能体如何修改它们、你按**整理**时智能体如何按知识集的规则整理它、一次整理如何记成一次可以撤销的改动、Coffer 唯一检查的东西（失效链接）、如何回看文件的历史并找回某个版本、如何在 Obsidian 中打开知识集，以及智能体如何找到这些内容。

## 知识用来做什么 {#what-knowledge-is-for}

知识存放的是你所处环境里的事实：哪个团队负责某个服务，某个内部 API 怎么鉴权，某个迁移为什么按这个顺序。它之所以在那里，是因为你或者和你一起工作的智能体把它放了进去。

- **所有智能体共用一份。** Claude Code 和 Codex 读的是同一批文件，一个智能体上午记下的东西，另一个下午就能读到。
- **普通文件。** 每个文件都是 Markdown，你可以打开、编辑、grep、备份。Coffer 不建索引、不做 embedding，也不在数据库里另存一份内容。
- **每个知识集自己定格式。** 知识集怎么组织、文件带哪些 frontmatter、怎么保持最新，都写在它的规则文件里，你和你的智能体都可以改。Coffer 不赋予任何文件夹、页面类型或 frontmatter 键自己的含义，只检查链接是否指得到东西。
- **共同编写。** 你在自己的编辑器里编辑文件，知识页面只以只读方式显示它们并把它们交给编辑器打开；智能体用自己的文件工具写，遵循知识集的规则文件。你按**整理**时，你的智能体按这些规则整理知识集并修好失效链接，整次整理记成一次你可以撤销的改动。Coffer 自己不在你的知识上运行任何模型。

知识不是[记忆](/zh/guides/memory)。记忆是智能体在工作中学到的东西，从它们各自的记忆库里读出来；知识是有人刻意写下来的东西。

## 知识集的结构 {#how-a-collection-is-laid-out}

**知识集**是知识根目录下的一个顶层文件夹。里面放什么由知识集自己决定。从 **LLM wiki** 模板起步的知识集（见[创建知识集](#create-a-collection)）是这样的：

```text
~/.coffer/vault/knowledge/
└── payments/                        ← one collection
    ├── README.md                    ← its description, and what it declares to Coffer
    ├── AGENTS.md                    ← its rules file: how it is written and kept
    ├── index.md                     ← its start page
    ├── pages/
    │   ├── session-ownership.md
    │   └── gateway/
    │       └── rate-limits.md
    ├── sources/                     ← its uploads folder: uploads land here
    │   ├── release-notes.md         ←   an upload converted to Markdown
    │   └── gateway-design/          ←   an upload with pictures: one folder
    │       ├── gateway-design.md
    │       └── image-1.png
    └── .inbox/                      ← hidden: a drop zone, moved to the uploads folder at the next sweep
```

- 知识集根目录的 **`README.md`** 说明这个知识集是什么。它在第一个 `##` 小节之前的第一段，就是 Coffer 所有显示知识集描述的地方用的描述，也是 `coffer-guide` 技能告诉智能体这个知识集讲什么的依据。它的 frontmatter 可以向 Coffer 声明三件事，都是可选的（见[README 声明什么](#what-a-readme-declares)）。它从不计入知识集的文件数。
- **规则文件**说明这个知识集怎么写、怎么维护：它的结构、文件带哪些 frontmatter、先读什么、一次整理检查什么。智能体写任何东西之前都会先读它，它优先于智能体默认会做的任何事。它就是知识集里的一个普通文件：改它，就改了知识集的维护方式。
- **入口页**，比如一个 `index.md`，是知识集指定了入口页时智能体开始阅读的地方。
- **上传文件夹**（默认是 `sources/`，README 可以另指一个）是 Coffer 写入上传文件和放进收件箱的文件的地方，都转换成 Markdown（见[上传文档](#upload-a-source)）。带图片或附件的上传在那里是一个单独的文件夹，文件和图片放在一起；它们和 Markdown 一样随知识集同步，也有历史。你上传的文件本身不放进知识集：Coffer 把它留在你上传它的那台 Mac 上（见[图片和原文件](#pictures-and-the-original-file)）。
- **其他所有文件和文件夹**都是知识集自己的。Coffer 在树里列出它们、检查它们的链接，从不移动它们。
- **隐藏条目**（以 `.` 开头的名字）不计入任何计数，也不进目录和检查，知识页面不会列出其中任何一个。Coffer 会读的是 `.inbox/`：留在那里的 Markdown 文件会在下一次扫描时移进上传文件夹（见[放进收件箱的文件](#a-file-in-the-inbox)）。

文件的路径就是它所在的位置；它的 **slug**（去掉 `.md` 的文件名）是 `[[slug]]` 链接用的名字。文件名可以包含除 `/`、`\` 和控制字符以外的任何字符，但不能以 `.` 开头。

知识根目录位于保险库仓库里，即 `~/.coffer/vault/knowledge`，`coffer-guide` 技能会把它告诉每个智能体。它不能挪到别处：保险库外的目录树，它的历史就看不到了。

### README 声明什么 {#what-a-readme-declares}

知识集的 `README.md` 可以在 frontmatter 里带三个键。每个都是相对知识集的路径，每个都是可选的：

```markdown
---
rules: AGENTS.md
entry: index.md
uploads: sources
---

# payments

How payments are taken, settled and refunded.
```

| 键 | 含义 | 不写时 |
| --- | --- | --- |
| `rules` | 智能体在这里写或整理时遵循的文件。它可以是另一个知识集里的文件，比如 `../shared/rules.md`，让几个知识集遵循同一套规则。 | 知识集根目录下 `AGENTS.md`、`CLAUDE.md`、`README.md` 中第一个存在的。 |
| `entry` | 智能体开始阅读的页面。 | 没有：`coffer-guide` 的目录改为按文件夹列出知识集的文件。 |
| `uploads` | 上传文件和收件箱文件落地的文件夹，必须在知识集里。 | `sources/`。 |

如果某个键指向的文件不存在，或者路径爬出了知识根目录，就当作没写。README 里的其他键，以及任何其他文件里的任何键，都是知识集自己的：Coffer 不读 `type`、`sources`、`verified` 或其他任何键，也不要求任何文件带某个键。

### Frontmatter {#frontmatter}

Coffer 不要求任何 frontmatter。知识集的文件带哪些 frontmatter，由它的规则文件决定。Coffer 只读两个键，而且只用来显示文件：`title`，文件在列表里的名字（没有就用第一个 `#` 标题，再没有就用文件名）；`aliases`，`[[链接]]` 可以用来指向这个文件的其他名字，Obsidian 也读这个键。

Coffer 写进上传文件夹的文件，带着 Coffer 保留它时写入的键：`title`、`description`、`actor`、`created_at`、`updated_at`；从上传的文件转换来的还带有 `original`（文件名）和 `original_sha256`（它的指纹），导入的 Confluence 页面另外带有 `origin`（它来自哪里）和 `import_report`（导入保留了什么、漏掉了什么）。这些键请保持原样。上传的 Markdown 文件原本带的 frontmatter 会保留在唯一的那个块里，从不作为正文里的第二个块。你或智能体给文件加的其他任何键，Coffer 每次重写文件时都会连同值一起保留。

### 用 slug 或相对路径链接文件 {#link-pages-by-slug}

文件用 slug 链接另一个文件：`[[session-ownership]]`，或者用 `[[session-ownership|the session service]]` 来指定显示的文字。链接也可以写某个文件的 `aliases` 之一。两个文件 slug 相同时，和发出链接的文件在同一文件夹里的那个优先。

按相对路径写的普通 Markdown 链接也可以：`[the cache](cache-ttl.md)`、`[the design](../sources/gateway-design.md)`。它相对于包含它的文件来读，和任何 Markdown 阅读器的读法一样；在知识页面上，它会打开它指向的文件，在另一个知识集里也可以。

每次读取文件时，Coffer 都会解析其中的每个链接，slug 不区分大小写。什么都指不到的链接是**失效**的，指到不止一个文件的链接是**有歧义**的，爬出知识根目录的相对链接是**越界**的；三者都是[失效链接](#check-a-collection)，知识页面也会在文件里标出失效或越界的链接。上传文件夹里的链接不检查，因为导入的素材保留了导出工具原来的文字。网页链接在你的浏览器里打开。

## 创建知识集 {#create-a-collection}

知识集只能有意创建，而且只能由人创建。读、写、智能体的工作目录，或者智能体放进其他文件夹的 Markdown 文件，都不会创建知识集。

<Shot name="knowledge-page" alt="“知识库”页面，含一个集合及其文档。" />

```text
知识 → 添加 → 新建知识集… → 名称、这里放什么、起步模板 → 创建知识集
```

树顶部也有**新建知识集**按钮。**添加**菜单会说明每一项保存什么：新建的知识集存在 Coffer 里，同步到你的其他 Mac，保留历史，由你的智能体整理。这会创建 `~/.coffer/vault/knowledge/payments/`，以及一个以名字为标题、以你填的内容为描述的 `README.md`。**起步模板**决定它还带什么：

- **LLM wiki**（默认）加上 `AGENTS.md` 和 `index.md`，README 把它们声明为 `rules` 和 `entry`。规则是一个由智能体从保留来源编译出来的 wiki，参照 Andrej Karpathy 的 “LLM Wiki”：上传的素材作为来源保留在 `sources/` 下；`pages/` 下的页面每个负责一个主题，引用它依据的来源，并记下最近一次核对的日期；`index.md` 列出所有页面；整理时把等待中的来源并进页面，重新核对超过 90 天的页面，合并、拆分、修正页面。
- **空白**只写 README。需要时再加规则文件，或者让智能体按知识集现有文件的写法来写。

这些文件只复制进来一次，从此就是知识集自己的：在里面改规则、期限、页面类型或结构，智能体就按改过的来。Coffer 不会再读模板，所以升级 Coffer 不会改动知识集的规则。在命令行里，`coffer knowledge create --set name=payments --set template=blank` 选择模板（见 [`coffer knowledge create`](/zh/reference/cli/knowledge#knowledge-create)）。

知识集没有标题：所有页面和列表都按文件夹名显示它。它的描述就是 README 在第一个 `##` 小节之前的开头一段：可以在知识集页面直接修改（点一下文字，离开输入框时保存），也可以直接改文件。不管哪种方式，都只改这一段，下面的内容保持不变。

要重命名知识集，在它的页面上选 **⋯ → 重命名…**，输入新名字。它的文件夹会随之改名（`~/.coffer/vault/knowledge/<新名字>/`），页面仍停在这个知识集上，智能体从下一次目录更新起按新名字找到它。如果新名字已被别的知识集占用，或不是合法的文件夹名，会在输入框下方提示，什么都不会改。

**知识**页面的树里列出所有知识集。

## 添加知识 {#add-knowledge}

知识以知识集里的文件的形式生长。有五种方式。

### 由智能体提交：写进知识集 {#from-an-agent-write-into-the-pages}

智能体用自己的文件工具记录知识。连接到 Coffer 的智能体会读 `coffer-guide` 技能（见[连接客户端](/zh/guides/connect-a-client)），它给出知识根目录、每个知识集及其规则文件和入口页，并告诉智能体：在知识集里写任何东西之前，先读它的规则文件并照着做。没有规则文件的知识集，就按它现有文件的写法来写。

指南还告诉智能体要**把弄清楚的东西写回去**。当它通过读代码、某个系统或某份文档回答了你的问题，而知识集里还没有这个答案时，它会在结束前把答案写到知识集规则规定的地方，并用一句话告诉你它加了什么。它不会写回猜测、观点，或只在那次对话里成立的东西。每一次这样的写入都在知识集的历史里，你可以撤销。

你也可以直接说：“把我们刚查清楚的 session TTL 记到 payments 知识集里。”知识集必须已经存在；只有你能创建知识集。智能体写下的东西立刻可读，下一次扫描会把它提交进[历史](#history-and-restore)。它留在智能体写下的位置：Coffer 不移动任何文件。

### 上传文档 {#upload-a-source}

上传会把文件转换成 Markdown，连同其中的图片立刻保留在知识集的上传文件夹里。你上传的文件本身只留在这台 Mac 上（见[图片和原文件](#pictures-and-the-original-file)）。

```text
知识 → 添加 → 上传文档… → 选择或拖入文件，选知识集 → 上传
```

**添加**菜单会说明上传保存什么：每个文件转换成 Markdown，保存在你选的知识集里，并随它同步。上传对话框还会说明图片会一起保留，文件本身留在这台 Mac 上。

| 接受 | 格式 |
| --- | --- |
| 转换 | `pdf`、`docx`、`pptx`、`xlsx`、`xls`、`html`、`htm`、`epub` |
| 表格 | `csv`、`tsv` |
| Confluence 页面 | `json`，页面导出（见[导入 Confluence 页面](#import-a-confluence-page)） |
| 按文本读取 | `md`、`markdown`、`mdx`、`txt`、`text`、`rst`、`json`、`yaml`、`yml`、`toml`、`ini`、`cfg`、`log`、`sql`，以及常见源码文件（`py`、`js`、`ts`、`go`、`rs`、`java`、`sh` ……） |

比如上传一个 PDF，会得到 `sources/gateway-design.md`（README 另指了上传文件夹时就在那里；提取出的 Markdown 加上 frontmatter），带图片的话就变成一个文件夹：`sources/gateway-design/gateway-design.md`，`image-1.png` 等图片就在它旁边，这样一次上传可以整体移动或删除。按文本读取的文件（Markdown、纯文本、源码）也以同样的方式保留。名字和那里已有的文件或文件夹重复时，会加上后缀（`-2`）。

可以一次选择或拖入多个文件。每个文件单独列出它的状态（等待、正在转换、完成，或失败及原因），文件一个接一个地发送，一个失败不会挡住其余的。ZIP 压缩包和超过 20 MB 的文件在发送前就会标为拒绝并写明原因。失败的文件留在对话框里，可以重试；最后会有一条提示说明保存了几个、失败了几个。上传只选知识集，不选文件夹。不支持的类型会被拒绝，并指出是哪种类型；转换后没有文本的（比如纯图片 PDF）也会被拒绝。被拒绝的文件不会留下任何东西。

保留下来的文件的 `title` 取自文件（它 frontmatter 里的 `title`、第一行的 `# ` 标题，没有就用文件名）。它的 `description` 取 frontmatter 里的 `description` 或 `summary`，没有就取开头的正文，再没有时用标题。文件原有的其他 frontmatter 都保留在它唯一的 frontmatter 块里。之后怎么处理它，由知识集的规则决定：在 LLM wiki 知识集里，它是一个等着并进页面的来源，你按**整理**时（见[整理一个知识集](#tidy-a-collection)）或你随时请求时，你的智能体会去做。

### 导入 Confluence 页面 {#import-a-confluence-page}

Confluence 页面以页面导出的形式进来：你的 Confluence 工具为一个页面写出的 JSON，带有它的存储格式、标题、id、版本和 URL，下载了附件时还带有附件。像上传其他文件一样上传这个 `.json` 文件，或者在终端里：

```sh
coffer knowledge upload payments account-core.json --attachments account-core-files/
```

`--attachments` 按 Confluence 里的文件名，加上在导出文件旁边下载的一个文件夹里的文件。Coffer 把页面变成上传文件夹里一个你读得懂的 Markdown 文件：

- **正文读起来就是这个页面。** 每个宏都变成页面读者看到的样子：只负责排版内容的宏（编号标题、分节、分栏、展开、标签页）交回它的内容，信息、备注、提示或警告面板变成带标签的引用，代码块保留它的语言，带合并单元格的表格仍是表格。Confluence 从别处生成的内容，比如目录或子页面列表，会被略去并注明。读它时看不到任何 Confluence 自己的标记。
- **附件会保留。** 页面用到的图片和文件放在这个页面在上传文件夹里自己的文件夹中，和文件放在一起，文件按名字链接它们。图表按页面里原来的样子显示：作为附件的 draw.io 图表显示它的图片，draw.io 链接保持为那个链接，直接画在页面里的 draw.io 图表变成一个 **draw.io diagram** 链接，点它就在 draw.io 的查看器里打开。图表放在链接 `#` 后面的部分，浏览器从不把这部分发给服务器。PlantUML 图表以代码块显示它的源码。Coffer 不下载任何东西，不渲染任何图表，也不向任何外部服务发送任何东西。
- **导出文件本身就是转换后文件的原文件。** 和其他上传一样，它留在你导入它的那台 Mac 上，在保险库之外，标题下面一行显示**原文件**和它的名字（见[图片和原文件](#pictures-and-the-original-file)）。
- **它来自哪里** 作为 `origin` 写进文件唯一的 frontmatter 块：Confluence URL、页面 id、空间、版本和获取时间。知识页面在标题下显示**来自 confluence**和指向这个页面的链接。
- **漏掉了什么会说出来。** `import_report` 记录正文是否完整转换，并分别为附件和宏记下保留了什么、缺了什么、什么不支持，以及原因。有缺失时，上传对话框保持打开并列出它们，文件的说明行显示**部分导入**。

知识集里已有的页面（按页面 id 匹配）会被拒绝，对话框会提供**替换**。可以先运行 `coffer knowledge upload … --preview`，看到标题、文件和报告，而不写入任何东西。**替换**（`--replace`）把新版本保存为一个新文件，放在它自己的文件夹里（`-2`），并把旧的标为被它 `superseded_by`，这样你的智能体能分辨哪个是当前的。什么都不会被覆盖，改动记录里的**撤销**可以带回之前的状态。

在 Coffer 能读 Confluence 页面之前导入的页面，文件里可能还带着导出的标记。知识页面会以转换后的样子读它，并注明这一点，文件本身保持不动；用**替换**重新导入这个页面，就能让它变成上面的结构。

不保留的东西：其他页面的附件、来自其他服务的嵌入内容（Google Drive、Jira 图表），以及导出时没有下载的附件。每一项都列为缺失。

### 图片和原文件 {#pictures-and-the-original-file}

**图片。** PDF、幻灯片、Word 文档或网页里的示意图、图表和截图会和转换后的文件一起保留。它们放在转换后的文件旁边，在以这次上传命名的文件夹中，文件在它们原来出现的位置按名字链接每一张；PDF 的图片列在正文之后的 **Images** 下，按它们所在的页分组。在知识页面上阅读时它们直接显示在正文里，从树里打开一张图片会显示这张图片。智能体像打开其他文件一样打开它们。并不是每张图片都会保留：

- 小装饰（项目符号、分隔线、图标，任何一边不到 48 像素的图）会被丢掉；
- 在文档里反复出现的图片，比如每张幻灯片上的标志，只保留一份；
- 超过 5 MB 的图片会被丢掉，一次上传最多保留 40 张；
- 浏览器不能显示的格式会存成 PNG。

图片随知识集同步到你的其他 Mac，和知识集里的任何文件一样有历史。只有图片、没有文字的扫描 PDF 仍然会被拒绝。

**原文件。** 你上传的文件保存在你上传它的那台 Mac 上，在保险库之外，从不同步：幻灯片、PDF 这样的原文件很大，而智能体读的是 Markdown 和图片。转换后的文件会记下它，所以在那台 Mac 上打开它时，标题下面一行会显示**原文件**和文件名；点文件名就会用默认应用打开它，看到原来的版式。在你的其他 Mac 上，这一行写着**原文件 `<name>` 在上传的那台 Mac 上**。Markdown 或文本上传按原样保留，所以没有要保留的原文件，除非转换改写了它（Confluence 导出里的存储标记被转成可读内容），这时你上传的文件会像其他上传一样保留。

### 放进收件箱的文件 {#a-file-in-the-inbox}

Markdown 文件也可能出现在知识集隐藏的 `.inbox/` 文件夹里：来自 Coffer 之外的智能体、另一台机器，或旧版指南。

```text
~/.coffer/vault/knowledge/payments/.inbox/session-ttl.md
```

文件名无所谓，frontmatter 可有可无。下一次扫描会把这个文件移进知识集的上传文件夹（默认是 `sources/`，README 可以另指），并补全它缺的部分：

| Frontmatter | 补全来源 |
| --- | --- |
| `title` | 第一个 `# ` 标题，没有就用文件名。 |
| `description` | 第一段正文，没有就用标题。 |
| `actor` | `agent`，除非文件里另有写明。 |
| `created_at`、`updated_at` | 扫描发现该文件的时间。 |

写入者自己设置的内容都会保留，包括其他键，每个文件都会记入审计日志。和上传一样，之后怎么处理它由知识集的规则决定。只有知识集自己的 `.inbox/` 才算数。写在不是知识集的顶层文件夹里的 Markdown 文件不会被处理，也不会进目录：只有人才能创建知识集。收件箱里不是 Markdown 的文件原样留着。

### 在聊天里：让智能体来存 {#from-a-chat-ask-your-agent}

如果你配对了一个[消息渠道](/zh/guides/channels)，并没有专门的知识命令。把文档或这段对话发给聊天里的智能体（私聊或群组都行），让它存进知识，比如「把这个存进 payments」。智能体用自己的文件工具把它写进知识集，遵循知识集的规则。

### 自己编辑文件 {#edit-a-file-yourself}

用任何编辑器在知识集里写、改、删文件，本身就是修改知识的完整方式，不需要导入步骤。改动在下一次读取时就生效，下一次扫描会把它作为在磁盘上编辑提交进历史。按知识集规则文件的要求来写；指不到东西的链接，[检查](#check-a-collection)会告诉你。

在知识页面上，选中一个文件，用**在编辑器中打开**，或 **⋯** 菜单里的**在访达中显示**跳到文件。知识页面本身从不编辑文件：它只读地显示文件，下一次读取就会显示你的编辑器或智能体保存的内容。没有未保存状态，没有保存过期的拒绝，也没有离开前不保存的询问，因为页面上没有任何东西持有你的文字。在编辑器中打开用的是**设置 › 通用**里选择的编辑器。

要添加文件，把它存到知识集规则说的位置（知识集上的**在访达中显示**）。要添加需要转换的文档，用**添加 → 上传文档…**，或把 Markdown 文件放进知识集的 `.inbox/`。

智能体用自己的文件工具做同样的事，遵循 `coffer-guide` 技能指给它们的知识集规则文件（见[由智能体提交](#from-an-agent-write-into-the-pages)）。

## 整理一个知识集 {#tidy-a-collection}

时间一长，知识集会攒下要做的事：它的规则要求保持更新的东西，以及已经指不到任何地方的链接。Coffer 自己不去修。它把这件事交给你的智能体，由它用自己的文件工具读文件，并按知识集的规则编辑它们。

### 按下整理 {#press-tidy}

```text
知识 → 选择知识集 → 整理
知识 → 整理全部   （每个知识集，一个接一个）
```

**整理**会在你的首选终端里启动默认的交接智能体，把一份提示词作为它的第一条消息：写明知识集、它的文件夹、它的规则文件、Markdown 文件数，以及 Coffer 发现的每个失效链接（见[检查一个知识集](#check-a-collection)）。你可以在终端里看着智能体工作。知识页面页头的**整理全部**会以同样的方式发送一份提示词，写明每个知识集及其数量（包括有几个失效链接），请智能体一个一个地处理，并用 `coffer knowledge check <collection>` 读出每个知识集的失效链接。没有可用的托管智能体时，按钮改为提供**复制提示词**：把它粘贴到你用的任何智能体里。

提示词会让智能体去看 `coffer-guide` 技能的**整理一个知识集**一节。照着做，智能体一次处理一个知识集：

1. 在改动任何东西之前，用 `coffer knowledge tidy-start <collection>` **开始整理**（见[一次整理就是一次改动](#a-tidy-is-one-change)）。
2. **读知识集的规则文件，按它整理。** 规则说一次整理要检查和修什么，整理就是什么。比如从 LLM wiki 模板起步的知识集，会让智能体把等待中的来源并进页面、重新核对超过期限的页面、补全缺 frontmatter 的页面、合并和拆分页面，并让 `index.md` 保持最新。
3. **修好 Coffer 报告的每个失效链接。**
4. **拿不准的不动手**：两个文件说法冲突却看不出哪个对、要删掉大段内容、要改规则文件，这些写进汇报，留给你决定。
5. 用 `coffer knowledge tidy-finish <collection> --set summary="<汇报>"` **结束整理**。汇报写明它改了什么、留给你决定的事，最后一部分是**缺口**：知识集回答不了的问题，以及值得去找的来源（一份规格、一份运行手册、一个可以问的人）。

不需要改的地方，它一概不动。你也可以用自己的话请任何装有 `coffer-guide` 技能的智能体去做这件事：「把 payments 的知识整理一下。」

### 一次整理就是一次改动 {#a-tidy-is-one-change}

从 `tidy-start` 到 `tidy-finish`，Coffer 把智能体在这个知识集里的编辑放在一起，而不是一个文件一个文件地记录：

- 知识集页面会提示有智能体正在整理它，整理结束后它的编辑会作为一次改动出现。磁盘上的文件随着智能体的工作而变化，每次读取都能看到。
- 这期间没有任何东西提交这些编辑：扫描不会，保险库自己的扫描器也不会。如果一轮[保险库同步](/zh/guides/vault-sync)要改动其中某个文件，它会等待，就像对待任何还没进历史的编辑一样。
- 智能体结束时，所有编辑记成**一次改动**，写入者是智能体，带着它的汇报。知识集的**改动记录**把它显示为一条：智能体、时间、汇报，以及按标题列出的文件。
- 什么都没改的整理不记录任何东西。
- 智能体一直不结束，也不会永远占着这个知识集：知识集 30 分钟没有变化后，Coffer 会结束这次整理，把它改过的东西记成一次改动，显示为*未汇报即结束*。
- `tidy-start` 之前知识集里已有的改动，会先作为在磁盘上编辑记录下来，所以这次整理只包含智能体做的事。

Coffer 只在整理进行时记着它：整理期间 Coffer 重启的话，已做的编辑会记成普通的在磁盘上编辑，丢掉的只是分组。智能体没有运行 `tidy-start` 时也是这样。

### 撤销一次整理 {#undo-a-tidy}

```text
知识 → 选择知识集 → 改动记录 → 这次整理 → 撤销这次整理…
```

**撤销这次整理…** 会把这次整理动过的每个文件放回整理之前的样子：改过的文件回到原来的文字，删掉的文件回来，新建的文件被移除。Coffer 会先询问，写明是哪次整理、会放回多少个文件。撤销是一次由你写入的新改动，所以那次整理仍留在历史里，排在撤销之前；撤销也会记入[活动](/zh/guides/activity)。

如果其中某个文件在整理之后又被改过（被你、别的智能体或同步），对话框会列出它，在你选择**仍然撤销**之前什么都不撤销；选择后，那些之后的修改也会丢掉。它们仍在历史里，所以文件的**历史**还能把它们找回来。

在命令行上，`coffer knowledge undo <version>` 做同样的事；有文件在之后被改过时，会以 `KNOWLEDGE_UNDO_CONFLICT` 拒绝并写明这些文件；加上 `--set force=true` 仍然撤销。version 是这次改动的版本，从 `coffer knowledge changes` 里找。

只想放回某一个文件，就打开它，按**历史**，选中整理之前的版本，按**恢复此版本…**（见[历史与恢复](#history-and-restore)）。

### 只想先听听意见 {#ask-for-a-review-only}

想在智能体动手之前先听它打算改什么，就在整理打开的会话里直接说：「先别改，说说你打算怎么做。」`coffer-guide` 技能会告诉只被要求检查或审阅的智能体：只报告，什么都不改。然后你再告诉它哪些可以动手。

### 没有什么会自己整理 {#nothing-tidies-on-its-own}

整理只在你按下它或请你的智能体去做时才运行。Coffer 不会自己启动智能体运行，所以不会有消耗你额度的动作，也不会开出你没发起的对话。

::: info 什么会离开你的机器
Coffer 不会把任何关于你知识的东西发给任何模型。你按下整理时，智能体读到的文件会发给该智能体自己的提供商，和与它的任何对话一样。
:::

## 检查一个知识集 {#check-a-collection}

Coffer 只检查一件事，每次读取知识集时都检查，一个都不修：每个链接都指得到东西。它不检查别的，因为只有这件事不依赖任何格式：页面是否完整、是否最新、出处是否充分，要由知识集的规则来定、由你的智能体来判断。修失效链接是[整理](#tidy-a-collection)的一部分，整理的提示词带着同一份清单。

### 失效链接 {#what-coffer-finds-on-its-own}

知识集页面的**失效链接**一节列出它们，按种类分组。每条按标题写明文件（悬停可看到路径），显示链接原来的写法，点一下就打开这个文件。没有可报告的内容时，这一节只显示一行说明。

| 种类 | 含义 |
| --- | --- |
| **失效链接** | 指不到任何文件或别名的 `[[链接]]`，或者指向不存在的文件的相对链接。 |
| **有歧义的链接** | 指到不止一个文件、且其中没有一个和发出链接的文件在同一文件夹里的 `[[链接]]`。 |
| **指向知识库之外的链接** | 爬出知识根目录的相对链接。把它改成指向某个知识集里的文件，或者改成网页链接。 |

知识集里的每个 Markdown 文件都会被检查，README 和规则文件也不例外，只有上传文件夹里的文件除外：导入的素材保留了导出工具原来的文字，Confluence 宏里的 `[[` 并不是链接。失效链接每次读取时从文件算出来，哪里都不存，所以文件一变它就是最新的。在命令行里，`coffer knowledge check <collection>` 打印同一份清单（见 [`coffer knowledge`](/zh/reference/cli/knowledge#knowledge-check)）。

## 自己在运行的是什么 {#what-runs-on-its-own}

后台的**扫描**让知识集保持最新。它大约每分钟运行一次，不调用任何模型。每一轮它会：

- 把放进知识集 `.inbox/` 的文件移进它的上传文件夹（见[放进收件箱的文件](#a-file-in-the-inbox)），
- 把自上次提交以来树里变过的东西（你编辑器里的保存和你的智能体对文件的编辑）作为在磁盘上编辑提交进历史，以及
- 重新渲染 `coffer-guide` 技能的目录，这样你或智能体手工添加的文件会被列出来。

它在每台机器上都运行，不参与[保险库同步](/zh/guides/vault-sync)的各轮，也从不等待其中任何一轮，不移动你的任何文件，也不改写任何文件的文字。知识功能关闭期间它会被跳过（见[实验功能](/zh/guides/experimental-features)）。

### 知识集自定格式之前建的知识集 {#collections-from-before-pages-and-sources}

早期版本的 Coffer 建的知识集照常工作：没有文件被移动或改写，文件里的键（`type`、`sources`、`verified` 等）原样保留，现在都是知识集自己的。在它的 README 写明 `rules` 之前，它按根目录下 `AGENTS.md`、`CLAUDE.md`、`README.md` 中第一个存在的来读，所以 README 里的**页面类型**和**规则**两节就是它的规则。要让它继续按原来的 wiki 维护，可以请智能体把 LLM wiki 的规则复制成一个 `AGENTS.md`，或者在 README 里加上 `rules:` 和 `entry:`，指向知识集已有的文件，比如它自己的 `schema.md` 和 `index.md`。早期版本的 Coffer 曾自己把零散文档归入 `pages/`；那些移动在**改动记录**里，由 **Coffer** 写入，可以从历史里恢复。

## 智能体如何找到知识 {#how-agents-find-knowledge}

Coffer **没有读取、列出或搜索知识的工具**。智能体用它已有的工具按路径读文件：`Read`、`Grep`、它的 shell。

告诉它去哪里找的是 Coffer 内置的 [`coffer-guide` 技能](/zh/guides/skills#the-built-in-coffer-guide-skill)，Coffer 会把它链接进每个智能体的技能文件夹：

- 它的**描述**出现在每个会话里，列出你各个知识集的主题，取自每个 `README.md`，并说明这个技能教如何在知识集里写和整理知识。
- 它的**正文**在智能体打开技能时加载，给出知识根目录的路径和每个知识集的目录：它的描述、它的规则文件；有入口页时还有入口页和它的 Markdown 文件数。没有入口页的知识集，会按文件夹列出它的文件，每个带着标题，有 `description` 时也带上。正文还说明了不管什么格式 Coffer 都会对知识集做什么，以及整理的步骤。

指南不教任何格式：格式由每个知识集的规则文件决定，而且以它为准。入口页没能把智能体带到它要找的东西时，指南会让它在知识集里 grep 确切的字符串。目录太大时会被缩短：先去掉文件的描述，还是太长就只给出每个知识集的文件数，技能里会说明这一点。

目录一变，Coffer 就重写这个技能，所以新文件会在一次扫描内出现在里面。

::: details 为什么没有搜索工具
智能体会稳定地使用它已有的文件工具，却很少记得去调一个专用的检索工具。给它们一份目录和一个路径，就把检索变成了它们本来就擅长的事；而且对几百个文件做一次字面 `grep`，能准确匹配标识符和名字，模糊搜索反而会把它们弄混。完整理由见[知识架构](/zh/architecture/knowledge)。
:::

给每个知识集写一个好的 `README.md`：模型判断你的知识是否相关时，匹配的就是它的第一段。也写一个好的规则文件：智能体遵循的就是它。

## 浏览和阅读 {#browse-and-read}

在知识页面里，先在树中选知识集，再选文件。它们同时也是普通文件：知识根目录是 `~/.coffer/vault/knowledge/`，每个知识集是其中的一个文件夹，所以你可以用自己的工具读和 grep。知识集的 **⋯** 菜单里有**复制路径**。

知识页面是一棵树加一个阅读窗格，两者都撑满页头下方的窗口。标题带着**实验性**标签；页头的操作是**整理全部**和**添加**，后者是页面唯一的主按钮。**添加**会打开一个菜单，每一项都带一行说明它在 Coffer 里保存什么：**上传文档…**（见[上传文档](#upload-a-source)）、**新建知识集…**（见[创建知识集](#create-a-collection)）和**接入外部文件夹…**（见[接入外部文件夹](#link-an-external-folder)）。树的顶部，**知识集**有一个**新建知识集**按钮；下面是按文件夹名显示的每个知识集。展开一个知识集，会按它们自己的名字显示其中的文件夹和文件，文件夹在前，每个 Markdown 文件带着文档图标。树会记住你展开和收起了什么：离开页面或刷新之后回来，还是同样的知识集和文件夹开着；切到别的页面再从侧边栏回到**知识**，会回到你上次打开的知识集和文档。

**知识集。** 选中一个知识集，它的窗格栏里有**整理**和 **⋯** 菜单。下面是它的文件夹名、这里放什么（点一下可编辑；离开输入框或按 **⌘Enter** 保存，**Esc** 取消，并有提示给出**撤销**），以及一行概要：多少个 Markdown 文件、文件夹路径和复制按钮、最后更新时间。下面一行写明它的**规则**文件和**入口**页，点开就打开对应文件。再下面一行浅色文字说明这个知识集由 Coffer 管理：同步到你的其他 Mac，保留历史，由你的智能体整理。有智能体正在整理它时，会有一条提示（见[一次整理就是一次改动](#a-tidy-is-one-change)）。然后是两节：

- **失效链接**按种类列出 Coffer 发现的失效链接，每条按标题写明文件，点一下就打开（见[检查一个知识集](#check-a-collection)）。
- **改动记录**列出这个知识集的每次改动，最新的在前：它做了什么、谁写的、什么时候，以及按标题列出它涉及的文件，点开每个文件都会打开它的历史。一次整理是一条，带着智能体的汇报和**撤销这次整理…**（见[撤销一次整理](#undo-a-tidy)）；彼此相隔不到 10 分钟的磁盘编辑合成一条，列出它们的文件。**显示更多**会加载更早的改动。

知识集的 **⋯** 菜单里有**在访达中显示**、这台 Mac 装了 Obsidian 时的**在 Obsidian 中打开**（见[在 Obsidian 中打开知识集](#open-a-collection-in-obsidian)）、**复制路径**、**重命名…**和**删除知识集…**；里面还什么都没有的知识集会这样说明，并提醒你可以上传一个文档，或把 Markdown 文件放进它的文件夹。

**文件。** 选中一个文件会只读地显示它。它的窗格栏先写明文件在哪里，然后是**历史**（见[历史与恢复](#history-and-restore)）、Markdown 的**预览 / 源码**切换、作为按钮的**在编辑器中打开**（见[自己编辑文件](#edit-a-file-yourself)），以及 **⋯** 菜单（**在访达中显示**、装了 Obsidian 时的**在 Obsidian 中打开**，以及**删除**）。标题下面一行写明谁、什么时候创建了它（frontmatter 里写了时读自 frontmatter）；上传来的文件还会显示**原文件**和文件名，在上传它的那台 Mac 上点它会打开这个文件（见[图片和原文件](#pictures-and-the-original-file)）。导入的 Confluence 页面显示**来自 confluence**和指向这个页面的链接，有东西被漏掉时还会显示**部分导入**。

正文里，每个 `[[链接]]` 和每个相对链接都会在它自己的知识集里打开它指向的文件；失效的链接标成红色，悬停提示说没有叫这个名字的东西，指向知识库之外的链接也会被标出。上传文件夹里的文件中，`[[` 按原样显示。网页链接在应用里用你的默认浏览器打开，在浏览器里则在新标签页打开。文件里的 HTML，比如导入时保留的表格，按 HTML 显示，脚本和注释会被去掉。```` ```mermaid ```` 代码块会画成图，画不出来时显示源码（见 [Web 界面](web-ui.md)）。行内代码比代码块更淡，长路径在 `/` 处换行。

文件用相对路径链接的图片会在预览里直接显示。在树里选中一个图片文件（比如一次上传的 `image-1.png`），会显示这张图片。

页面没有搜索框，也没有按知识集的开关：⌘K 按名字跳到知识集，每个知识集都到达每个智能体。知识页面上没有手工输入文件的表单：你在自己的编辑器里写，智能体则通过写文件来写。

## 在 Obsidian 中打开知识集 {#open-a-collection-in-obsidian}

知识集就是 [Obsidian](https://obsidian.md) 能直接读的普通 Markdown：把它的文件夹（或整个知识根目录）作为 Obsidian 库打开，就可以在 Obsidian 里浏览、搜索和编辑文件。`[[slug]]` 链接按文件名解析，和 Obsidian 的解析方式一样；frontmatter 里的 `aliases` 正是 Obsidian 本来就读的键。Coffer 会忽略 `.obsidian/` 这类隐藏文件夹（Obsidian 在里面存它的设置）：不提交、不进目录、不同步。

这台 Mac 装了 Obsidian 时，知识集的 **⋯** 菜单和文件的 **⋯** 菜单里会有**在 Obsidian 中打开**。第一次使用时：

1. 在 Obsidian 里选**打开文件夹作为仓库**（Open folder as vault），选中知识集的文件夹 `~/.coffer/vault/knowledge/<collection>/`。`~/.coffer` 是隐藏的：在对话框里按 **⌘⇧.** 显示它，或者在知识集上用**复制路径**，再按 **⌘⇧G** 粘贴。
2. 在 Obsidian 的**设置 › 文件与链接**里，把**新建笔记的存放位置**设成知识集规则放新文件的位置（LLM wiki 知识集是 `pages/`）。Coffer 不移动任何文件；建在其他地方的笔记会留在那里。如果你更喜欢路径链接，把**内部链接类型**（New link format）设成**基于当前笔记的相对路径**（Relative path to file）：Coffer 会像跟随和检查 `[[slug]]` 一样跟随和检查它们。

在 Obsidian 里保存的编辑和在任何编辑器里一样：马上生效，由下一次扫描记成在磁盘上编辑。Coffer 写进上传文件夹的文件，按知识集的规则处理。

## 接入外部文件夹 {#link-an-external-folder}

如果你已经在用自己的工具记笔记，比如一个 Obsidian 库、一个 Logseq 图谱，或者仓库里的一个 Markdown 文件夹，可以把这个文件夹共享给你的智能体，而不用挪动它。Coffer 把它叫作接入的外部文件夹。

```text
知识 → 添加 → 接入外部文件夹… → 文件夹、名称 → 接入文件夹
```

**文件夹**是它的绝对路径，比如 `/Users/you/Obsidian/Work`。**名称**是 Coffer 和智能体称呼它的名字：在你自己输入之前，它跟着文件夹本身的名字走；不管怎样，磁盘上的文件夹都不会改名。在命令行里，同样的操作是 `coffer knowledge link --set folder=/Users/you/Obsidian/Work`（见 [`coffer knowledge link`](/zh/reference/cli/knowledge#knowledge-link)）。

### Coffer 会做什么 {#what-coffer-does-with-a-linked-folder}

- **把它共享给每个智能体。** 这个文件夹在每个智能体都会读的 `coffer-guide` 技能里有单独的一节：它的路径、它的规则文件、它指定了入口页时的入口页，否则按标题列出每篇 Markdown 笔记。智能体用自己的文件工具在原处读这些笔记。
- **在知识页面上显示它。** 树里用外部文件夹图标列出它，你可以打开、阅读其中任何一篇笔记。它的页面在名字旁标着**外部**，并列出这些信息：**位置**（它的路径，附**在访达中显示**）、**笔记**（它有多少篇 Markdown 笔记）、**规则文件**、它的 README 指定了入口页时的**入口页**，以及**管理方式**：由它自己的工具维护，Coffer 只把它共享给智能体。
- **每次都重新读取。** 不做任何缓存，所以你在 Obsidian 里保存的笔记，就是页面和智能体下一次看到的内容。

### Coffer 不会做什么 {#what-coffer-does-not-do-with-a-linked-folder}

- **不复制任何东西。** 没有文件会进入 `~/.coffer`。这个文件夹始终是唯一的一份。
- **不往文件夹里写任何东西。** 不能往里上传，它的笔记没有**删除**，它的描述（它自己 `README.md` 的第一段）不在这里编辑，它也没有**整理**、**失效链接**和收件箱。
- **不记录历史。** 它的笔记没有**历史**，它的页面没有**改动记录**，也不能通过 Coffer 撤销任何东西。需要时请用这个文件夹自己的工具：Obsidian 的文件恢复，或者文件夹本身是仓库时用 git。
- **不同步它。** 文件夹里的文件和这个接入关系都不会经由[保险库同步](/zh/guides/vault-sync)到达你的其他 Mac。接入关系只记录在这台 Mac 上的 `~/.coffer/local/resources/knowledge/` 里，因为文件夹的路径只在这台 Mac 上成立。想在另一台 Mac 上用同样的笔记，就用文件夹自己的工具（Obsidian Sync、iCloud 云盘、git）让它保持一致，再在那台 Mac 上也接入一次。

### 智能体怎样往里写 {#how-agents-write-in-a-linked-folder}

接入的文件夹和 Coffer 保存的知识集读法一样（见 [README 声明什么](#what-a-readme-declares)）：它的**规则文件**是它的 `README.md` 用 `rules` 指定的文件，没有就是根目录下 `AGENTS.md`、`CLAUDE.md` 和 `README.md` 中第一个存在的那个；`entry` 指定它的入口页。两者都必须在这个文件夹里。指南会告诉智能体，在往文件夹里写任何东西之前先遵守规则文件；没有规则文件时，只按现有笔记的写法来写。所以，如果你希望智能体往你的库里添加笔记，就把你的约定写进库根目录的 `AGENTS.md`；如果只希望它们读，也在那里写明。

### 大文件夹 {#large-linked-folders}

Coffer 会跳过 `.obsidian/`、`.git/` 这类隐藏文件夹和 `node_modules`。一个文件夹最多读取 5000 篇 Markdown 笔记，超过 2 MB 的文件会列出，但不在页面上显示。只想共享大库的一部分时，接入其中的子文件夹，而不是整个库。

### 不能接入的文件夹 {#folders-that-cannot-be-linked}

文件夹必须存在，并且要用绝对路径给出。Coffer 自己的文件夹 `~/.coffer` 不能接入，包含它的文件夹也不行，比如你的主目录或磁盘根目录。这些会被拒绝并返回 [`KNOWLEDGE_FOLDER_REFUSED`](/zh/reference/error-codes)。已经接入过的文件夹，或者别的知识集已经在用的名字，会被拒绝并返回 `KNOWLEDGE_COLLECTION_EXISTS`。

### 重命名或断开接入 {#rename-or-disconnect-a-linked-folder}

接入文件夹的 **⋯** 菜单里有**在访达中显示**、装了 Obsidian 时的**在 Obsidian 中打开**、**复制路径**、**重命名…**和**断开接入…**。**重命名…**只改 Coffer 和智能体使用的名字。**断开接入…**会先询问；之后智能体不再看到这个文件夹，里面的每个文件都留在原处。

## 每个知识集都对所有智能体生效 {#every-collection-reaches-every-agent}

知识集没有开关，也没有按智能体设置的生效范围：每个知识集（包括接入的外部文件夹）对所有智能体都可用，只有删除才能让它从智能体的 `coffer-guide` 技能里消失（接入的文件夹用**断开接入…**，文件保持不动）。

::: warning 这不是访问控制
技能会把知识根目录交给智能体，智能体可以用自己的工具读取其下的任何东西。不要把这台机器上的智能体不该读的内容放进知识集。
:::

## 历史与恢复 {#history-and-restore}

知识集的每一次改动都会作为一个版本保留：你的上传和删除、放进收件箱并移进上传文件夹的文件、保险库同步带进来的内容，一次整理（记成一次由智能体写入、带着汇报的改动），以及在 Coffer 之外用你自己的编辑器或智能体文件工具做的编辑。每次改动都注明**写入者**：`user`、`agent`、`sync` 或 `disk`（早期版本的 Coffer 写的版本上还有 `daemon`，表示它把零散文档归入 `pages/`，以及 `curation`），所以你总能知道谁改了什么。知识集页面在它的**改动记录**里列出这些改动。

历史就是保险库仓库自己的历史：知识集位于 `~/.coffer/vault` 的 `knowledge/` 下，所以 `git -C ~/.coffer/vault log -- knowledge/<collection>/<path>` 读到的是同样的版本，[保险库同步](/zh/guides/vault-sync)会把它们带到你的其他机器上。Coffer 的保险库需要 `git`；没有 git 时，应用会一直显示 [Coffer 需要 git](/zh/guides/troubleshooting#coffer-needs-git)，直到装好为止。如果守护进程运行期间 git 没了，所有写入照常工作，知识集的改动记录和删除的**撤销**所读的改动流会被拒绝。这个拒绝附带一段提示词，让你的智能体按适合你机器的方式安装 git，并用 `git --version` 确认。

### 找回较早的版本 {#bring-back-an-earlier-version}

在文件的窗格栏里按**历史**。历史会占满整个知识区域，树和文件都让开，给版本列表和 diff 留出空间；页面地址会加上 `?history=1`，所以指向它的链接也会打开历史。里面是一张卡片，中间有一条可以拖动的分隔线；按它的 ✕ 或按 **Esc** 回到文件。

- **左边：版本列表，最新的在最上面，** 标题是**版本**并带着数量。每一行说明这个版本做了什么（*创建*、*编辑*或*删除*，或*恢复了 &lt;日期&gt; 的版本*）、谁写的、什么时候，以及它改动的行数（+N −M）。写入者显示为**你**（你通过 Coffer）、**在磁盘上编辑**（你自己的编辑器、shell，或智能体自己的文件工具）、按产品名显示的智能体（通过 Coffer 工具写入时）、**Coffer** 或**同步**。最新的一个标着**当前**，打开历史时默认选中它。
- **右边：选中的版本，** 显示它的短 id、写入者和时间，以及它改动的每个文件的差异。对于不是当前的版本，一个开关决定差异显示什么：**本版本的改动**（与它之前的版本比）或**与当前版本对比**（从该版本到文件现在的样子）。

要回到某个版本，选中它，按**恢复此版本…**。Coffer 会先询问：文件会恢复成那个版本，**作为一个新版本**保存，所以历史里的内容都不会丢。恢复由你写入，在历史里显示为*恢复了 &lt;日期&gt; 的版本*，并记入[活动](/zh/guides/activity)。如果文件在你打开历史之后又变了（有了更新的版本，或你在编辑器里保存过），恢复会被拒绝并返回 `VAULT_FILE_STALE`，对话框会这样告诉你；重新打开历史再试即可。打开历史时，你在磁盘上做的编辑也会先记成它自己的一个版本，所以最新的版本总是文件现在的样子。

你也可以用 git 读同样的版本：`git -C ~/.coffer/vault log -p -- knowledge/<collection>/<path>`。

提示消失之后，已删除的文件就没有窗格可以打开它的历史了，但它的版本仍在保险库的 git 历史里，所以可以用 git 找回（见[删除文件和知识集](#delete-files-and-collections)）。

## 删除文件和知识集 {#delete-files-and-collections}

通过 Coffer 删除只能由人来做。Coffer 不给智能体任何能删除知识的工具，而你可以删除任何文件，不管是谁写的。这也只是一次普通的文件删除，所以在你自己的编辑器里删文件同样可以，历史里会把它记为一次磁盘上的编辑。

- **删除一个文件：** 知识 → 选中文件 → **⋯** → **删除**。立刻执行。其他文件里指向它的链接会在[检查](#check-a-collection)里变成失效链接。上传文件的图片仍留在它的文件夹里，它的原文件仍留在上传它的那台 Mac 上；不再需要的话请自己删掉。
- **删除整个知识集及其中所有文件：** 知识 → 选中知识集 → **⋯** → **删除知识集…**。Coffer 会先询问，写明知识集的名字和会一并删除多少个文件。

::: tip 删除可以撤销
删除会弹出一条提示 *已删除 `<name>`*，带**撤销**，它会完整放回被删掉的东西：文件回到它的知识集，知识集连同它的所有文件一起回来，作为一次由你写入的新改动。如果同一路径上已经又有了文件，或者同名知识集已经重新存在，撤销会被拒绝，不写入任何东西。提示消失之后，被删的文件就没有窗格可以打开它的历史了，但它的版本仍在保险库的历史里，可以用 git 找回（`git -C ~/.coffer/vault log -- knowledge/<path>`）；被删知识集的文件也可以，但它的注册信息不行，所以**删除知识集…**会先询问。
:::

## 不要放进知识的东西 {#what-not-to-put-in-knowledge}

- **密钥。** 不放 key、令牌或密码。请用[密钥存储](/zh/guides/secret-store)。
- **代码里已经写明的东西。** 智能体能在仓库里读到的，就不该放这里。
- **草稿笔记。** 放进来的东西，一个月后应该依然成立。

## 故障排查 {#troubleshooting}

**一次整理把文件改坏了。** 在知识集**改动记录**里这次整理的那一条上，用**撤销这次整理…**撤销整次整理（见[撤销一次整理](#undo-a-tidy)）；或者只放回一个文件：打开它，按**历史**，选一个整理之前的版本，按**恢复此版本…**。

**一次整理显示成了好几次磁盘编辑。** 智能体没有先运行 `coffer knowledge tidy-start`，或者它工作时 Coffer 重启了。它的编辑都在历史里，一次编辑一条；从文件的**历史**里恢复。

**知识集页面说有智能体在整理，但什么都没发生。** 智能体没有运行 `tidy-finish` 就停了。请它结束，或者等着：知识集 30 分钟没有变化后，Coffer 会结束这次整理，记为*未汇报即结束*。

**某个链接显示为红色。** 它指不到任何文件或别名，通常是文件被改了名、被移动或被合并掉了。修好这个链接，或者把旧 slug 加进保留下来的文件的 `aliases`；**整理**会修好它发现的失效链接。

**我的文档被移进了 `pages/`。** 早期版本的 Coffer 会把零散的 Markdown 归入 `pages/`；现在的版本什么都不移动。那次移动在**改动记录**里，可以从历史里恢复（见[知识集自定格式之前建的知识集](#collections-from-before-pages-and-sources)）。

**Confluence 页面显示部分导入。** 页面上有东西没有保留：文件的 `import_report` 写明了每一项及原因。导出时没有下载的附件，可以用 `--attachments` 加上，再用 `--replace` 重新导入这个页面。

**Confluence 上传因为已经导入过而被拒绝。** 知识集里已有从同一页面 id 导入的文件。按**替换**，或者先用 `--preview` 运行上传，再用 `--replace`。

**整理只提供复制提示词。** 没有可用的托管智能体。到**智能体**里添加一个，或者把复制的提示词粘贴到你用的智能体里；它必须装有 `coffer-guide` 技能。

**菜单里没有在 Obsidian 中打开。** 只有这台 Mac 装了 Obsidian（在 `/Applications` 或你自己的“应用程序”文件夹里）时，Coffer 才会提供它。

**文件说它的原文件在另一台 Mac 上。** 上传的文件只保存在上传它的那台 Mac 上。到那台 Mac 上打开转换后的文件，或者在这台 Mac 上重新上传这个文件。

**上传的文档里少了一张图。** 一边不到 48 像素、超过 5 MB，或一次上传里排在第 40 张之后的图片不会保留；画在图片里的文字会作为图片保留，而不是文字。可以在上传它的那台 Mac 上查看原文件。

**智能体没有用到知识。** 检查 `coffer-guide` 技能已启用并且到达那个智能体（技能页面上它的**生效范围**按钮），以及知识集的 `README.md` 开头是否有一句写明主题的话。

**智能体不遵守知识集的约定。** 看知识集页面的**规则**写的是不是你预期的文件。不是的话，在它的 `README.md` 顶部加上 `rules: <文件>`。

**智能体写的文件没有出现。** 写进知识集的文件在下一次读取时就会出现。留在 `.inbox/` 里的文件必须是 Markdown，直接放在已有知识集的 `.inbox/` 文件夹里，并在下一次扫描（约一分钟内）移进上传文件夹；放在别处的文件不会被处理，不是 Markdown 的文件留在收件箱里。
