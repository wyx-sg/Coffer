# 知识 {#knowledge}

知识是一个存放工作环境相关 Markdown 文档的目录：服务、仓库、约定、决策、坑，这台机器上的每个智能体都会读。本页讲如何创建知识集、添加和编辑文档、你的智能体如何写进这些文档并在你按**整理**时整理它们、如何回看每一次改动并恢复其中一次，以及智能体如何找到这些内容。

## 知识用来做什么 {#what-knowledge-is-for}

知识存放的是你所处环境里的事实：哪个团队负责某个服务，某个内部 API 怎么鉴权，某个迁移为什么按这个顺序。它之所以在那里，是因为你或者和你一起工作的智能体把它放了进去。

- **所有智能体共用一份。** Claude Code 和 Codex 读的是同一批文件，一个智能体上午记下的东西，另一个下午就能读到。
- **普通文件。** 每篇文档都是一个 Markdown 文件，你可以打开、编辑、grep、备份。Coffer 不建索引、不做 embedding，也不在数据库里另存一份内容。
- **共同编写。** 你在知识页面或自己的编辑器里编辑文档；智能体用自己的文件工具写进文档，遵循 `coffer-guide` 技能里的规则：一条事实放进已经覆盖这个主题的文档。当文档渐渐重叠，你按**整理**，你的智能体会把它们合并、拆分、修正。Coffer 自己不在你的知识上运行任何模型。

知识不是[记忆](/zh/guides/memory)。记忆是智能体在工作中学到的东西，从它们各自的记忆库里读出来；知识是有人刻意写下来的东西。

## 知识集的结构 {#how-a-collection-is-laid-out}

**知识集**是知识根目录下的一个顶层文件夹：

```text
~/.coffer/vault/knowledge/
└── payments/                     ← one collection
    ├── README.md               ← what this collection is about
    ├── session-ownership.md    ← a document
    ├── gateway/
    │   └── rate-limits.md      ← nesting is allowed and means nothing
    └── .inbox/                 ← hidden: a drop zone, adopted at the next sweep
```

- **文档**是知识集里的 Markdown 文件。文档的路径就是它的身份，没有单独的 id。文件名是标题的 slug，重名时加 `-2` 这样的后缀。
- 知识集里的**文件夹**是可选的，不代表任何含义。你或你的智能体都可以创建、移动、删除它们。
- 知识集根目录的 **`README.md`** 描述这个知识集。它的第一段就是 Coffer 所有显示知识集描述的地方用的描述，也是 `coffer-guide` 技能告诉智能体这个知识集讲什么的依据。它从不作为文档列出或计数。
- **隐藏条目**（以 `.` 开头的名字）不计入任何文档数，也不进目录，知识页面不会列出其中任何一个。Coffer 会读的是 `.inbox/`：留在那里的 Markdown 文件会在下一次扫描时变成文档（见[放进收件箱的文件](#a-file-in-the-inbox)）。

知识根目录位于保险库仓库里，即 `~/.coffer/vault/knowledge`，`coffer-guide` 技能会把它告诉每个智能体。它不能挪到别处：保险库外的目录树，它的历史就看不到了。

### Frontmatter {#frontmatter}

每篇文档都带 YAML frontmatter：

```markdown
---
title: Session ownership
description: Which service owns user sessions, and where the TTL is configured.
actor: user
created_at: 2026-09-20T08:14:03.512840+00:00
updated_at: 2026-09-22T10:02:41.090311+00:00
---

The `account-session` service owns ...
```

| 键 | 含义 |
| --- | --- |
| `title` | 文档标题。 |
| `description` | 一句话说明文档讲什么。智能体在目录里看到的就是它。 |
| `actor` | `user` 或 `agent`，表示这篇文档是谁写的。 |
| `created_at`、`updated_at` | 时间戳。 |

你加的其他键，Coffer 每次重写文件时都会连同值一起保留。Coffer 不会往文档里写任何别的东西。

::: tip 写主题，不写文件名
文档里不能用文件名或路径去引用另一个知识文件，因为整理知识集时路径会变。要写「见网关限流的说明」，不要写「见 `gateway/rate-limits.md`」。`coffer-guide` 技能会把这条规则告诉智能体。
:::

## 创建知识集 {#create-a-collection}

知识集只能有意创建，而且只能由人创建。读、写、智能体的工作目录，或者智能体放进其他文件夹的 Markdown 文件，都不会创建知识集。

```text
知识 → 新建知识集 → 名称、这里放什么 → 创建知识集
```

这会创建 `~/.coffer/vault/knowledge/payments/`，以及一个装着这段描述的 `README.md`。知识集没有标题：所有页面和列表都按文件夹名显示它。它的描述就是 README 的开头一段：可以在知识集页面直接修改（点一下文字，离开输入框时保存），也可以直接改文件。不管哪种方式，都只改这一段，下面写的内容保持不变。

要重命名知识集，在它的页面上选 **⋯ → 重命名…**，输入新名字。它的文件夹会随之改名（`~/.coffer/vault/knowledge/<新名字>/`），页面仍停在这个知识集上，智能体从下一次目录更新起按新名字找到它。如果新名字已被别的知识集占用，或不是合法的文件夹名，会在输入框下方提示，什么都不会改。

**知识**页面的树里列出所有知识集，每个带文档数。

## 添加知识 {#add-knowledge}

有五种方式，每一种都以一篇你马上就能读到的文档结束。

### 由智能体提交：写进文档 {#from-an-agent-write-into-the-documents}

智能体用自己的文件工具归档知识。连接了 Coffer 的智能体会读到 `coffer-guide` 技能（见[连接客户端](/zh/guides/connect-a-client)），里面写明了知识根目录和各个知识集，并教了写下一件事的六条规则：

1. 找到这条事实的归属：把它并入已经回答这个问题的那篇文档，只有没有文档回答它时才新建文件。
2. 一个字都不丢：文档里原有的每条事实都要在这次编辑后保留。
3. 按主题组织，不按谁写的、什么时候写的。
4. 两种说法不一致时，较新的胜出，除非较旧的被来源、日期、命令输出或代码证明是对的。被取代的说法仍然看得到。
5. 不要提到另一个知识文件；说出主题。
6. 给每篇文档写 `title`、一行说明它回答什么问题的 `description`，以及 `actor: agent`。

你也可以直接要求：「把我们刚发现的 session TTL 记到 payments 知识集里。」知识集必须已经存在；只有你才创建知识集。智能体写下的东西马上就能读到，下一次扫描会把它提交进[历史](#history-and-restore)。

### 放进收件箱的文件 {#a-file-in-the-inbox}

Markdown 文件也可能出现在知识集隐藏的 `.inbox/` 文件夹里：来自 Coffer 之外的智能体、另一台机器，或旧版指南。

```text
~/.coffer/vault/knowledge/payments/.inbox/session-ttl.md
```

文件名无所谓，frontmatter 可有可无。下一次扫描会把这个文件变成知识集根目录下的一篇文档，并补全它缺的部分：

| Frontmatter | 补全来源 |
| --- | --- |
| `title` | 第一个 `# ` 标题，没有就用文件名。 |
| `description` | 第一段正文，没有就用标题。 |
| `actor` | `agent`，除非文件里另有写明。 |
| `created_at`、`updated_at` | 扫描发现该文件的时间。 |

写入者自己设置的内容都会保留，包括其他键，每个文件都会记入审计日志。只有知识集自己的 `.inbox/` 才算数。写在不是知识集的顶层文件夹里的 Markdown 文件不会被处理，也不会进目录：只有人才能创建知识集。收件箱里不是 Markdown 的文件原样留着。

### 上传文档 {#upload-a-document}

上传会把文件转换成 Markdown，并立刻作为一篇文档加入知识集。原始文件和提取出的文本都不会单独保存成文件。

```text
知识 → 上传 → 选择文件和知识集 → 上传
```

| 接受 | 格式 |
| --- | --- |
| 转换 | `pdf`、`docx`、`pptx`、`xlsx`、`xls`、`html`、`htm`、`epub` |
| 表格 | `csv`、`tsv` |
| 按文本读取 | `md`、`markdown`、`mdx`、`txt`、`text`、`rst`、`json`、`yaml`、`yml`、`toml`、`ini`、`cfg`、`log`、`sql`，以及常见源码文件（`py`、`js`、`ts`、`go`、`rs`、`java`、`sh` ……） |

每次上传一个文件，最大 20 MB。不支持的类型会被拒绝，并指出是哪种类型；转换后没有文本的（比如纯图片 PDF）也会被拒绝。被拒绝的上传不会留下任何东西。

文档的 `title` 取自文件（第一行的 `# ` 标题，没有就用文件名）。它的 `description` 取文档开头的正文，没有时用标题。上传按文档原样加入；把它并进已有文档是整理的事（见[整理一个知识集](#tidy-a-collection)）。

### 在聊天里：让智能体来存 {#from-a-chat-ask-your-agent}

如果你配对了一个[消息渠道](/zh/guides/channels)，并没有专门的知识命令。把文档或这段对话发给聊天里的智能体（私聊或群组都行），让它存进知识，比如「把这个存进 payments」。智能体用自己的文件工具来写，和它写其他知识文件的方式一样。

### 自己编辑文件 {#edit-a-file-yourself}

用任何编辑器在知识集文件夹里写、改、删 Markdown 文件，本身就是修改知识的完整方式，不需要导入步骤。改动在下一次读取时就生效，下一次扫描会把它作为在磁盘上编辑提交进历史。

在知识页面上，选中一篇文档，用**编辑**原地修改，或者用 **⋯** 菜单里的**在编辑器中打开**或**在 Finder 中显示**跳到文件。编辑器里只有文档正文：frontmatter 以只读方式显示在上方。编辑器是唯一需要你主动保存的地方：**放弃**会丢掉改动，**保存**（**⌘S**）保留改动；带着未保存的改动离开时，页面会先问是否不保存就离开，期间树里会用一个点标出正在编辑的文档。如果保存时发现文件在页面加载后已经在磁盘上被改过（无论是你自己的编辑器还是智能体改的），保存会被当作冲突拒绝，文件保持原样。页面会提示文档已在磁盘上改动、你的文字没有保存，并提供**比较**、**复制我的文字**和**重新加载**，但绝不会再覆盖保存一次。**比较**会并排显示两个版本和它们的差异：**保留我的编辑**或**采用磁盘上的版本**；没被选中的那个版本仍保留在文档的历史里。**重新加载**会采用磁盘上的版本，并且会先确认，因为它会丢掉你的文字。保存下来的文件算作一次编辑，和在你自己编辑器里改的完全一样。

智能体用自己的文件工具做同样的事，遵循 `coffer-guide` 技能给它们的写作规则（见[由智能体提交](#from-an-agent-write-into-the-documents)）。

## 整理一个知识集 {#tidy-a-collection}

时间一长，知识集会攒下重叠：两篇回答同一个问题的文档，一篇回答好几个问题的文档，一条被较新文档推翻的说法。Coffer 自己不去修。它把这件事交给你的智能体，由它用自己的文件工具读文档并编辑。

### 按下整理 {#press-tidy}

```text
知识 → 选择知识集 → 整理
知识 → 整理全部   （每个知识集，一个接一个）
```

**整理**会用你的默认托管智能体新开一个对话，带着一份写明知识集及其文件夹的提示词，并**立即发送**。你会落在这个对话上，可以看着智能体工作。知识页面页头的**整理全部**会发送一份写明每个知识集的提示词，请智能体一个一个地处理。没有可用的托管智能体时，按钮改为提供**复制提示词**：把它粘贴到你用的任何智能体里。

提示词会让智能体去看 `coffer-guide` 技能的**整理一个知识集**一节。照着做，智能体一次处理一个知识集：

1. 读知识集的 `README.md` 和每篇文档的标题与描述，再完整读文档。
2. 把回答同一个问题的文档**合并**成一篇，保留每条事实，并删掉被合并掉的那些。
3. 把回答好几个不相关问题的文档**拆分**，一个主题一个文件。
4. 按「新的说法胜出，除非旧的被证明是对的」这条规则**修正**错误或矛盾之处，并重写没有说明文档回答什么问题的描述。
5. 报告它合并、拆分、修正和删除了什么。

不需要改的地方，它一概不动。你也可以用自己的话请任何装有 `coffer-guide` 技能的智能体去做这件事：「把 payments 的知识整理一下。」

### 没有什么会自己整理 {#nothing-tidies-on-its-own}

整理只在你按下它或请你的智能体去做时才运行。Coffer 不会自己启动智能体运行，所以不会有消耗你额度的动作，也不会开出你没发起的对话。

### 整理出了问题 {#if-a-tidy-goes-wrong}

智能体做的每次编辑都是[历史](#history-and-restore)里的一个版本，记为在磁盘上编辑。打开文档的**历史**标签页，恢复你想要的版本；或者打开**最近改动**，那里列出智能体改了什么、删了什么，每次删除都带**恢复**。

::: info 什么会离开你的机器
Coffer 不会把任何关于你知识的东西发给任何模型。你按下整理时，智能体读到的文档会发给该智能体自己的提供商，和与它的任何对话一样。
:::

## 自己在运行的是什么 {#what-runs-on-its-own}

后台的**扫描**让知识集保持最新。它大约每分钟运行一次，不调用任何模型。每一轮它会：

- 把放进知识集 `.inbox/` 的文件变成文档（见[放进收件箱的文件](#a-file-in-the-inbox)），
- 把自上次提交以来树里变过的东西（你编辑器里的保存和你的智能体对文件的编辑）作为在磁盘上编辑提交进历史，以及
- 重新渲染 `coffer-guide` 技能的目录，这样你或智能体手工添加的文档会被列出来。

它在每台机器上都运行，不参与[保险库同步](/zh/guides/vault-sync)的各轮，也从不等待其中任何一轮，并且不改写任何已有文档。知识功能关闭期间它会被跳过（见[实验功能](/zh/guides/experimental-features)）。

## 智能体如何找到知识 {#how-agents-find-knowledge}

Coffer **没有读取、列出或搜索知识的工具**。智能体用它已有的工具按路径读文件：`Read`、`Grep`、它的 shell。

告诉它去哪里找的是 Coffer 内置的 [`coffer-guide` 技能](/zh/guides/skills#the-built-in-coffer-guide-skill)，Coffer 会把它链接进每个智能体的技能文件夹：

- 它的**描述**出现在每个会话里，列出你各个知识集的主题，取自每个 `README.md`。
- 它的**正文**在智能体打开技能时加载，给出知识根目录的路径和每个知识集里每篇文档的目录：路径、标题和描述。它还带有上面讲的写作规则和整理步骤。

目录一变，Coffer 就重写这个技能，所以新文档会在一次扫描内出现在里面。

::: details 为什么没有搜索工具
智能体会稳定地使用它已有的文件工具，却很少记得去调一个专用的检索工具。给它们一份目录和一个路径，就把检索变成了它们本来就擅长的事；而且对几百个文件做一次字面 `grep`，能准确匹配标识符和名字，模糊搜索反而会把它们弄混。完整理由见[知识架构](/zh/architecture/knowledge)。
:::

给每个知识集写一个好的 `README.md`：模型判断你的知识是否相关时，匹配的就是它的第一段。

## 浏览和阅读 {#browse-and-read}

在知识页面里，先在树中选知识集，再选文档。文档同时也是普通文件：知识根目录是 `~/.coffer/vault/knowledge/`，每个知识集是其中的一个文件夹，所以你可以用自己的工具读和 grep。知识集的 **⋯** 菜单里有**复制路径**。

知识页面是一棵树加一个阅读窗格，两者都撑满页头下方的窗口。标题带着**实验性**标签；页头的操作是**整理全部**和**上传**，后者是页面唯一的主按钮，编辑文档时会降为次要按钮。树的顶部，**知识集**有一个**新建知识集**按钮；下面是按文件夹名显示的每个知识集，每个展开后是它的文档，按文件名显示。**最近改动**在知识集上方。选中一个知识集会显示它的文件夹名、这里放什么（点一下可编辑；离开输入框或按 **⌘Enter** 保存，**Esc** 取消，并有提示给出**撤销**）和它的属性：**文档**和**文件夹**，旁边是**整理**。知识集的 **⋯** 菜单里有**在 Finder 中显示**、**复制路径**、**重命名…**和**删除知识集**；里面还什么都没有的知识集会这样说明，并提醒你可以上传一个，或把 Markdown 文件放进它的文件夹。选中一篇文档会渲染它，带**编辑**（见[自己编辑文件](#edit-a-file-yourself)）、Markdown 的**预览 / 源码**切换，以及 **⋯** 菜单（**在编辑器中打开**、**在 Finder 中显示**、**删除文档**），分为两个标签页：**文档**和**历史**（见[历史与恢复](#history-and-restore)）。标题下面一行写着谁写的、什么时候创建的。

页面没有搜索框，也没有按知识集的开关：⌘K 按名字跳到知识集，每个知识集都到达每个智能体。页面上没有手工输入文档的表单：你通过**编辑**来写，智能体则通过写文件来写。

## 每个知识集都对所有智能体生效 {#every-collection-reaches-every-agent}

知识集没有开关，也没有按智能体设置的生效范围：每个知识集对所有智能体都可用，只有删除才能让它从智能体的 `coffer-guide` 技能里消失。

::: warning 这不是访问控制
技能会把知识根目录交给智能体，智能体可以用自己的工具读取其下的任何东西。不要把这台机器上的智能体不该读的内容放进知识集。
:::

## 历史与恢复 {#history-and-restore}

知识集的每一次改动都会作为一个版本保留：你的保存和删除、立刻成为文档的上传或放进来的文件、保险库同步带进来的内容，以及在 Coffer 之外用你自己的编辑器或智能体文件工具做的编辑，一次整理就是这样显示出来的。每次改动都注明**写入者**：`user`、`agent`、`sync` 或 `disk`（早期版本的 Coffer 写的版本是 `curation`），所以你总能知道谁改了什么。

历史就是保险库仓库自己的历史：知识集位于 `~/.coffer/vault` 的 `knowledge/` 下，所以 `git -C ~/.coffer/vault log -- knowledge/<collection>/<path>` 读到的是同样的版本，[保险库同步](/zh/guides/vault-sync)会把它们带到你的其他机器上。Coffer 的保险库需要 `git`；没有 git 时，应用会一直显示 [Coffer 需要 git](/zh/guides/troubleshooting#coffer-needs-git)，直到装好为止。如果守护进程运行期间 git 没了，所有写入照常工作，历史读取会被拒绝。这个拒绝附带一段提示词，让你的智能体按适合你机器的方式安装 git，并用 `git --version` 确认：历史标签页（*历史需要 git*）和**最近改动**（*最近改动需要 git*）会显示一行，带**重新检查**和**交给智能体 ▾**（菜单里可复制提示词）。

### 查看文档的历史 {#look-at-a-document-s-history}

文档的**历史**标签页和技能的一样左右分割：左边是按从新到旧排列的版本，显示写入者和行数变化；右边是选中的版本——打开时选中最新的。拖动中间的分割线可以给任一边更多空间。右边显示差异：**这个版本的改动**（相对上一个版本）或**与当前版本比较**，除当前版本外每个版本都有**恢复这个版本**。过长的行会折行，不会被截断。如果读不出历史，标签页里会显示一行**加载错误**，带**重试**和**打开活动**，文档标签页照常可用。

恢复本身是一个新版本，写入者是你；之前的历史保持不变。已删除的文档也用同样的方式，从删除前的那个版本恢复。

### 查看最近改动 {#see-recent-changes}

树顶部的**最近改动**是所有知识集最近七天的时间线，按天分组，带**知识集**和**作者**筛选以及**清除筛选**（你的选择保存在页面地址里）。

每次改动会列出写入者、时间、知识集，以及它新增、修改或删除的每篇文档和行数。删除操作带有**恢复**（见[删除文档和知识集](#delete-documents-and-collections)）。

## 删除文档和知识集 {#delete-documents-and-collections}

通过 Coffer 删除只能由人来做。Coffer 不给智能体任何能删除知识的工具，而你可以删除任何文档，不管是谁写的。这也只是一次普通的文件删除，所以在你自己的编辑器里删文件同样可以，历史里会把它记为一次磁盘上的编辑。

- **删除一篇文档：** 知识 → 选中文档 → **⋯** → **删除文档**。
- **删除整个知识集及其中所有文件：** 知识 → 选中知识集 → **⋯** → **删除知识集**。

::: tip 删除可以恢复
在 Web 界面里，删除会立刻执行：没有确认框，也不用输入名称，只弹出一条提示 *已删除 `<name>`*，带**撤销**。被删除的文档或知识集仍在[历史](#history-and-restore)里，所以即使提示消失了，**撤销**也能把它放回来。**最近改动**会列出这次删除并带有**恢复**，它会完整放回被删掉的东西：文档回到它的知识集，知识集连同它的文档和 README 一起回来，作为一次由你写入的新改动。如果同一路径上已经又有了文档，或者同名知识集已经重新存在，恢复会被拒绝，不写入任何东西。
:::

## 不要放进知识的东西 {#what-not-to-put-in-knowledge}

- **密钥。** 不放 key、令牌或密码。请用[密钥存储](/zh/guides/secret-store)。
- **代码里已经写明的东西。** 智能体能在仓库里读到的，就不该放这里。
- **草稿笔记。** 放进来的东西，一个月后应该依然成立。

## 故障排查 {#troubleshooting}

**一次整理把文档改坏了。** 打开文档的**历史**标签页，恢复智能体编辑之前的那个版本；或者打开**最近改动**，在那里找到智能体的改动。

**整理只提供复制提示词。** 没有可用的托管智能体。到**智能体**里添加一个，或者把复制的提示词粘贴到你用的智能体里；它必须装有 `coffer-guide` 技能。

**智能体没有用到知识。** 检查 `coffer-guide` 技能已启用并且到达那个智能体（技能页面上它的**生效范围**按钮），以及知识集的 `README.md` 开头是否有一句写明主题的话。

**智能体写的文件没有出现。** 写进知识集的文档在下一次读取时就会出现。留在 `.inbox/` 里的文件必须是 Markdown，直接放在已有知识集的 `.inbox/` 文件夹里，并在下一次扫描（约一分钟内）成为文档；放在别处的文件不会被处理，不是 Markdown 的文件也不会变成文档。
