# 对话 {#conversations}

**对话**页面列出每个受管智能体（Claude Code 或 Codex）的每一个会话，无论它从哪里开始：在终端里、由 [IM 消息渠道](/zh/guides/channels)，或来自本页的**新建对话**。它是一个列表，而不是聊天客户端：打开一行，就在你自己的终端里恢复那个会话，由智能体自己的界面接手。本指南讲这个列表、新建对话、如何打开一行、运行中的轮次或等待中的提问对打开意味着什么、重命名和删除，以及对话本身存放在哪里。

## 对话页面用来做什么 {#what-conversations-is-for}

Coffer 负责的是轮次平台，让 IM 消息渠道能触达这台机器上的智能体：你在手机上给机器人发消息，Coffer 在 Claude Code（通过 Claude Agent SDK）或 Codex（通过 `codex app-server`）上运行轮次，答复回到聊天里。Coffer 不在中间插入自己的模型，也没有自己的聊天窗口。Claude 桌面应用、Codex 应用和智能体的终端本来就是聊天客户端。

这个页面多出来的是一个找到所有会话的地方，包括手机上发起的那些：你能看到有哪些会话、哪个在运行、哪个在等你，然后在桌面前接着做。

::: info Web 界面与 REST
这个列表可以从对话页面访问，也可以通过 REST API 的 `/api/v1/agent-sessions` 访问。
:::

## 前提条件 {#prerequisites}

- 一个正在运行的守护进程。用[桌面应用](/zh/guides/desktop-app)打开界面，或在浏览器里访问守护进程的地址。
- 在**智能体**页面登记至少一个受管智能体，并且它的 CLI 安装在这台机器上。见[智能体](/zh/guides/agents)。
- 可选：一个已配对给你的[消息渠道](/zh/guides/channels)，用于从手机发起的对话。你在终端里开启的会话无需它也会列出。
- 智能体已按你在终端里使用它的方式登录。对 Claude Code，运行一次 `claude` 并完成 `/login`。

你**不需要**[模型提供商](/zh/guides/providers)。提供商是可选的覆盖项；没有它时，智能体用自己的登录运行。

## 在终端中打开对话 {#open-in-terminal}

点一行，或按它的分体按钮**在 *终端* 中打开**（终端名取自你的首选终端；旁边的 **▾** 先列出其他终端，再列出**复制命令**）。Coffer 会在会话所在的目录打开终端，并运行智能体自己的恢复命令：

- Claude Code：`claude --resume <会话 id>`
- Codex：`codex resume <会话 id>`

**复制命令**会把同一条命令放进剪贴板，供你在 Coffer 不认识的终端或别的 shell 里运行。命令以进入会话所在目录开头。

在**设置 › 通用 › 首选终端**里选择终端，做法和**首选编辑器**一样：

- **系统默认**是平台自己的终端。
- Coffer 在这台机器上发现的终端按名字列出（例如 Terminal、iTerm、Warp、Orca，Linux 上有 GNOME Terminal 和 Konsole）。
- **自定义命令**接受一个模板，其中 `{cwd}` 是目录，`{command}` 是智能体命令，用于 Coffer 没有列出的终端。模板会被拆成参数后直接运行，不经过 shell。

同一节还有**交接智能体**，可选 Claude Code 或 Codex，应用里其他位置的交接按钮会用到它。

命令由守护进程根据会话 id、目录和智能体自己构造，页面从不发送命令行。会话 id 里出现字母、数字和连字符之外的字符会被拒绝。终端启动失败时，提示会说明原因，**复制命令**是出路。

### 一个会话，一个地方 {#running-or-waiting}

一个会话同一时间应该只在一个地方运行。当一行的轮次正在运行，或智能体在等你回答时，打开按钮会先询问：

- **在*平台*里回答**（或等待）：让轮次留在原地，用消息渠道。
- **停止这个轮次并在终端中继续**：像**停止**一样停止轮次，告诉智能体是你停的，然后打开终端。

反过来，当一条消息渠道的消息到达一个正在终端里打开的会话时，Coffer 不会启动轮次。聊天里会回复该会话在终端里打开着：到那里继续，或发送 `/thread` 开一个新的。Coffer 靠查找参数里带有该会话 id 的进程来判断，所以在智能体自己的列表里选出来打开的会话看不到；Codex 自己会拒绝第二个写入者。

## 回答智能体的提问 {#answer-a-question}

智能体需要决定时，会通过 `coffer__ask`（或 Claude Code 自己的 `AskUserQuestion`）提问，它的轮次暂停，直到你回答。你在消息渠道里回答，点卡片或在聊天里回复，见[消息渠道](/zh/guides/channels)。对话的那一行显示**等你处理**，概览也会把它列在**需要你处理**下。

页面没有回答卡片，也没有回复框。如果你想在桌面前回答，用这一行的分体按钮：它会先询问，选**停止这个轮次并在终端中继续**会结束这次提问（智能体会被告知是你停止的），并在终端里恢复会话。提问本身只保存在守护进程的内存里；守护进程重启会丢掉未回答的提问。

## 轮次进行中继续发送 {#send-while-a-turn-runs}

轮次运行时你发给机器人的消息会在对话的队列里等待，按顺序各自成为一个轮次。消息渠道的 `/status` 会统计它们。队列在守护进程的内存里，所以重启守护进程会丢掉还没开始的消息。

## 停止轮次 {#stop-a-turn}

运行中的行带有一个行内**停止**。停止会结束轮次，把智能体已产生的内容连同一句你停止了它的说明发到聊天里，并**暂停**待处理队列，这样下一条排队消息不会直接冲进你刚停掉的轮次。消息渠道的下一条消息会恢复队列。它和消息渠道里的 `/stop` 是同一个动作，对列表里任何对话都有效。

## 轮次失败时 {#when-a-turn-fails}

失败的轮次会在消息所来自的聊天里报告。除了智能体自己报告的错误，Coffer 还会报告三种自己的失败：

| 错误 | 含义 |
| --- | --- |
| `stream_ended` | 智能体的事件流在没有完成事件的情况下结束了：它的进程在轮次中途退出或断了连接。 |
| `turn_timeout` | 智能体在空闲窗口内没有产生任何事件：`COFFER_TURN_IDLE_TIMEOUT_SECONDS`，默认 300。设为 `0` 可关闭这个看门狗。 |
| `daemon_stopped` | 轮次运行时守护进程关闭了。 |

轮次从不悄无声息地结束。守护进程被直接杀掉也不会留下写了一半的东西：消息渠道的下一条消息会恢复智能体的会话。

如果 Claude Code 没有登录，回复会说明，并提示你运行 `claude` 完成 `/login`。

## 附件 {#attachments}

你发给机器人的照片、文件或语音消息，会以引用的形式交给智能体，指向 Coffer 下载到 `~/.coffer/content/channel-media` 的文件；限制见[消息渠道](/zh/guides/channels)。智能体如何收到附件取决于附件类型：

- **图片**：PNG、JPEG、GIF 或 WEBP 图片，如果编码发送后不超过 5 MB（磁盘上约 3.75 MB），Claude Code 会内联收到，作为它能看到的图片。更大的图片或其他格式的图片会以文件路径的形式交给 Claude Code，这样轮次仍能运行。Codex 总是收到文件路径。
- **文档**（PDF、Office 格式、epub、rtf）：提取成文字放进提示词，所以每个智能体都能读到内容。如果无法提取或提取失败，智能体收到文件路径。
- **音频**：在**设置 › 通用 → 语音转文字**下打开了**语音转文字**时，会转写成文字。关闭转写时，什么都不会离开你的机器，智能体收到的是音频文件。

文件在**附件**保留期之后清理（默认最后修改 30 天后；可在**设置 → 数据 → 本地内容**里修改，或永久保留）。之后智能体再也打不开这个文件。Web 页面不上传文件。

## 管理对话 {#manage-conversations}

`/conversations` 列出每个受管智能体的每一个会话，无论它从哪里开始：在终端里、由消息渠道，或来自**新建对话**。按最近活动从新到旧排列；对话在轮次开始时就会移到顶部，不只是在轮次结束时。列表先读 30 个，滚动时再加载更多，也不显示总数，因为 Codex 不读完全部会话就数不出来。行的上方有一行表头，写着列名：**标题**、**来源**、**智能体**、**目录**和**最近活动**，行按**今天**、**昨天**和**更早**分组。每一行显示：

- 标题；如果是消息渠道的对话，还带一个状态词：轮次进行中是**运行中**（绿点），智能体在等你回答是**等你处理**（黄点）；
- **来源**：消息渠道的对话显示平台的图标加它聊天里的位置，例如 `SeaTalk · DM`、并行线程的 `SeaTalk · DM · Thread 2`、`SeaTalk · coffer-dev › thread` 或 `Telegram · Group › topic`；你自己开启的会话这里不显示任何内容；
- **智能体**、工作**目录**和**最近活动时间**（今天和昨天显示时钟，更早显示 `Sep 22` 这样的日期）；
- 轮次运行时有行内**停止**，还有分体按钮（**在 *终端* 中打开 ▾**）和 **⋯** 菜单。这些始终显示。

列表上方：一个按标题和目录搜索的搜索框（按 `/` 跳到它）、一个**来源**筛选和一个**智能体**筛选，以及筛选生效后出现的**清除筛选**。**来源**筛选提供**这台 Mac**（不是消息渠道发起的会话）和每个消息渠道，可多选。筛选由服务器执行，所以滚动加载的只是匹配项。它们是 URL 的一部分，所以筛选后的列表就是一个链接：

- 搜索：`?q=sentry`。
- 来源：`?source=local` 表示这台 Mac，`?source=<渠道 uid>` 表示某个消息渠道，也可以用逗号连起来。消息渠道总览页上的**来自此渠道的对话 →** 链接会打开列表，并勾选该渠道。
- 智能体：`?agent=codex`。

如果某个智能体的会话读不出来（比如 Codex 没有响应），其他智能体的会话仍然列出，列表上方用一行写出这个智能体的名字，并带**重试**。只有所有智能体都读不出来时，页面才改为显示带**重试**的错误。

分体按钮写作**在 *终端* 中打开**，终端名取自你的首选终端，它的 **▾** 先列出其他终端，再列出**复制命令**。**⋯** 菜单有两个动作，都由智能体自己对它自己的会话执行：

| 动作 | 效果 |
| --- | --- |
| **重命名** | 直接在行内编辑标题。先在智能体里重命名会话（Claude Code 的 `rename_session`，Codex 的 `thread/name/set`），再改 Coffer 的这一行，所以新标题在智能体自己的列表里也能看到。Coffer 不会覆盖你设置的名字。 |
| **删除…** | 先确认，然后在智能体里删除会话并移除这一行。**这是永久的**：智能体自己的会话文件会随之删除，其中正在运行的轮次会被取消。消息渠道的下一条消息会开始一个新的对话。 |

还没有任何智能体有会话时，页面只有标题和一条消息。筛选没有匹配项时，**没有匹配的对话**提供**清除筛选**。窗口重新获得焦点时，以及对话变化时，列表会刷新。

### 新建对话 {#new-conversation}

页头的**新建对话**，以及[智能体的会话标签页](/zh/guides/agents)上同样的按钮，会在你的终端里开启一个全新的会话。它打开一个小对话框，有两个字段：

- **智能体**：Claude Code 或 Codex。对话框会记住你上次选的那个。
- **工作目录**：默认是 Coffer 的工作区 `~/.coffer/content/workspace`；用文件夹选择器可以换成别的。

确认按钮写作**在 *终端* 中打开**（你的首选终端），它的 **▾** 列出其他终端。确认后，会在那个目录里不带参数地运行智能体，由智能体自己的界面开启新会话。Coffer 还不知道新会话的 id，所以这一行不会立刻加进去：等智能体记录下这个会话后，它会在下一次刷新时出现，回到 Coffer 窗口就会触发一次刷新。

对话不会被归档，没有「活跃/已归档」开关，也没有批量操作栏。已不再由 Coffer 管理的智能体的会话不会出现；所属消息渠道已删除的对话仍会出现，作为它所属智能体的一个会话。

## 对话和智能体自己的会话 {#chat-and-the-agent-s-own-sessions}

**Coffer 不保存说过的话。** 一个对话就是智能体的一个真实会话。Coffer 只存一行小小的索引（标题、所属的消息渠道和聊天、目录和智能体的会话 id），每个轮次都恢复这个会话，所以智能体保留自己的上下文，和在终端里完全一样。智能体自己的会话就是记录：消息、工具调用和结果都在智能体的文件里，**智能体 › *智能体* › 会话**把它们和你直接在终端里跑的会话列在一起。轮次不会写进审计日志。

如果智能体不再认识存下的会话 id，Coffer 会把这个轮次作为全新会话重试一次，而不是直接失败。

::: warning Claude Code 会清理旧会话
Claude Code 会删除超过 `cleanupPeriodDays` 没有动过的会话，**默认约 30 天**。因为 Coffer 不留副本，比这更久的对话就无法再恢复或打开：它的聊天里的下一条消息会作为**全新会话**继续，没有之前的上下文。想保留更久，请在 Claude Code 的 `settings.json`（`~/.claude/settings.json`，或智能体配置目录里的 `settings.json`）里调大 `cleanupPeriodDays`，例如 `{ "cleanupPeriodDays": 365 }`，然后重启 Claude Code。这只能保护还没被清理的会话。
:::

每个对话只有一个所有者：你。Coffer 不支持多人共享一个对话；让手机能驱动对话的消息渠道配对，和你的浏览器会话是同一个信任决定。

## 智能体从保险库拿到什么 {#what-the-agent-gets-from-the-vault}

消息渠道的轮次运行在同类型已登记智能体的配置目录上（每种类型一个）。Coffer 把[技能](/zh/guides/skills)投递到这个目录，并在这里装它的 MCP 条目，所以消息渠道里的智能体拥有和你终端里一样的 Coffer 技能和 [MCP 服务器](/zh/guides/mcp-servers)。这个智能体的配置目录不在标准位置时，Coffer 会为轮次设置 `CLAUDE_CONFIG_DIR` 或 `CODEX_HOME`。

在智能体自己的系统提示词之后，Coffer 按以下顺序追加：

1. 一段说明，告诉智能体它在聊天渠道上，回复要简短，而且它不能点你电脑上的对话框。
2. 对话工作目录和 `global` 的[记忆](/zh/guides/memory#in-channel-turns)索引，以及笔记所在的位置。
3. 说明 Coffer 让智能体用的是哪个模型。

从对话页面打开或用**新建对话**开启的会话在你的终端里运行，在 Coffer 之外，所以不追加记忆；智能体连接到 Coffer 后，会通过它自己设置里 Coffer 的记忆 Hook 收到记忆。

::: danger 完全权限
消息渠道的轮次以 `bypassPermissions` 运行 Claude Code，以 `approvalPolicy: never` 和 `sandbox: danger-full-access` 运行 Codex。Coffer 不会让你逐个批准工具调用。把消息渠道配对到你自己的账号，就是来自 IM 的轮次的关卡；见[消息渠道](/zh/guides/channels#security)。
:::

## 工作原理 {#how-it-works}

一条消息渠道的消息会在守护进程里启动或排队一个轮次。轮次的输出是一串带类型的事件（`turn_start`、`text_delta`、`tool_call`、`tool_result`、`turn_done`、`turn_error` 和 `queue_changed`），由消息渠道渲染到聊天里。这个流在轮次运行期间存在于内存中，不会存下任何东西；Web 界面不订阅它。设计见[对话与轮次](/zh/architecture/chat)。

## 故障排查 {#troubleshooting}

**智能体显示为不可用。** 要么它的 CLI 不在你的 `PATH`（登录 shell 的 `PATH` 与守护进程自己的合并）上，要么没有注册该类型的智能体。安装 CLI，然后在「智能体」页面选**连接**。Coffer 只运行它管理的智能体。

**每个轮次都以 `stream_ended` 失败。** 智能体进程在轮次中途退出了。先确认智能体在终端里能正常工作，再到**活动 → 守护进程**查看底层错误。

**没有流式输出，回复一下子全部出现。** Claude Code 轮次需要支持部分消息的 CLI。SDK 使用自己内置的 CLI；如果它缺失、而 `PATH` 上的 `claude` 又太旧，轮次会在连接时失败。请更新 Claude Code。

**「在 *终端* 中打开」没有反应。** 检查**设置 › 通用 › 首选终端**：没有安装的终端，或写错了的自定义模板，都无法启动。用**复制命令**，粘贴到终端里。

**终端提示没有可恢复的对话。** 智能体已经清理了这个会话（见[上文](#chat-and-the-agent-s-own-sessions)）。消息渠道会在下一条消息时作为全新会话继续。

**页面显示一条横幅而不是列表。** 守护进程无法访问。见 [Web 界面](/zh/guides/web-ui#when-the-daemon-is-not-reachable)。
