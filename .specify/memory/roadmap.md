- **2026-09-09** — **Desktop shell retired (2026-09-09):** spec mcp-gateway (MCP Gateway Desktop) is retired and its directory deleted; the daemon now serves the built web UI itself at its own loopback origin, the daemon hands the browser an authenticated session by injecting its live token into the `index.html` it serves, guarded by a loopback-`Host` check ([The Daemon Serves Its Token in the Page](../../docs/decisions/daemon-serves-the-token-in-the-page.md)), the frozen daemon deploys its sibling binaries into `~/.coffer/bin/` on start, and the release collapses to one `coffer-cli-<triple>.tar.gz` tier plus an aggregated `SHA256SUMS` (spec mcp-gateway FR-022–FR-026, [PyInstaller Distribution](../../docs/decisions/distribution-pyinstaller.md))
- **2026-09-12** — **Fixed daemon port added 2026-09-12:** the port is a persistent setting in `~/.coffer/daemon-config.json`, read before the database opens, so a browser bookmark to Coffer's UI survives restarts. Set it and the daemon binds exactly that port or refuses to start, naming the process that holds it; leave it unset and the 8000–8009 scan is unchanged. CLI (`coffer daemon port show/set/clear`, plus the `coffer daemon restart` the ADR had long referenced without it existing), REST and Settings → General all reach it (spec mcp-gateway FR-028)
- **2026-09-12** — **Desktop shell restored 2026-09-12, and the port default inverts:** the 2026-09-09 retirement priced the cost of every update and not the cost of access — without a shell Coffer is one `127.0.0.1` tab among dozens, with no Dock icon and no route to the UI that does not begin by knowing whether a daemon is running. The shell returns smaller than it left: binary deployment stays in the daemon's frozen-start path and native file actions stay on daemon HTTP routes a webview reaches like any browser tab, leaving it the four things a browser cannot do for itself — a Dock-visible window, a resident tray, detect-or-spawn at launch, and the IPC credential handshake a locally-hosted page has no other way to make. One `frontend/dist` serves both hosts, which gain a second credential *supplier* and not a second code path. Distribution grows a second tier: a self-contained `.dmg` embedding `coffer`, `coffer-daemon`, `coffer-mcp-shim` and `coffer-callback`, reusing the artifacts the CLI leg already freezes, and since FR-026 deploys all four into `~/.coffer/bin/`, installing the app installs the CLI. The daemon's port default inverts with it — bind 8000 and refuse to start rather than scan, because a drifting origin silently resets every browser-stored preference — and the Settings card and `/settings/daemon` endpoints go, leaving `coffer daemon port set/clear` as the escape hatch (spec mcp-gateway FR-022, FR-026, FR-028 – FR-032, [The Desktop Shell Returns](../../docs/decisions/desktop-shell-over-a-shared-frontend.md))

### 007 — Knowledge Layer

- **2026-06-12** — Accepted — code merged in PRs #55/#58 ([Files as Truth](../../docs/decisions/files-as-truth-sqlite-retrieval.md) + [One Shared Knowledge Store](../../docs/decisions/agent-native-shared-memory.md))
- **2026-09-09** — **Removed 2026-09-09:** transcript distillation (the automatic ingest half of the memory loop) and the `journal` lane it wrote into; writes are explicit — `coffer__write` in, `coffer__search` out
- **2026-09-10** — **Merged 2026-09-10:** spec knowledge (Knowledge Base) is absorbed here and its directory deleted. Memory and the knowledge base were always two faces over one substrate — `documents`, `chunks`, FTS5 and sqlite-vec were shared from the start — so they collapse into a single resource kind `knowledge`: one storage root `~/.coffer/knowledge/<scope>/` with `knowledge/` (agent-written entries), `inbox/` (ingested documents), `rules/`, `handoff/` and `superseded/` lanes; scope read from the resource name (`global` and `project-<ULID>` auto-provision, any other name is a collection the user created deliberately); 8 MCP tools instead of 12; one `coffer knowledge` CLI group; one `/api/v1/knowledge` route family; one **Knowledge** page. The directory stays `specs/knowledge/` deliberately — it is the acceptance-audit spec id and the target of every inbound link — so that folder name is now historical
- **2026-09-10** — **Removed 2026-09-10:** the rules lane's delivery channel — FR-049 (SessionStart hook), FR-050 (the two seeded built-in rules), FR-052 (`disable_native_memory`) and FR-055 (ambient project-knowledge index). Rules are still written, classified, stored and synced; nothing pushes them into a session any more, so an agent must reach for the knowledge tools itself — the eight `coffer__` tools the layer exposes are `search`, `grep`, `read`, `list`, `write`, `delete`, `set_handoff` and `resume`. That is a real loss of the delivery half of cross-agent memory, accepted because the hook — though shipped — had never actually been installed on the maintainer's machine, so the injection path had never run
- **2026-09-11** — **Redesigned 2026-09-11 — two lanes:** the storage lanes collapse to the two kinds of material a person actually distinguishes, `notes/` (what an agent or the user wrote; `coffer__write` lands there) and `docs/` (uploaded documents, normalized to markdown), plus hidden `.history/` (pre-rewrite copies) and `.raw/` (uploaded originals). `knowledge/`, `knowledge/inbox/`, `knowledge/INDEX.md`, `inbox/`, `rules/`, `handoff/`, `superseded/` and `consolidation-log.md` are deleted, destructively and with no holding pen; `documents.lane` becomes `notes` | `docs`. The rules lane goes outright — its delivery channel was removed on 2026-09-10 and nothing read it — and the handoff lane takes `coffer__set_handoff` and `coffer__resume` with it, leaving **six** MCP tools: `search`, `grep`, `read`, `list`, `write`, `delete`. The inbox organizer is replaced by a **periodic tidy**: a bounded agentic pass over `notes/` that merges duplicates and rewrites notes into topic documents, copying the prior revision into `.history/` first, run by a background worker shaped like the `RetentionWorker` (boot catch-up pass, then on an interval), a no-op with no internal model configured, and triggerable by hand from the page's Tidy button or `coffer knowledge organize`; each pass is recorded in the existing audit log instead of a per-scope changelog file. The AI-assisted scope merge (FR-056…FR-058) is deleted with its CLI and routes — worktree-aware `git_root` fixed the fragmentation at its root and `consolidate.py` heals the residue at every daemon start. Files-as-truth and vector retrieval are untouched
- **2026-09-12** — **Reduced to plain files 2026-09-12:** the layer stops being an index and becomes a directory ([Knowledge Is Plain Files](../../docs/decisions/knowledge-is-plain-files.md), which supersedes Files as Truth and Retrieval Mode Is Internal). An audit of the live installation found most of the machinery had never executed — `embedding_config` was an empty table, `.history/` did not exist on disk, 50 of 50 documents were `converter: passthrough`, and every knowledge tool call in a month landed on the single day an agent built the corpus. Two structural mistakes explained it: properties had been built as directories (the `notes/` ÷ `docs/` lanes, the `global` ÷ `project-<ULID>` ÷ collection scopes), and with embeddings never configured an index bought only ranking the agent does for itself. So: markdown files under `~/.coffer/knowledge/<collection>/`, path as identity, readable slugs instead of ULIDs, frontmatter of exactly `title` / `description` / `actor` / timestamps, and a collection that describes itself in its own `README.md`. Retrieval is a generated catalogue (`list`, one level at a time) plus ripgrep, and there is no `search` tool — **five** MCP tools: `list`, `grep`, `read`, `write`, `delete`. A collection is the only boundary and exists to be authorized by the framework's per-agent scope; nothing is derived from a cwd and nothing auto-provisions. Upload and format conversion go — the filesystem is the ingestion surface. Tidy survives, still archiving into `.history/`, with its background worker governed by one installation-wide setting that is **off by default**, and Coffer now delivers a `coffer-knowledge` skill so agents learn the layer exists. Migration 0066 rewrites the tree and drops eleven tables, leaving the layer with none
- **2026-09-12** — **Ingestion and ranked retrieval restored 2026-09-12:** three of the reduction's removals come back, for reasons the reduction did not weigh — document **upload** with conversion to Markdown and the original kept under `.raw/` (the filesystem is not reachable from the phone the user actually works from, and a channel already accepts attachments), and **ranked semantic retrieval** with a sixth tool `coffer__search` (spec memory must answer "what bears on this task" against material the caller cannot quote, under a budget that forbids the catalogue). Path-as-identity, frontmatter-as-metadata and files-as-sole-truth are untouched. Two constraints keep the audited failure from recurring: embeddings ride the already-configured `internal_default` connection with **no settings surface of their own**, and the index is a **disposable sidecar** outside the vault and outside `coffer.db` with a literal-search fallback that answers while it is missing. No vector-store or embedding-model dependency is added (spec knowledge FR-032–FR-037, FR-080–FR-081)
- **2026-09-14** — **Ranked retrieval removed 2026-09-14:** embeddings go out of Coffer entirely — the ranked-retrieval engine shared with memory, the disposable sidecar and its `~/.coffer/index` directory, the `/embeddings` client, the `index` / `index/rebuild` routes and `coffer knowledge index` / `reindex`, and the `score` / `heading` / `mode` / `reason` fields. `coffer__search` keeps its name and keeps answering: it is now the literal tier that used to be its fallback — ripgrep over the visible collections, reported as files with their matched lines. This is a deliberate reduction of a capability that was built and worked, not a cleanup of dead code, and it costs what the 2026-09-12 restoration was buying: a query in the caller's own words no longer finds what a distinctive phrase would not. Six MCP tools still: `list`, `grep`, `read`, `search`, `write`, `delete`. Migration 0077 purges the `embedding_config_updated` audit rows; no table is dropped because none was left (spec knowledge FR-024, FR-028, FR-029, FR-080)

### 010 — Vault Sync

- **2026-09-09** — Accepted — **downgraded from continuous multi-machine sync.** Coffer now exports the vault to a directory the user picks and imports one back; no remote, no git workspace, no background worker, no machine registry and no tombstones ([Vault Export and Import](../../docs/decisions/vault-sync.md)). Carrying the directory between machines is the user's business, so the feature needs no exception to Principle I — the constitution 0.4.0 amendment removes the 0.3.0 user-controlled-medium exception
- **2026-09-09** — **Scope collapsed to one axis:** resource `scope` is a list of agent names, not a machine × agent matrix; the top-level Machines fleet view is removed along with the machine identities it rendered ([Per-Agent Resource Scope](../../docs/decisions/per-agent-resource-scope.md))
- **2026-09-10** — **Key bootstrap carries material, not a path (2026-09-10):** `POST /sync/key/export` returns `{material}` and `POST /sync/key/import` accepts it; each surface does its own file I/O (the CLI writes/reads the file, the web UI uses a browser download and `<input type="file">`), so the daemon opens no caller-named path and runs no `osascript`/`zenity` save/open dialog
- **2026-09-12** — **Backup remote added 2026-09-12:** exports can be committed to a git working tree and pushed to one user-owned remote on a timer, with `coffer sync restore [--at <rev|date>]` as the recovery path — answering disk loss and late-noticed deletion, which moving a directory by hand does not. One-way only: the constitution 0.5.0 amendment authorises backup, explicitly **not** the convergence machinery 0.4.0 removed
- **2026-09-13** — **Redesigned 2026-09-13 — bidirectional convergence:** the remote stops being a backup and becomes a **rendezvous** the vault converges with ([Vault Sync](../../docs/decisions/vault-sync.md), constitution 0.6.0, which replaces the 0.5.0 one-way backup exception with a *user-owned sync remote* one). A background worker runs a converge round: it serializes the vault differentially into the git working tree and commits it as `L`, merges `origin/<branch>` into `L` giving `M`, and applies the diff `L..M` back into the vault path by path — deletions included — so what lands is exactly what the remote contributed rather than a wholesale overwrite, and the local **pointer** at the last provably absorbed commit is the base of every diff. Local export and import are **deleted**: writing a bundle to a directory and reading one back is an overwrite with no base — the operation behind the 2026-07-10 mutual deletion — and the needs it served are met without it (a new machine runs `coffer sync adopt`, an offline medium is a `file://` remote, handing someone a copy is `git clone`). Resource `scope` regains a **machine axis**: two `AND`-ed lists, `agents` and `machines`, each `null` meaning unrestricted, so `machines: null` reproduces today's behaviour and existing rows migrate by addition. The machine registry returns as a **derived view**, not the synced table 0.4.0 deleted — each machine writes exactly one `machines/<machine_id>.yaml` it alone owns, so descriptors cannot conflict and the registry is whatever the tree holds; `machine_id` is derived from the host (`IOPlatformUUID` / `/etc/machine-id`, hashed before it travels) so a reinstall returns under the same identity instead of becoming a ghost. Sync leaves Settings for a **top-level Sync page** with Status and Machines tabs. Two guards bound the blast radius of writing the vault unattended: a pre-apply snapshot tag per round, and a circuit breaker that holds an oversized deletion for confirmation in both directions — what a round would apply here, and what its own export would publish as a deletion. The knowledge tidy pass, the one unattended rewriter of synced content, gains an owner machine so one corpus is never rewritten twice
- **2026-09-14** — **Reach made machine-local 2026-09-14:** a resource's **reach** — its `enabled` flag and its `scope`, one control in the UI and one decision to the user — is declared machine-local and is **removed from the bundle entirely**: a resource document is now identity, description and config, a converge round neither reads nor writes reach, and every machine sets its own. With that settled the **machine axis is withdrawn again** — `scope` is a list of agent names, `is_active(scope, agent)` is the only predicate, and `excluded_by` / `agent_axis_admits` / the `ScopeEvaluator` that existed solely to bind this machine's id are deleted along with it. Migration `0076` strips the `machines` key, resolving each row against the machine id the daemon was actually using and taking `agents: []` (dormant) whenever it cannot tell, so nothing widens. The `channel` kind stops converging at all — it is an inbound surface bound to one host — and `resources/channel/**` is ignored in **both** directions, because the first round after the change publishes the deletion of the channel documents already in the tree and a machine that honoured it would lose the channels it configured itself. The machine **registry** is untouched: it belongs to sync, not to permissions. The reach control states, where reach is set, that it stops at this machine

## Explicit non-goals (current spec)

Decisions about what `mcp-gateway` does **not** ship. Documented here so
reviewers do not mistake their absence for an oversight.

- **macOS Apple notarisation** — requires a paid Apple Developer account; users
  clear quarantine manually on the extracted release binaries. Add when the
  account is set up.
- **Streaming progress forwarding through the gateway** — no mainstream MCP
  gateway does this; this spec matches the ecosystem (token passthrough +
  timeout reset, no active forward).
- **System service install** (launchd / systemd / Windows service) — additive
  to [Detect-or-Spawn](../../docs/decisions/daemon-detect-or-spawn.md)'s detect-or-spawn pattern; can be added later as
  `coffer daemon install --system` without breaking the current model.
- **Plugin marketplace / third-party kind authoring** — see [Resource Framework Upfront / Layer-First Code Layout
  alternatives](../../docs/decisions/resource-framework-upfront.md).
- **Tool call argument or result persistence** — the invocation log records
  who / when / how-long / outcome only; argument and result content are
  considered sensitive and stay out of the database.

## How this file grows

When a new spec is drafted (`/speckit-specify` in Coffer's flow), add a row to
the **Active** table with its number, title, and status. When a spec ships,
update its status. Do **not** pre-allocate numbers or pre-name features that
have not yet had a spec written.
