## 问题

单个用户在多台机器上运行 Coffer，每个保险库都会各自分叉。宪章禁止把厂商云
作为权威数据源（system of record），因此在一个有边界的修订案允许使用
**用户自有**介质之前，同步一直是非目标。

## 传输方案

| 方案                           | 历史/合并     | 本地优先契合度 | 冲突处理          | 结论    |
| ------------------------------ | ------------- | --------------- | ----------------- | ------- |
| **用户自有 git 仓库**          | 内建          | 强（用户拥有远端） | git 三方合并 + 单文件粒度 | **选定** |
| 点对点（Syncthing 风格）       | 无            | 最强            | 后写者胜，无历史 | 推迟 |
| 用户自有对象存储（S3）         | 无            | 强              | 弱               | 否决 |
| 托管的 Coffer 服务             | 不适用        | 违反原则 I | 不适用          | 否决 |

对开发者受众而言 git 胜出：他们本就有 git 凭据，而我们能免费获得
diff/历史/合并能力。

## 为何采用独立工作区 + 导出/导入（而非提交实时目录）

`coffer.db` 是二进制且不可合并的，而实时运行时目录把真值
（knowledge/memory 文件）和可重建/本地状态（db、日志、daemon.json）混在一起。
一个专用工作区配合文本导出，能让 git diff 保持有意义，并让
SQLite 继续作为本地权威数据源。Knowledge/memory 本就是文件，因此
可直接镜像；config 和 credentials 则投影为文本。

## 为何只导出密文 + 带外密钥

把主密钥放进仓库会让密文失去意义，并违反修订案。只导出密文意味着即便是
托管在 GitHub 上的远端也不含任何可用内容。每台机器一次性的密钥引导
是被接受的代价；在密钥存在之前，密文会被报告为已锁定，而不是悄无声息地失败。

## 为何默认手动 + 可选开启自动

单个用户通常一次只在一台机器上，因此手动 `coffer sync` 是
可预测且冲突少的。自动同步（防抖推送 + 定时拉取）作为一种无需人工干预的
收敛便利方式提供，但保持为可选开启，以避免意外的后台网络
和意外的冲突。

## 确定性

干净的合并依赖于稳定的序列化：键排序、时间戳归一化，
以及排除机器本地字段（`id`、`created_at`、`updated_at`）。这一点经过了
单元测试，因为它对整个合并故事是承重的。

## 2026-09-13 —— 为什么收敛又回来了

在 0.4.0 那次撤销被推翻之后追加。推动它的有三条发现，而每一条都能在仓库里查证，
不必靠回忆。

### 1. 2026-07-10 那次事故是导出的缺陷，不是对收敛的证伪

两个提交把它关掉，而它们指向同一个根因。

`c856196f` —— *merge-safe export, auto-resolve conflicts, remote probe (#290)*。
它自己对事故的描述是：两台跑着不同构建的机器互相删掉了 skill、记忆与资源，因为
**导出是破坏性的**——它 `rmtree` 之后从本地状态整棵重写——并且跑在两台机器各自的第一次
导入**之前**。那些修复统统是在让导出的树变诚实：保留那些没有本地行、也没有墓碑的
工作区文档（是「待导入」，不是「已删除」）；只有在本机的某次运行已经完成过一次导入之后
才传播树与凭据的删除；收敛大小写别名的凭据路径（v3 之前小写的 ref 与 v3 的资源名大小写
在 macOS 上把 `git add` 弄坏了）；按路径以「更新者胜」自动解决冲突；在接受一个远端之前
先无头探测它。同一个 PR 上的一趟评审又找出四个问题，其中两个值得作为关于这套机械的
教训带走：一个中文名的冲突文件从 `git diff` 回来时是 C 引号转义的，把自动解决逼进了
一个报错重试循环（在 `ensure_repo` 里加 `core.quotepath=false`）；以及一个瞬时错误
会挂起删除传播，其方式恰好会通过同一次运行的导入**把用户的删除复活**。

`ad430204` —— *credential guards from the 2026-07-10 stale-clobber incident
(#293)*。三条发现：`install_key` 会就地截断既有主密钥的唯一一份副本，从而永久孤立
用它加密过的一切（现在会先备份到一个带时间戳的同名兄弟文件）；Fernet 密文块在**明文**
里嵌着自己的加密时间，因此同一个 ref 的两份密文完全不需要密钥就能排序——现在由一个
共享的比较器在三处这样做；以及删除一个资源会留下孤儿凭据行，而此后每一次导出都会把
它们重新播种进 vault，直到某一次盖掉了另一台机器上重新创建的 ref ——用那个提交自己的话
说，这就是*事故的源头*。

合起来读，上面每一条都是**树是怎么被写出来的**这件事上的缺陷。没有一条能论证两个 vault
无法收敛。破坏性导出是唯一的根因，而基于 diff 的应用是在结构上消除它、而不是防着它：
一条删除之所以能进入 diff，只可能是因为某台机器相对于共同 base 真的删掉了那份文档。

### 2. 0.4.0 的移除删掉了那套机械，而失败的并不是那套机械

`git show 1d58f5f2 --stat` —— *replace continuous sync with vault export and
import (#314)* —— 是一个 57 个文件的改动。它把收敛切片整个删掉了：
`application/sync/` 失去了 `auto_resolve.py`、`config_service.py`、`identity.py`、
`machines.py`、`slice.py` 与 `worker.py`；`infrastructure/sync/` 失去了 `git_repo.py`
与 `persistence.py`；`domain/sync/` 失去了 `fernet_time.py`。`exporter.py`、
`importer.py`、`ports.py`、`service.py`、`models.py` 与 `errors.py` 被掏空，而
migration 0049 删掉了四张 sync 表，并把 `scope` 从两条轴塌缩成一条。

其中三项移除如今正被撤销，值得把是哪三项说清楚：**机器身份**、**Fernet 时间比较器**
——它是整个切片里唯一一条不需要密钥也可证明正确的守卫——以及 **scope 的机器轴**，
后者当初被撤掉只是因为给它做键的机器注册表要没了。

> 机器轴回来了，又在同一天被再次撤除。这一次的理由不是机器不存在了：一项资源的
> *触达范围 (reach)*——它的 `enabled` 开关与它的 `scope`——被确定为本机专属，于是
> 「这东西在这里触达到哪里」由每台机器各自回答，机器轴也就再没有什么可表达的了。见
> [Per-agent resource scope](../../docs/decisions/per-agent-resource-scope.zh.md)。

### 3. 取代它的东西没有回答问题，而且其中一半很快又回来了

导出/导入是没有 base 的整体覆盖：导入器对 bundle 包含的一切都采用 bundle 的版本。
那正是造成事故的那个操作，只不过改由人手刻意执行。三天之后，备份远端（章程 0.5.0）
为了单向用途又把 git 工作树与后台 worker 加了回来——0.4.0 移除的三样里的两样，同一周
内就回来了，服务于一个严格更弱的目的。

### 这在设计上改变了什么

- base 是一个 **pointer**，保存在本地、永不随行。一个会随行的 pointer，就是把别人的断言当成
  自己的来读。
- 导出是**差分的**，且是规范性的。它是唯一的根因，因此它是 spec 里的一条规则，而不是
  某个实现的性质。
- 删除来自 diff，这让**墓碑、它们的 TTL 与时间戳仲裁都变得不必要**——那是 0.3.0 那套
  机械的大部分。
- `machine_id` **派生自主机**，于是注册表完全不需要任何本地状态就能回答「我以前来过
  这里吗」。这正是把新机器（取并集）与回归机器（恢复 base）分开的东西，也是重装之后
  仍然可以信任这次加入检测的原因。
- **Fernet 新鲜度比较器从 `ad430204` 原样回归**。它是正确的、是廉价的，也是唯一能在
  没有密钥的情况下给两份密文排序的规则。
- 熔断器守卫**两个方向**。应用侧一向是显而易见的；发布侧才是阻止一个被清空的 vault 把
  自己的损失导出去的东西——从另一端抵达的那个 2026-07-10 形状。

### 2026-06 的调研里什么存活了、什么被推翻了

存活：git 作为传输、仅密文加带外密钥的凭据处理、确定性要求，以及对着各机器 home 的
路径可移植。

推翻：**「默认手动 + 可选开启自动」**——收敛本身就是目的，因此只要配置了远端，worker
就开始跑。而**「独立工作区 + 导出/导入」**被推翻了一半：独立工作区完全正确、留下来，
而它当初服务的那个导出/导入动作被删掉。
