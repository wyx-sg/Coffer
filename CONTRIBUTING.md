# Contributing to Coffer

Thanks for the interest in Coffer. This file is the **human contributor** entry point. AI agents (Claude Code, Codex) should read [`AGENTS.md`](./AGENTS.md) instead.

## Quick Start

```bash
git clone https://github.com/wyx-sg/Coffer.git
cd Coffer
make install                       # .venv from uv.lock + frontend, OpenSpec CLI and e2e npm deps
make hooks                         # wire pre-commit + commit-msg hooks
make dev                           # backend (:8000) + frontend (:5173)
```

## Workflow

1. Branch off `main` (see [`.agents/workflow.md`](./.agents/workflow.md) for naming).
2. If the change is user-visible, propose an [OpenSpec](https://github.com/Fission-AI/OpenSpec) change **first** (`/opsx:propose`), and archive it (`/opsx:archive`) in the same PR (see [`.agents/openspec.md`](./.agents/openspec.md)).
3. Implement, with tests in the right tier (see [`.agents/testing.md`](./.agents/testing.md)).
4. `make verify-all` locally.
5. Open a PR; title must be Conventional Commits.
6. Wait for review + merge. Branch is squash-merged.

### Work that is not ready yet

There is one line of development: everything lands on `main`, and a release is a
tagged `main`. Work that is not ready for users still lands there, behind an
entry in the experimental-feature registry (`coffer.domain.features`), so it is
off on a `stable` build and on in every `dev` build, including your own. Gate
every surface it adds through that entry — never a prefix or a group name of
its own. Once the feature is ready, remove it from the registry and delete its
gates in the same PR. Do not keep a long-lived side branch for it (see
[Experimental Features Instead of a Release Branch](./docs/decisions/experimental-features-instead-of-a-release-branch.md)).

## Testing

Four tiers, see [`.agents/testing.md`](./.agents/testing.md):

```bash
make verify-unit          # backend unit tests + frontend vitest: about a minute and a half
make verify-integration   # the longest tier, several minutes (CI runs it as four shards)
make verify-contract      # about 15 s
make verify-e2e           # both Playwright projects (see below)

make verify               # lint + unit + integration + contract + acceptance audit
make verify-all           # verify + e2e
```

`make verify-e2e` runs the two projects `e2e/playwright.config.ts` defines. The **web**
project runs the browser-driven specs in `e2e/web/specs/` against the frontend, one per page
or flow. The **mcp** project spawns the daemon and the shim as OS subprocesses and drives a
real MCP client through them to upstream servers. Download the browser once with
`make install-e2e-browsers`.

## Lockfile

`backend/uv.lock` is the single source of truth for backend dependency versions. It is generated by [uv](https://docs.astral.sh/uv/) from `backend/pyproject.toml` and pins every transitive dependency to an exact version + hash.

- **CI and releases install frozen.** `.github/workflows/ci.yml` and `release.yml` run `uv sync --frozen`, which installs the exact versions in `uv.lock` and fails if the lockfile is out of sync with `pyproject.toml`. This is what makes tagged release artifacts reproducible — they are never built against the `>=` floors in `pyproject.toml`. One job is the deliberate exception: the scheduled **latest-deps canary** in `ci.yml` installs with `uv sync --upgrade --extra dev --project backend` and no `--frozen`, re-resolving the floors to the newest compatible versions. A red canary means an upstream release broke us, not that your lockfile drifted; the pinned jobs are the ones that answer that.
- **`pyproject.toml` declares floors; `uv.lock` pins.** Edit dependencies in `pyproject.toml` (the human-readable constraints); never hand-edit `uv.lock`.
- **Refresh the lock when you change deps.** After adding, bumping, or removing a dependency in `pyproject.toml`, run:

  ```bash
  make lock        # = uv lock --project backend
  ```

  Commit the updated `uv.lock` in the same change as the `pyproject.toml` edit. CI's frozen install will reject a PR whose lockfile drifted from `pyproject.toml`.

- **Local install** (`make install`) syncs the same frozen lock into `.venv` (`uv sync --frozen --extra dev`), so a local run tests the versions CI tests. It needs [uv](https://docs.astral.sh/uv/).
